### 1. Cấu hình VLAN Network Cho các VM

**Mục tiêu**:

- Cấu hình Neutron dùng VLAN
- Tạo nhiều VLAN network tách biệt
- Test isolate giữa các VLAN.

**Sơ đồ**:

![Lab_Neutron](./images/Lab_Neutron_12.png)

- Tạo 2 `VLAN ID`: 10,20 rồi gán nó với các VM riêng biệt.

**Các bước thực hiện**:

Lưu ý Lab ta đang dùng Linux Bridge, VLAN ID `10` và `20` sẽ tạo dưới dạng provider VLAN network. VM không tự thấy VLAN tag, nó chỉ thấy thêm card mạng bình thường; VLAN tag do Neutron/Linux Bridge xử lý ở Compute node.

Đầu tiên để có thể cấu hình Neutron cấu hình dùng VLAN ta cấu hình `ml2` module cũng giống như `VXLAN`.

Trước hết, check và cấu hình Neutron cho phép VLAN:

```bash
# Trên Controller. Mở file cấu hình ml2
nano /etc/neutron/plugins/ml2/ml2_conf.ini

# Đảm bảo có VLAN trong ML2:
[ml2]
type_drivers = flat,vlan,vxlan
tenant_network_types = vxlan
mechanism_drivers = linuxbridge,l2population
extension_drivers = port_security

[ml2_type_vlan]
network_vlan_ranges = provider:10:20
```

Tiếp theo, check file config `/etc/neutron/plugins/ml2/linuxbridge_agent.ini`:

```bash
# Đảm bảo mapping provider đang trỏ vào card external ens33:

[linux_bridge]
physical_interface_mappings = provider:ens33
```

Sau đó, restart các service để ăn cấu hình:

```bash
# Controller
systemctl restart neutron-server neutron-linuxbridge-agent neutron-dhcp-agent neutron-metadata-agent

# Compute
systemctl restart neutron-linuxbridge-agent
```

Tiếp theo đó. Tạo 2 VLAN network ID `10` và `20`:

```bash
source /root/admin-openrc
openstack network create vlan10-net \
  --provider-network-type vlan \
  --provider-physical-network provider \
  --provider-segment 10

openstack network create vlan20-net \
  --provider-network-type vlan \
  --provider-physical-network provider \
  --provider-segment 20
```

### 2. Cấu hình RBAC policy

**Mục tiêu**:

- Chia sẻ network giữa các project

- Tạo RBAC rule cho phép project B dùng network của project A

**Chi tiết**:

```bash
project-a sở hữu network rbac-net
project-b ban đầu không thấy rbac-net
admin tạo RBAC policy share rbac-net cho project-b
project-b thấy network và tạo port/VM vào network đó
```

Đầu tiên, ta cần tạo project/user để test

```bash

openstack project create project-b

# Tạo Domain

openstack role add --project project-b --user user-b member
```

Nếu lỗi role `member` không tồn tại:

### 4. Cấu hình VPN (VPNaas)

**Mục tiêu**:

- Dùng VPN để truy cập VM trong tenant network của dải
- Test tunnel giữa 2 private network khác subnet

**Chi tiết**:

- Tạo 1 VM làm VPN gateway trong `tiennet` (hoặc subnet tenant riêng).
- Gán floating IP cho VM đó.
- Cài VPN server trên VM: `WireGuard` (dễ nhất) hoặc `OpenVPN` / `strongSwan`.
- Mở security group đúng cổng:

  - WireGuard: UDP `51820`
  - IPsec: UDP `500`, UDP `4500`, protocol ESP

- Bật `net.ipv4.ip_forward=1` trên VPN VM và thêm route/NAT để client đi vào dải tenant.

**Mô hình sử dụng Wire Guard**:

```text
Laptop/Host
   |
   | WireGuard UDP 51820
   v
Floating IP của VM VPN
   |
VM wg-vpn trong tiennet: 192.168.10.x
   |
Tenant network 192.168.10.0/24
   |
vm1, vm2, các VM nội bộ
```

**Thực hiện**:

Đầu tiên, check router tenant đã ra provider chưa:

```bash

openstack router show tien-router
openstack network list
openstack subnet list
```

![Lab_Neutron](./images/Lab_Neutron_23.png)
![Lab_Neutron](./images/Lab_Neutron_24.png)

**Note**: Nếu chưa có gateway ra external network thì phải tạo ngay

```bash
PostDown = iptables -D FORWARD -i wg0 -o ens3 -j ACCEPT; iptables -D FORWARD -i ens3 -o wg0 -m state --state RELATED,ESTABLISHED -j ACCEPT; iptables -t nat -D POSTROUTING -s 10.200.200.0/24 -d 192.168.10.0/24 -o ens3 -j MASQUERADE

[Peer]
PublicKey = <client_public_key>
AllowedIPs = 10.200.200.2/32

# Ta start Wire Guard:

systemctl status wg-quick@wg0 --no-pager
```

### 5. Cấu hình DNS (Designate + Neutron)

**Mục tiêu**:

- Gắn DNS domain vào network
- Tự động tạo DNS record khi tạo VM

**Tác dụng**:

- Quản lý VM dễ hơn
Không cần nhìn openstack server list rồi copy IP. Tên VM trở thành DNS name.
- Ứng dụng nội bộ dùng hostname ổn định hơn
App web gọi database bằng
- Tự động hóa cloud-native hơn
Khi **Terraform/Heat/Ansible** tạo VM, DNS record sinh luôn theo lifecycle VM/port. Tạo VM thì có record, xóa port/VM thì record cũng được dọn.
- Phục vụ floating IP/public service
Với cấu hình nâng cao, floating IP cũng có thể publish DNS record.
- Chứng minh OpenStack không chỉ cấp IP cho VM, mà còn quản lý tên miền/DNS record tự động theo VM/network.

**Inside-Flow**:

```text
Designate + BIND9 chạy trên Controller
                 |
Neutron gắn dns_domain vào tiennet
                 |
Subnet tiensubnet bật dns_publish_fixed_ip
                 |
Khi tạo VM tên dns-vm1, Neutron tự publish A record dns-vm1.openstack.lab.
```

**Chi tiết cấu hình**:

Đầu tiên, cài Cài **Designate + BIND9** trên Controller:

```bash
source /root/admin-openrc

mysql
```

Trong MariaDB, tạo DB cho service:

```sql
CREATE DATABASE designate CHARACTER SET utf8 COLLATE utf8_general_ci;

GRANT ALL PRIVILEGES ON designate.* TO 'designate'@'localhost' IDENTIFIED BY 'Tien123';
GRANT ALL PRIVILEGES ON designate.* TO 'designate'@'%' IDENTIFIED BY 'Tien123';

FLUSH PRIVILEGES;
EXIT;
```

Tạo user, service, endpoint:

```bash
openstack user create --domain default --password Tien123 designate
openstack role add --project service --user designate admin

openstack service create --name designate --description "OpenStack DNS" dns

openstack endpoint create --region RegionOne dns public http://controller:9001/
openstack endpoint create --region RegionOne dns internal http://controller:9001/
openstack endpoint create --region RegionOne dns admin http://controller:9001/
```

Cài gói **BIND9** và **Designated**:

```bash
apt update
apt -y install designate bind9 bind9utils bind9-doc
apt -y install designate-worker designate-producer designate-mdns
```

Tiếp theo, cấu hình **BIND9** cho **Designated**:

```bash
rndc-confgen -a -k designate -c /etc/bind/designate-rndc.key -r /dev/urandom
chown root:bind /etc/bind/designate-rndc.key
chmod 640 /etc/bind/designate-rndc.key
```

Sửa file config của BIND:

```bash
# Sửa file cấu hình chính
nano /etc/bind/named.conf

# Dán nội dung kiểu này và nhớ dán trước các dòng include khác:
 include "/etc/bind/designate-rndc.key";

controls {
    inet 127.0.0.1 port 953
    allow { 127.0.0.1; } keys { "designate"; };
};

# Sửa file config option
nano /etc/bind/named.conf.options

# Dán nội dung kiểu này:
options {
    directory "/var/cache/bind";

    allow-new-zones yes;
    request-ixfr no;

    listen-on port 53 { 127.0.0.1; 10.0.0.5; 192.168.122.5; };
    allow-query { any; };

    recursion no;
    dnssec-validation auto;
};

# Sau đó restart service:
systemctl restart bind9
systemctl status bind9 --no-pager -l
```

Trong đó:

- Dòng `include "/etc/bind/designate-rndc.key";` dùng để nạp key `rndc` mà Designate dùng để nói chuyện với BIND9 (Designate muốn bảo BIND9 “tạo zone openstack.lab.” thì phải có chìa khóa này)
- Dòng `options { directory "/var/cache/bind";`: Thư mục làm việc của BIND9. Các file zone động do BIND tạo/cập nhật thường nằm quanh khu vực cache/runtime của BIND.
- Dòng `allow-new-zones yes;`: Cho phép BIND9 tạo zone mới qua `rndc`. Dòng này rất quan trọng với Designated.(Nếu không có dòng này, Designate có thể gọi BIND nhưng BIND không cho tạo zone mới.)
- Dòng `request-ixfr no;`: không cho xử lí đồng bộ zone.
- Dòng `listen ...`: cho phép BIND lắng nghe trên mọi mạng.
- Dòng `query ...`: cho phép query mọi đường mạng
- Vì đây là authoritative DNS cho zone OpenStack, không phải DNS resolver internet lên có dòng `dnssec-validation auto;`
- Dòng `controls { ...`: là cổng điều khiển `rndc`
(chỉ local host là `controller` mới được phép điều khiển)

### 6. Đọc Namespaces của Neutron (`NET`)

Ta hiểu **namespaces** là các tiến trình được cách ly trong vùng riêng trong nhân kernel

Có 6 loại namespaces chính:

| Namespace | Cách ly cái gì               | Ví dụ                                  |
| --------- | ---------------------------- | -------------------------------------- |
| PID       | Process IDs                  | Container thấy process của nó là PID 1 |
| NET       | Network interfaces, IP, port | Container có network card riêng        |
| MNT       | Filesystem mount points      | Container có `/` riêng                 |
| UTS       | Hostname                     | Container đặt hostname khác host       |
| IPC       | Shared memory, message queue | Process không can thiệp nhau           |
| USER      | User/Group IDs               | Root trong container ≠ root ngoài host |

Nhưng trong Openstack hay cụ thể Neutron ta chỉ tìm hiểu về `NET` namespaces.

`NET` namespaces hiểu là các phần thiết bị mạng ảo dùng trong các network agent.

Giả sử ta có:

```text
qrouter ->Router ảo
tap     ->Interface ảo
qdhcp   ->Dhcp ảo
brq..   ->Bridge ảo
```

Một số lệnh thao tác với namespaces:

```bash
# Xem danh sách namespace
ip netns list

# Tạo namespace mới
ip netns add phong-a

# Chạy lệnh trong namespace đó
ip netns exec phong-a ip addr
ip netns exec phong-a ping 8.8.8.8

# Xóa
ip netns delete phong-a
```
