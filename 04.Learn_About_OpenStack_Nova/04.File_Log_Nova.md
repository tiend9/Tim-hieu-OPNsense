# TÌM HIỂU FILE LOG NOVA

## I. LOGGING MODULE (Module Ghi Nhật Kí)

Ta có thể thay đổi cách ghi nhật ký bằng cách tạo tệp cấu hình. Để chỉ định tệp cấu hình, hãy thêm dòng này vào tệp `/etc/nova/nova.conf`:

```bash
log-config = /etc/nova/logging.conf
```

Tệp cấu hình ghi nhật ký là một tệp cấu hình kiểu INI, phải chứa một phần có tên là `<logging.config>` (hoặc `#logger_nova`). Phần này kiểm soát hoạt động của cơ chế ghi nhật ký trong các `nova-*Service`. Ví dụ:

Ví dụ:

```bash
[logger_nova]
level = INFO
handlers = stderr
qualname = nova
```

- Ví dụ này thiết lập mức độ gỡ lỗi là `INFO`(ít chi tiết hơn so với mặc định là `DEBUG`).

- Để thay đổi cấp độ ghi nhật kí, hãy thêm `DEBUG`, `INFO`, `WARNING`, hoặc `ERROR` làm tham số . Hãy thêm `DEBUG`, `INFO`, `WARNING`, hoặc `ERROR` làm tham số.

Để biết thêm chi tiết về cú pháp cấu hình ghi nhật ký, bao gồm cả các biến **handlers** và **quaname**, hãy xem [tài liệu Python](https://docs.python.org/release/2.7/library/logging.html#configuration-file-format) về các tệp cấu hình ghi nhật ký.

Để xem ví dụ về tệp `logging.conf` có nhiều trình xử lý được định nghĩa khác nhau, hãy xem [ví dụ file cấu hình cho Nova](https://docs.openstack.org/oslo.log/latest/admin/example_nova.html).

## II. SYS LOG

Các dịch vụ OpenStack có thể gửi log vào syslog. Sau đó dùng rsyslog để chuyển log sang server khác. Phải cấu hình riêng từng service:

- Nova: `/etc/nova/nova.conf`.

- Keystone: `/etc/keystone/keystone.conf`.

- Glance:`/etc/glance/glance-api.conf` và `/etc/glance/glance-registry.conf`.

- Cinder: `/etc/cinder/cinder.conf`.

Trong mỗi tệp cấu hình, hãy thêm các dòng sau:

```bash
debug  =  False 
use_syslog  =  True 
syslog_log_facility  =  LOG_LOCAL0
```

-> Ngoài việc bật syslog, các thiết lập này cũng tắt gỡ lỗi đầu ra từ nhật ký.

**Lưu ý**: Mặc dù ví dụ này sử dụng cùng một cơ sở cục bộ cho mỗi dịch vụ ( `LOG_LOCAL0` tương ứng với cơ sở syslog `LOCAL0`), chúng tôi khuyên bạn nên cấu hình một cơ sở cục bộ riêng biệt cho mỗi dịch vụ, vì điều này mang lại khả năng cách ly tốt hơn và linh hoạt hơn. Ví dụ, bạn có thể thu thập thông tin nhật ký ở các mức độ nghiêm trọng khác nhau cho các dịch vụ khác nhau. **Syslog** cho phép bạn định nghĩa tối đa tám cơ sở cục bộ . Để biết thêm thông tin, hãy xem tài liệu `syslog.LOCAL0`, `LOCAL1`, ..., `LOCAL7`.

## III. RSYSLOG

Thay vì mỗi node **Compute** giữ log riêng:

```text
compute0 → log local
compute1 → log local
controller → log local
```

Ta gom lại:

```text
compute0 ─┐
compute1 ─┤
compute2 ─┤
           ▼
        Log Server
```

Công dụng:

- Dễ debug lỗi
- Dễ giám sát hệ thống
- Lưu log tập trung

### Bước1. Cấu hình Rsyslog

Ví dụ: Giả sử máy chủ của bạn đã cài `rsyslog` (hầu hết các bản distro Linux đều cài sẵn)

- Trên máy **log Server**, chỉnh file:

```bash
/etc/rsyslog.conf
```

Chỉnh:

```bash
# Cung cấp khả năng nhận kí hệ thống TCP
$ModLoad imtcp              # Bật module nhận log qua TCP
$InputTCPServerRun 1024     # Mở port 1024 để nhận log
```

-> Sau bước này logServer lắng nghe log từ máy khác.

### Bước2. Lọc log theo hostname

**Vẫn ví dụ trên** .Thêm rule vào file config `/etc/rsyslog.conf`:

```bash
:hostname, isequal, "COMPUTE_01" /mnt/rsyslog/logs/compute-01.log
```

Ý nghĩa:

- Nếu log đến từ host: `COMPUTE_1`
- Thì lưu vào file: `/mnt/rsyslog/logs/compute-01.log`

=> Lúc này log Server sẽ có:

```bash
/mnt/rsyslog/logs/
   compute-01.log
   compute-02.log
   controller.log
```

### Bước3. Cấu hình trên compute host

Trên mỗi compute node tạo file:`/etc/rsyslog.d/60-nova.conf`

Thêm nội dung:

```bash
# Ngăn chặn lỗi từ dnsmasq
*.*;auth,authpriv.none,daemon.none,local0.none -/var/log/syslog

# send ERROR logs (chỉ định mức ERROR)
local0.error @@172.20.1.43:1024
```

=> Sau khi tạo tệp, hãy khởi động lại dịch vụ `rsyslog`. Các thông báo lỗi trên máy chủ tính toán giờ đây sẽ được gửi đến máy chủ nhật ký.

## SERIAL CONSOLE (BẢNG ĐIỀU KHIỂN NỐI TIẾP)

### 1. Serial Console là gì ?

**Serial console** là một cách truy cập console của VM để xem:

- kernel output.
- system messages.
- boot logs.

Ứng dụng thực tế **Serial Console**: VM không có network, SSH không vào được thì ta dùng cách này xem log của VM qua **Serial Console**.

### 2. Hai loại truy cập qua Serial Console

#### a. Read-Only

Tác dụng:

- Chỉ xem log.

Dùng API:

```bash
os-GetSerialOutput
```

Hầu hết cloud image đã bật sẵn.

#### b. Read-write

Có thể:

- xem log.
- gửi input vào console.

-> Giống như đang dùng console trực tiếp của VM.(Feature được hỗ trợ từ **OpenStack Juno**)

### 3. Cấu hình SerialConsole

Trên **compute node**, chỉnh file: `/etc/nova/nova.conf`.

Bật **Serial Console**:

```bash
[serial_console]
enabled = true
```

Cấu hình **Proxy**:

```bash
[serial_console]
base_url = ws://controller:6083/
listen = 0.0.0.0
proxyclient_address = MANAGEMENT_INTERFACE_IP
```

Giải thích từng tham số:

| Option                | Ý nghĩa                              |
| --------------------- | ------------------------------------ |
| `enabled`             | bật serial console                   |
| `base_url`            | URL websocket client dùng để kết nối |
| `listen`              | interface nova-compute lắng nghe     |
| `proxyclient_address` | IP interface để proxy kết nối        |

### 4. Web Socket dùng để làm gì ?

Serial Console dùng:

```bash
WebSocket
```

để truyền dữ liệu realtime giữa:

```bash
Client ↔ Controller ↔ Compute ↔ VM
```

### 5. LibVirt XML của VM

Khi bật Serial Console, Nova sẽ thêm cấu hình vào **libvirt XML**:

Ví dụ:

```bash
<console type='tcp'> # VM mở TCP port nội bộ 
  <source mode='bind' host='127.0.0.1' service='10000'/>
  <protocol type='raw'/>
  <target type='serial' port='0'/>
</console>  # Nova proxy kết nối vào console đó.
```

### 6. Lấy URL Serial Console

Dùng CLI:

```bash
nova get-serial-proxy INSTANCE_NAME
```

Ví dụ:

```bash
serial ws://127.0.0.1:6083/?token=xxxx
```

-> URL này dùng để kết nối console.

### 7. Truy cập bằng API

Có thể gọi trực tiếp API:

```bash
 POST /servers/<instance>/action
```

body:

```Json
{
 "os-getSerialConsole": {
   "type": "serial"
 }
}
```

=> API của **OpenStack Nova** sẽ trả về URL WebSocket.

### 8. Kết nối bằng Python Webcket

```bash
import websocket
ws = websocket.create_connection(
'ws://127.0.0.1:6083/?token=xxxxx',
subprotocols=['binary', 'base64'])
```

Sau đó có thể:

```bash
send()
recv()
```

=> Để tương tác với Console

### 9. Lưu ý

Khi bật serial console:

```bash
nova console-log
```

-> Sẽ không còn hiển thị kernel log nữa.

Muốn xem log phải:

```bash
mở serial console trực tiếp
```
