# QUÁ TRÌNH QUẢN LÍ VÀ TRUY CẬP VNC CONSOLE

OpenStack cung cấp một số phương thức khác nhau để tương tác với các máy ảo khách: VNC, SPICE, Serial, RDP hoặc MKS. Nếu được cấu hình, người dùng có thể truy cập các phương thức này thông qua bảng điều khiển OpenStack hoặc dòng lệnh. Tài liệu này trình bày cách thức cấu hình công nghệ VNC Console.

## 1. VNC là gì ?

**VNC (Virtual Network Computing)** là một công nghệ cho phép **truy cập và điều khiển giao diện màn hình của một máy tính từ xa thông qua mạng**.

Về bản chất, VNC sử dụng giao thức:

- RFB (Remote Frame Buffer)

-> để truyền dữ liệu màn hình từ máy server đến máy client.

## 2. Tác dụng của VNC trong OpenStack

**VNC (Virtual Network Computing)** được dùng để:

- truy cập console của VM
- quản lý VM khi:

  - chưa cấu hình network
  - không SSH được
  - VM boot lỗi

OpenStack sử dụng **web-based VNC client**:`noVNC`

-> để cho phép truy cập console trực tiếp từ trình duyệt.

## 3. Các thành phần tham gia

| Thành phần      | Vai trò                          |
| --------------- | -------------------------------- |
| nova-api        | nhận request console             |
| nova-novncproxy | proxy kết nối VNC                |
| nova-compute    | quản lý VM trên compute node     |
| libvirt         | tạo và quản lý VNC server cho VM |
| noVNC           | client VNC trên browser          |

## 4. Quá trình quản lí và truy cập VNC

![Nova](./images/Nova_16.png)

### `Bước 1`: User yêu cầu truy cập console

User truy cập Console từ:

- DashBoard **OpenStack Horizon**
- Hoặc CLI:

``` bash
openstack console url show <instance>
```

Request được gửi đến `nova-api`

### `Bước 2`: Nova API tạo Console Token

Dịch vụ `Nova-API` sẽ:

- Tạo Console Token
- Lưu Token vào Databases thông qua service **nova-consoleauth**

Token dùng để:

- Xác thực User
- Xác định Instance
- Xác định Compute Node

Service nova-consoleauth có nhiệm vụ:

- lưu token
- ánh xạ token → instance
- ánh xạ token → compute node
- ánh xạ token → VNC port

Sau đó Nova trả về URL:

```ruby
http://controller:6080/vnc_auto.html?token=xxxx
```

### `Bước 3`: User Mở URL trên Browser

Browser sẽ dùng client VNC web: `noVNC`

### `Bước 4`: Browser kết nối đến noVNC Proxy

User mở URL Console:

```ruby
http://controller:6080
```

Browser sẽ kết nối tới:

```ruby
nova-novncproxy
```

Proxy sẽ kiểm tra `Console Token`

### `Bước 5`: Proxy xác thực console token

Dịch vụ `nova-novncproxy` kiểm tra token nhận được. **nova-novncproxy** gửi token tới **nova-consoleauth**. Để kiểm tra:

- Token có hợp lệ không
- Token thuộc instance nào
- Compute node nào
- Port VNC nào

Nếu token hợp lệ, proxy sẽ xác định:

- Instance tương ứng
- Compute node đang chạy VM
- Cổng VNC của VM

### `Bước 6`: Proxy kết nối đến VNC server trên Compute Node

Sau khi xác thực thành công, proxy sẽ kết nối tới VNC Server của instance trên Compute Node.

VNC server được tạo bởi hypervisor thông qua libvirt khi instance được khởi tạo.

- Ví dụ cấu hình VNC trong libvirt:

```bash
<graphics type='vnc' port='5901' listen='127.0.0.1'/>
```

### `Bước 7`: Hiển thị console VM

Sau khi kết nối thành công, nova-novncproxy chuyển tiếp dữ liệu giữa:

- Trình duyệt người dùng
- VNC server của VM

Console của VM sẽ được hiển thị trực tiếp trên trình duyệt.
