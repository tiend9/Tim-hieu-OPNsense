# TÌM HIỂU NOVA CONDUCTOR

![Nova](./images/Nova_1.png)

> Phiên bản tham chiếu: OpenStack `2026.1 Gazpacho` / Nova `33.x`.
> Đây là bản stable mới nhất tại thời điểm cập nhật tài liệu ngày `26/05/2026`.

## I. TỔNG QUAN VỀ NOVA CONDUCTOR

### 1. Nova Conductor là gì?

**Nova Conductor** là một service chạy nền của Nova. Nhiệm vụ chính của nó là:

- điều phối các workflow của Nova;
- hỗ trợ query/update database cho các service Nova;
- làm lớp trung gian để `nova-compute` không phải truy cập database trực tiếp;
- hỗ trợ kiến trúc **Cells v2** trong các cloud lớn.

Nói ngắn gọn:

```text
nova-compute  --RPC-->  nova-conductor  -->  database
```

Trong tài liệu OpenStack, `nova-conductor` được mô tả là daemon cung cấp **coordination** và **database query support** cho Nova.

### 2. Vì sao Nova Conductor tồn tại?

Trước đây, nếu compute node truy cập database trực tiếp:

```text
nova-compute  -->  MariaDB/MySQL
```

Sẽ có nhiều vấn đề:

- **Security**: compute node thường nằm gần workload của user. Nếu compute bị compromise thì database dễ bị ảnh hưởng.
- **Scale**: nhiều compute node cùng query DB làm DB chịu tải lớn.
- **Upgrade**: nếu logic DB nằm rải rác trên compute, rolling upgrade khó kiểm soát hơn.
- **Maintainability**: workflow tạo VM, migrate, resize, rebuild... không nên phân tán quá nhiều ở compute.

Vì vậy Nova đặt `nova-conductor` ở giữa:

```text
nova-compute  --RPC-->  nova-conductor  -->  cell database
```

Compute tập trung vào hypervisor và VM. Conductor tập trung vào workflow, state, DB và điều phối.

### 3. Vị trí của Nova Conductor trong kiến trúc Nova hiện đại

Luồng tổng quát khi tạo VM:

```text
User / CLI / Horizon
        |
        v
     nova-api
        |
        v
 nova-conductor
        |
        v
 nova-scheduler  -->  Placement
        |
        v
 nova-conductor
        |
        v
 nova-compute  -->  Hypervisor
```

Trong thực tế, Nova dùng thêm:

- **API database**: lưu dữ liệu global/routing, build request, cell mapping.
- **Cell database**: lưu phần lớn dữ liệu instance trong từng cell.
- **Message queue**: RPC giữa các service, thường gặp nhất là RabbitMQ.
- **Placement**: quản lý inventory, allocation, trait, aggregate của resource provider.

### 4. Vai trò chính của Nova Conductor

#### 4.1 Là proxy database cho compute

`nova-compute` không nên ghi trực tiếp vào database. Khi compute cần cập nhật state của instance, lưu metadata, báo lỗi build, update migration state..., nó gọi RPC tới conductor.

Ví dụ:

```text
nova-compute
    |
    | RPC
    v
nova-conductor
    |
    v
cell database
```

Điều này giúp compute node nhẹ hơn và giảm rủi ro bảo mật.

#### 4.2 Điều phối workflow dài và phức tạp

Một số thao tác VM có nhiều bước:

- create/build instance;
- rebuild;
- resize;
- cold migrate;
- live migration preparation;
- evacuate;
- unshelve;
- delete.

Các thao tác này không chỉ là "chạy VM". Chúng còn phải cập nhật DB, gọi scheduler, kiểm tra Placement allocation, gọi Neutron, Glance, Cinder và gửi RPC tới compute.

Conductor là nơi gom phần lớn logic điều phối đó.

#### 4.3 Kết nối nova-api, scheduler, compute và cell

Trong Nova hiện đại, conductor là cầu nối rất quan trọng:

| Thành phần | Conductor liên quan như nào |
| ---------- | ---------------------------- |
| `nova-api` | nhận request đã validate, xử lý workflow dài thay API |
| `nova-scheduler` | gọi scheduler để chọn host/cell phù hợp |
| Placement | phối hợp allocation/resource candidate qua scheduler |
| `nova-compute` | gửi RPC build/migrate/delete VM |
| DB | đọc/ghi API DB và cell DB tùy loại conductor |
| Message queue | nhận/gửi RPC giữa các service |

#### 4.4 Hỗ trợ Cells v2

Cells v2 là kiến trúc bắt buộc trong Nova hiện đại. Kể cả cloud nhỏ cũng là một deployment Cells v2, chỉ khác là thường chỉ có một cell thật.

Trong multi-cell:

```text
API level
  nova-api
  nova-scheduler
  super conductor
  API database

Cell 1
  nova-conductor
  nova-compute
  cell database
  cell message queue

Cell 2
  nova-conductor
  nova-compute
  cell database
  cell message queue
```

Điểm cần nhớ:

- **Super conductor** xử lý API-level operation.
- **Per-cell conductor** xử lý thao tác trong từng cell.
- Mỗi cell có thể có database và message queue riêng.
- Cách chia này giúp scale và cô lập failure domain tốt hơn.

## II. FLOW KHI TẠO VM CÓ NOVA CONDUCTOR

### 1. Flow đơn giản

```text
1. User gọi openstack server create
2. nova-api validate request
3. nova-api tạo build request / instance record ban đầu
4. nova-api gọi nova-conductor
5. nova-conductor gọi nova-scheduler
6. nova-scheduler hỏi Placement để lấy allocation candidates
7. nova-scheduler chạy filter + weigher, chọn host
8. nova-conductor cập nhật DB và gửi RPC tới nova-compute
9. nova-compute gọi hypervisor để spawn VM
10. nova-compute báo state về conductor
11. conductor update DB
```

### 2. Diagram dễ nhớ

```text
User
 |
 v
nova-api
 |
 v
nova-conductor
 |
 v
nova-scheduler <--> Placement
 |
 v
nova-conductor
 |
 v
nova-compute
 |
 v
KVM / QEMU / Libvirt
```

### 3. Khi scheduler không tìm được host

Nếu không có host phù hợp:

```text
nova-scheduler -> NoValidHost
nova-conductor -> update instance state/error
```

Các nguyên nhân thường gặp:

- Placement không có đủ `VCPU`, `MEMORY_MB`, `DISK_GB`;
- compute service bị `down` hoặc `disabled`;
- host aggregate/AZ không match;
- flavor extra specs hoặc image metadata yêu cầu trait không có;
- filter như anti-affinity, NUMA, PCI, aggregate làm hết candidate;
- cell chưa map host hoặc chưa `discover_hosts`.

## III. MESSAGE QUEUE TRONG NOVA CONDUCTOR

Nova dùng oslo.messaging để giao tiếp RPC. Message broker phổ biến nhất trong production là **RabbitMQ**.

Ví dụ compute gửi RPC tới conductor:

```text
nova-compute
    |
    v
RabbitMQ
    |
    v
nova-conductor
```

Một số RPC phổ biến:

- update instance state;
- report build result;
- request migration/resize workflow;
- fetch/update objects;
- gọi compute đúng host/cell.

Nếu RabbitMQ lỗi:

- API có thể nhận request nhưng workflow bị treo/fail;
- compute không gửi được state;
- conductor không nhận được RPC;
- tạo VM, migrate, resize dễ fail.

## IV. CONFIG FILE NOVA CONDUCTOR

File cấu hình chính thường là:

```bash
/etc/nova/nova.conf
```

Các section quan trọng:

```ini
[DEFAULT]
transport_url = rabbit://openstack:RABBIT_PASS@controller:5672/

[api_database]
connection = mysql+pymysql://nova:NOVA_DBPASS@controller/nova_api

[database]
connection = mysql+pymysql://nova:NOVA_DBPASS@controller/nova

[conductor]
workers = 4
```

Ý nghĩa:

| Option | Ý nghĩa |
| ------ | ------- |
| `[DEFAULT] transport_url` | endpoint message queue để RPC |
| `[api_database] connection` | kết nối API DB |
| `[database] connection` | kết nối cell DB/main DB |
| `[conductor] workers` | số worker process của conductor; nếu để trống, mặc định theo số CPU |

Trong multi-cell, mỗi cell có thể có file config riêng với `transport_url` và `database.connection` riêng.

## V. QUẢN LÝ SERVICE NOVA CONDUCTOR

Tên service phụ thuộc bản phân phối:

```bash
# RHEL/CentOS/Rocky/Alma kiểu package openstack-*
systemctl status openstack-nova-conductor

# Ubuntu/Debian thường gặp
systemctl status nova-conductor
```

Start/restart:

```bash
systemctl restart openstack-nova-conductor
```

Kiểm tra process:

```bash
ps -ef | grep nova-conductor
```

Log thường gặp:

```bash
/var/log/nova/nova-conductor.log
```

Tùy distro/container deployment, log có thể nằm trong journald hoặc log container.

## VI. CLI NOVA CONDUCTOR

### 1. `nova-conductor` không phải CLI cho user

`nova-conductor` là daemon service, không giống `openstack` CLI.

Cú pháp chạy thủ công:

```bash
nova-conductor [options]
```

Các option phổ biến:

```bash
nova-conductor --config-file /etc/nova/nova.conf
nova-conductor --config-dir /etc/nova/nova.conf.d
nova-conductor --debug
```

Ý nghĩa:

| Option | Ý nghĩa |
| ------ | ------- |
| `--config-file` | chỉ định file config |
| `--config-dir` | chỉ định thư mục chứa nhiều file `.conf` |
| `--debug` hoặc `-d` | bật log DEBUG |
| `--version` | in version |

### 2. CLI admin liên quan conductor

Kiểm tra service Nova:

```bash
openstack compute service list
openstack compute service list --service nova-conductor
```

Kiểm tra Cells v2:

```bash
nova-manage cell_v2 list_cells
nova-manage cell_v2 list_hosts
nova-manage cell_v2 discover_hosts
```

Sync DB:

```bash
nova-manage api_db sync
nova-manage db sync
```

Kiểm tra upgrade:

```bash
nova-status upgrade check
```

## VII. CELLS V2 VÀ CONDUCTOR

### 1. Single-cell deployment

Cloud nhỏ thường có:

```text
API DB
cell0 DB
cell1 DB
RabbitMQ
nova-api
nova-scheduler
nova-conductor
nova-compute
```

`cell0` là cell đặc biệt, không có compute host. Nó lưu các instance fail scheduling.

```text
NoValidHost -> instance record nằm ở cell0
```

### 2. Multi-cell deployment

Cloud lớn có thể tách:

```text
API Cell:
  nova-api
  nova-scheduler
  super conductor
  API DB

Cell A:
  nova-conductor
  nova-compute
  Cell A DB
  Cell A MQ

Cell B:
  nova-conductor
  nova-compute
  Cell B DB
  Cell B MQ
```

Lợi ích:

- scale nhiều compute host hơn;
- giảm blast radius nếu một cell lỗi;
- chia DB/MQ theo cell;
- hỗ trợ vận hành/upgrade từng phần tốt hơn.

Điểm cần nhớ:

```text
transport_url + database.connection = service thuộc cell nào
```

Nếu cấu hình sai cell mapping, conductor/API/scheduler có thể không route đúng tới compute.

## VIII. SCALE VÀ HIGH AVAILABILITY

Nova Conductor có thể scale ngang:

```text
nova-conductor-1
nova-conductor-2
nova-conductor-3
```

Các instance conductor cùng đọc message queue và xử lý RPC.

Best practice:

- chạy nhiều conductor trên controller khác nhau;
- dùng RabbitMQ cluster/HA phù hợp;
- database có HA;
- cấu hình `[conductor] workers` hợp lý;
- theo dõi queue backlog và conductor log.

## IX. TROUBLESHOOTING NOVA CONDUCTOR

### 1. Service down

Kiểm tra:

```bash
openstack compute service list --service nova-conductor
systemctl status openstack-nova-conductor
journalctl -u openstack-nova-conductor -f
```

Triệu chứng:

- tạo VM fail;
- instance kẹt `BUILD`;
- migration/resize fail;
- compute không update state được.

### 2. Lỗi RabbitMQ

Kiểm tra trong log:

```text
MessagingTimeout
AMQP server unreachable
Connection refused
```

Kiểm tra config:

```ini
[DEFAULT]
transport_url = rabbit://...
```

### 3. Lỗi database

Log thường có:

```text
DBConnectionError
OperationalError
Access denied
Too many connections
```

Kiểm tra:

```ini
[database]
connection = mysql+pymysql://...

[api_database]
connection = mysql+pymysql://...
```

### 4. Lỗi Cells v2

Lệnh hữu ích:

```bash
nova-manage cell_v2 list_cells
nova-manage cell_v2 list_hosts
nova-manage cell_v2 discover_hosts --verbose
```

Nếu compute mới thêm vào nhưng scheduler không thấy host, thường cần:

```bash
nova-manage cell_v2 discover_hosts
```

Hoặc bật tự động:

```ini
[scheduler]
discover_hosts_in_cells_interval = 300
```

## X. TẠI SAO NOVA CONDUCTOR QUAN TRỌNG?

| Lý do | Ý nghĩa |
| ----- | ------- |
| Security | compute không cần truy cập DB trực tiếp |
| Scale | giảm số service chạm DB trực tiếp |
| Workflow | điều phối build, resize, migrate, evacuate |
| Cells v2 | route request đúng cell, đúng DB/MQ |
| Upgrade | gom logic ở service control-plane, dễ rolling upgrade hơn |
| HA | có thể chạy nhiều conductor instance |

Kết luận:

```text
Không có nova-conductor ổn định thì Nova gần như không vận hành ổn định được.
```

Nếu học Nova, hãy nhớ câu này:

```text
nova-api nhận request
nova-scheduler chọn host
nova-compute chạy VM
nova-conductor điều phối workflow và database
Placement quản lý resource
```
