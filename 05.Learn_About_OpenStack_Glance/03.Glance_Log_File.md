## 1. Tổng quan về Logging trong Glance

Glance sử dụng thư viện **oslo.log** (thư viện logging chung của OpenStack) để ghi log, được xây dựng trên nền tảng module `logging` chuẩn của Python.

Glance ghi log cho các hoạt động sau:

| Loại hoạt động             | Ví dụ                                 |
|----------------------------|---------------------------------------|
| Khởi động / tắt dịch vụ    | Worker start, shutdown                |
| Xác thực (Authentication)  | Token validation với Keystone         |
| Thao tác với image         | Upload, download, delete, list        |
| Kết nối Database           | Query, connection error               |
| Kết nối Storage Backend    | Ghi/đọc file từ Ceph, Swift, Local FS |
| Import image               | Quá trình web-download, glance-direct |
| Image Cache                | Cache hit/miss, pruning               |
| Lỗi và Exception           | Stack trace, HTTP error               |

## 2. Vị trí file log

### 2.1. Đường dẫn mặc định

```bash
/var/log/glance/glance-api.log
```

Khi cài đặt bằng các công cụ như **DevStack**, **Kolla-Ansible**, hoặc **OpenStack-Ansible**, đường dẫn log có thể khác:

| Phương thức cài đặt | Đường dẫn log |
|---|---|
| Cài thủ công (Ubuntu/CentOS) | `/var/log/glance/glance-api.log` |
| DevStack | `/opt/stack/logs/glance-api.log` |
| Kolla-Ansible (container) | `/var/log/kolla/glance/glance-api.log` |
| Systemd Journal | `journalctl -u glance-api` |

### 2.2. Xem log trực tiếp

```bash
# Xem log realtime
sudo tail -f /var/log/glance/glance-api.log

# Xem N dòng cuối
sudo tail -n 100 /var/log/glance/glance-api.log

# Dùng systemd journal (nếu không dùng file log)
sudo journalctl -u glance-api -f

# Xem log của container Kolla
docker logs glance_api -f
```

## 3. Cấu hình Logging trong glance-api.conf

Tất cả cấu hình logging nằm trong section `[DEFAULT]` của file `/etc/glance/glance-api.conf`.

### 3.1. Cấu hình cơ bản

```ini
[DEFAULT]
# Tên file log đầu ra
# Nếu không set => log ra stderr
log_file = /var/log/glance/glance-api.log

# Thư mục chứa file log (dùng khi log_file là đường dẫn tương đối)
log_dir = /var/log/glance

# Bật chế độ debug (ghi thêm nhiều thông tin chi tiết)
# Mặc định: false — chỉ bật khi debug sự cố
debug = false
```

### 3.2. Cấu hình nơi xuất log

```ini
[DEFAULT]
# Gửi log tới Syslog (/var/log/syslog hoặc /var/log/messages)
use_syslog = false

# Facility của syslog (LOG_USER, LOG_LOCAL0 ... LOG_LOCAL7)
syslog_log_facility = LOG_USER

# Gửi log tới systemd Journal (khuyên dùng trên hệ thống systemd)
use_journal = false

# Xuất log dưới định dạng JSON (tiện lợi cho ELK/Loki)
use_json = false

# Xuất log ra stderr
use_stderr = false
```

> **Lưu ý:** Chỉ nên chọn **một** đầu ra log chính (file, syslog, hoặc journal) để tránh trùng lặp.

### 3.3. Cấu hình định dạng log

```ini
[DEFAULT]
# Định dạng timestamp
log_date_format = %Y-%m-%d %H:%M:%S

# Format dòng log có context (request từ user)
logging_context_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [%(global_request_id)s %(request_id)s %(user_identity)s] %(instance)s%(message)s

# Format dòng log không có context (log nội bộ)
logging_default_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [-] %(instance)s%(message)s

# Thêm thông tin debug (function, file, line) vào log DEBUG
logging_debug_format_suffix = %(funcName)s %(pathname)s:%(lineno)d

# Prefix cho các dòng exception
logging_exception_prefix = %(asctime)s.%(msecs)03d %(process)d ERROR %(name)s %(instance)s
```

### 3.4. Cấu hình Log Rotation (Luân chuyển file log)

```ini
[DEFAULT]
# Kiểu rotation: none | interval | size
log_rotation_type = none

# --- Khi log_rotation_type = size ---
# Kích thước tối đa mỗi file log (MB)
max_logfile_size_mb = 200

# --- Khi log_rotation_type = interval ---
# Khoảng thời gian rotation
log_rotate_interval = 1
# Đơn vị: Seconds, Minutes, Hours, Days, Weekday, Midnight
log_rotate_interval_type = days

# Số file log cũ tối đa được giữ lại
max_logfile_count = 30
```

> **Khuyến nghị production:** Dùng **logrotate** của Linux thay vì rotation trong Glance để kiểm soát tốt hơn.

Ví dụ file `/etc/logrotate.d/glance-api`:

```bash
/var/log/glance/glance-api.log {
    daily
    rotate 30
    compress
    missingok
    notifempty
    copytruncate
}
```

### 3.5. Cấu hình Log Level theo thư viện

```ini
[DEFAULT]
# Đặt log level riêng cho từng thư viện
# Giảm log spam từ các thư viện ít quan trọng
default_log_levels = amqp=WARN,sqlalchemy=WARN,oslo.messaging=INFO,keystonemiddleware=WARN,stevedore=WARN,keystoneauth=WARN
```

### 3.6. Rate Limiting Log

```ini
[DEFAULT]
# Khoảng thời gian (giây) để áp dụng rate limit
# 0 = tắt rate limiting
rate_limit_interval = 0

# Số log message tối đa trong khoảng rate_limit_interval
rate_limit_burst = 0

# Log level được miễn rate limiting (vẫn ghi bình thường)
rate_limit_except_level = CRITICAL
```

## 4. Cấu trúc và định dạng một dòng log

### 4.1. Định dạng chuẩn (có context)

```ini
2024-10-15 08:23:45.123 12345 INFO glance.api.v2.images [req-abc123 user-uuid project-uuid] Image abc-456 uploaded successfully
│           │           │     │     │                    │                                    │
│           │           │     │     │                    │                                    └─ Nội dung log
│           │           │     │     │                    └─ Request ID, User ID, Project ID
│           │           │     │     └─ Tên logger (module Python)
│           │           │     └─ Log Level
│           │           └─ Process ID (PID)
│           └─ Milliseconds
└─ Timestamp
```

### 4.2. Giải thích từng trường

| Trường            | Ý nghĩa                                   |             Ví dụ             |
|-------------------|-------------------------------------------|-------------------------------|
| **Timestamp**     | Thời điểm ghi log                         | `2024-10-15 08:23:45.123`     |
| **PID**           | ID tiến trình Glance worker               | `12345`                       |
| **Level**         | Mức độ nghiêm trọng                       | `INFO`, `ERROR`, `DEBUG`      |
| **Logger**        | Module Python ghi log                     | `glance.api.v2.images`        |
| **Request ID**    | ID định danh HTTP request                 | `req-abc123def456`            |
| **User Identity** | User và Project thực hiện                 | `user-uuid project-uuid`      |
| **Message**       | Nội dung log                              | `Image uploaded successfully` |

### 4.3. Ví dụ thực tế các dòng log

```log
# Log khởi động dịch vụ
2024-10-15 08:00:01.001 1234 INFO glance.common.wsgi [-] Starting 4 workers

# Log request upload image
2024-10-15 08:23:45.100 1234 INFO glance.api.v2.images [req-abc user-111 proj-222] Creating image

# Log lưu file xuống backend
2024-10-15 08:23:45.500 1234 INFO glance.store.rbd [-] Wrote image data to RBD store, image id: abc-456

# Log hoàn thành upload
2024-10-15 08:23:46.200 1234 INFO glance.api.v2.images [req-abc user-111 proj-222] Image abc-456 is now active

# Log lỗi xác thực
2024-10-15 08:30:00.001 1234 WARNING keystonemiddleware.auth_token [-] Authorization failed: Token has expired

# Log lỗi database
2024-10-15 08:31:00.001 1234 ERROR glance.db.sqlalchemy.api [-] DB Exception: connection refused
```

## 5. Các mức độ Log Level

Glance dùng 5 mức log chuẩn của Python:

| Level | Mô tả | Khi nào xuất hiện |
|---|---|---|
| **DEBUG** | Thông tin chi tiết nhất | Chỉ khi `debug = true`. Mọi câu query SQL, mọi bước xử lý request |
| **INFO** | Hoạt động bình thường | Upload thành công, khởi động dịch vụ, request hoàn thành |
| **WARNING** | Cảnh báo, không phải lỗi nghiêm trọng | Token sắp hết hạn, cấu hình deprecated |
| **ERROR** | Lỗi xảy ra, request thất bại | Kết nối DB thất bại, backend không phản hồi |
| **CRITICAL** | Lỗi nghiêm trọng, dịch vụ không thể tiếp tục | Không thể bind port, lỗi khởi động |

**Thay đổi log level không cần restart:**

```bash
# Glance hỗ trợ thay đổi debug mode runtime
# Chỉnh debug = true trong glance-api.conf
# Sau đó gửi SIGHUP để reload config
sudo kill -HUP $(cat /var/run/glance/glance-api.pid)
```

## 7. Các lỗi thường gặp trong log và cách xử lý

### 7.1. Lỗi kết nối Database

```log
ERROR glance.db.sqlalchemy.api [-] DB exception: (OperationalError) (2003, "Can't connect to MySQL server on 'controller'")
```

**Nguyên nhân & Cách xử lý:**

```bash
# Kiểm tra MySQL/MariaDB đang chạy
sudo systemctl status mariadb

# Kiểm tra kết nối từ host Glance
mysql -u glance -p -h controller glance

# Kiểm tra connection string trong cấu hình
grep connection /etc/glance/glance-api.conf
```

### 7.2. Lỗi xác thực Keystone

```log
WARNING keystonemiddleware.auth_token [-] Authorization failed: The request you have made requires authentication
ERROR glance.api.v2.images [-] 401 Unauthorized
```

**Nguyên nhân & Cách xử lý:**

```bash
# Kiểm tra Keystone endpoint
openstack endpoint list --service image

# Xác minh thông tin service account
openstack token issue

# Kiểm tra cấu hình trong glance-api.conf
grep -A 10 '\[keystone_authtoken\]' /etc/glance/glance-api.conf
```

### 7.3. Lỗi Storage Backend (Ceph/RBD)

```log
ERROR glance.store._drivers.rbd [-] Failed to connect to Ceph: [errno 111] ECONNREFUSED
ERROR glance.store._drivers.rbd [-] Pool 'images' does not exist
```

**Nguyên nhân & Cách xử lý:**

```bash
# Kiểm tra kết nối Ceph
ceph status

# Kiểm tra pool images tồn tại
ceph osd lspool | grep images

# Tạo pool nếu thiếu
ceph osd pool create images 128

# Kiểm tra quyền user glance
ceph auth get client.glance
```

### 7.4. Lỗi Storage Backend (Local Filesystem)

```log
ERROR glance.store._drivers.filesystem [-] Permission denied: '/var/lib/glance/images'
ERROR glance.store._drivers.filesystem [-] No space left on device
```

**Cách xử lý:**

```bash
# Kiểm tra quyền thư mục
ls -la /var/lib/glance/

# Sửa quyền
sudo chown -R glance:glance /var/lib/glance/images/

# Kiểm tra dung lượng đĩa
df -h /var/lib/glance/
```

### 7.5. Lỗi vượt quá giới hạn kích thước image

```log
ERROR glance.api.v2.image_data [-] Image size exceeded the limit (1099511627776 bytes)
```

**Cách xử lý:**

```bash
# Tăng giới hạn trong glance-api.conf
# [DEFAULT]
# image_size_cap = 2199023255552  # 2TiB
sudo systemctl restart glance-api
```

### 7.6. Lỗi RabbitMQ (Messaging)

```log
ERROR oslo.messaging._drivers.amqp [-] Failed to connect to AMQP server: connection refused
WARNING glance.notifier [-] Could not send notification: transport error
```

**Cách xử lý:**

```bash
# Kiểm tra RabbitMQ
sudo systemctl status rabbitmq-server

# Kiểm tra connection
sudo rabbitmqctl status

# Kiểm tra transport_url trong config
grep transport_url /etc/glance/glance-api.conf
```

### 7.7. Lỗi Import Image thất bại

```log
ERROR glance.async_.flows.api_image_import [-] Import failed for image abc-456
ERROR glance.async_.flows.web_download [-] Failed to download: HTTP 404 Not Found
```

**Cách xử lý:**

```bash
# Kiểm tra trạng thái image
openstack image show abc-456

# Xem log chi tiết hơn với debug
# Bật debug = true tạm thời, sau đó thử lại import
```

## 8. Các lệnh phân tích log thực tế

### 8.1. Tìm kiếm lỗi cơ bản

```bash
# Liệt kê tất cả lỗi ERROR và CRITICAL
grep -E "ERROR|CRITICAL" /var/log/glance/glance-api.log

# Xem log trong khoảng thời gian cụ thể
grep "2024-10-15 08:" /var/log/glance/glance-api.log

# Theo dõi image cụ thể theo ID
grep "abc-456-image-id" /var/log/glance/glance-api.log

# Theo dõi request cụ thể theo Request ID
grep "req-abc123" /var/log/glance/glance-api.log
```

### 8.2. Đếm số lỗi

```bash
# Đếm số lần lỗi xuất hiện
grep -c "ERROR" /var/log/glance/glance-api.log

# Thống kê loại lỗi phổ biến nhất
grep "ERROR" /var/log/glance/glance-api.log | awk '{print $6}' | sort | uniq -c | sort -rn
```

### 8.3. Phân tích hiệu suất

```bash
# Xem các request chậm (tìm những request kéo dài)
grep "HTTP/1" /var/log/glance/glance-api.log | awk '$NF > 5000'

# Đếm số request theo loại HTTP method
grep "GET\|POST\|PUT\|DELETE" /var/log/glance/glance-api.log | awk '{print $6}' | sort | uniq -c
```

### 8.4. Theo dõi realtime theo user

```bash
# Theo dõi hoạt động của một project cụ thể
tail -f /var/log/glance/glance-api.log | grep "project-uuid-here"

# Xem chỉ log lỗi realtime
tail -f /var/log/glance/glance-api.log | grep -E "ERROR|CRITICAL"
```

### 8.5. Dùng journalctl (systemd)

```bash
# Xem log từ lần khởi động hiện tại
sudo journalctl -u glance-api -b

# Xem log trong khoảng thời gian
sudo journalctl -u glance-api --since "2024-10-15 08:00" --until "2024-10-15 09:00"

# Chỉ xem lỗi
sudo journalctl -u glance-api -p err

# Xuất log ra file
sudo journalctl -u glance-api > /tmp/glance-api-$(date +%Y%m%d).log
```

## 9. Tích hợp với hệ thống log tập trung

Trong môi trường production với nhiều node, cần tập trung log về một nơi để dễ quản lý.

### 9.1. Sử dụng Rsyslog

Cấu hình Glance gửi log tới Rsyslog:

```ini
# Trong /etc/glance/glance-api.conf
[DEFAULT]
use_syslog = true
syslog_log_facility = LOG_LOCAL0
```

Cấu hình Rsyslog forward log (`/etc/rsyslog.d/glance.conf`):

```bash
# Forward log của LOCAL0 tới log server trung tâm
local0.*   @logserver.example.com:514
```

### 9.2. Sử dụng Filebeat + ELK Stack

Cấu hình Glance xuất JSON log:

```ini
[DEFAULT]
use_json = true
log_file = /var/log/glance/glance-api.log
```

Cấu hình Filebeat thu thập (`/etc/filebeat/filebeat.yml`):

```yaml
filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /var/log/glance/glance-api.log
    json.keys_under_root: true
    json.add_error_key: true
    fields:
      service: glance
      environment: production

output.elasticsearch:
  hosts: ["elasticsearch:9200"]
  index: "openstack-glance-%{+yyyy.MM.dd}"
```

### 9.3. Sử dụng Promtail + Grafana Loki

```yaml
# /etc/promtail/config.yml
scrape_configs:
  - job_name: glance
    static_configs:
      - targets:
          - localhost
        labels:
          job: glance
          host: controller
          __path__: /var/log/glance/glance-api.log
    pipeline_stages:
      - regex:
          expression: '^(?P<timestamp>\S+ \S+) (?P<pid>\d+) (?P<level>\w+) (?P<logger>\S+)'
      - labels:
          level:
          logger:
```

## Tóm tắt nhanh

|      Chủ đề      | Thông tin quan trọng                                           |
|------------------|----------------------------------------------------------------|
| **Vị trí log**   | `/var/log/glance/glance-api.log`                               |
| **Cấu hình**     | Section `[DEFAULT]` trong `glance-api.conf`                    |
| **Bật debug**    | `debug = true` + restart hoặc SIGHUP                           |
| **Log format**   | `timestamp PID level logger [request_id user project] message` |
| **Log rotation** | Dùng `logrotate` Linux thay vì rotation trong config           |
| **Lệnh xem log** | `tail -f`, `grep`, `journalctl -u glance-api`                  |
| **Tích hợp**     | Syslog, ELK Stack (Filebeat), Loki (Promtail)                  |
| **Log level**    | DEBUG > INFO > WARNING > ERROR > CRITICAL                      |
