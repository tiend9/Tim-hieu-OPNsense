# CÀI ĐẶT VÀ CẤU HÌNH MAGNUM

> **Phiên bản tham chiếu**: OpenStack **2026.1 Gazpacho** + Kolla-Ansible **19.x**

## I. CÀI MAGNUM (KOLLA-ANSIBLE HOẶC THỦ CÔNG)

Việc cài đặt và khởi chạy các container dịch vụ của Magnum có thể thực hiện tối ưu bằng cách sử dụng công cụ tự động hóa Kolla-Ansible hoặc cài đặt thủ công các package dịch vụ trên hệ thống.

### 1. Triển khai bằng Kolla-Ansible (Khuyến nghị cho Production)

Kolla-Ansible tự động tạo cơ sở dữ liệu, khởi tạo dịch vụ Keystone và thiết lập cấu hình container tương thích tuyệt đối cho hai tiến trình lõi:

- **`magnum-api`**: Cổng tiếp nhận các API requests từ người dùng và CLI.
- **`magnum-conductor`**: Xử lý logic nghiệp vụ và phối hợp với Heat để xây dựng hạ tầng Kubernetes.

Các bước thực hiện trên Deployment Node:

```bash
# 1. Truy cập file globals.yml:
nano /etc/kolla/globals.yml

# Kích hoạt dịch vụ Magnum:
enable_magnum: "yes"

# 2. Chạy playbook deploy tag magnum:
kolla-ansible -i /etc/kolla/multinode deploy --tags magnum
```

### 2. Cấu hình thủ công trên node Controller

Nếu cài đặt không thông qua container, ta cần thực hiện tạo database và khai báo dịch vụ trong Keystone thủ công:

```bash
# 1. Tạo database cho Magnum trong MariaDB:
mysql -u root -p -e "CREATE DATABASE magnum DEFAULT CHARACTER SET utf8;"
mysql -u root -p -e "GRANT ALL PRIVILEGES ON magnum.* TO 'magnum'@'localhost' IDENTIFIED BY 'Tien123_db_pass';"
mysql -u root -p -e "GRANT ALL PRIVILEGES ON magnum.* TO 'magnum'@'%' IDENTIFIED BY 'Tien123_db_pass';"

# 2. Đăng ký tài khoản hệ thống trong Keystone:
openstack user create --domain default --password Tien123_magnum_pass magnum
openstack role add --project service --user magnum admin

# 3. Đăng ký dịch vụ (Service Entity):
openstack service create --name magnum --description "OpenStack Container Infrastructure Management Service" container-infra

# 4. Đăng ký các Endpoint của API:
openstack endpoint create --region RegionOne container-infra public http://controller:8989/v1
openstack endpoint create --region RegionOne container-infra internal http://controller:8989/v1
openstack endpoint create --region RegionOne container-infra admin http://controller:8989/v1
```

## II. CÁC THAM SỐ QUAN TRỌNG TRONG MAGNUM.CONF

File cấu hình chính của Magnum nằm tại `/etc/magnum/magnum.conf`. Đối với hệ thống Kolla-Ansible, các cấu hình ghi đè vĩnh viễn cần được đặt tại `/etc/kolla/config/magnum.conf`.

### 1. Kết nối Keystone, Database, Message Queue

Khai báo tài khoản xác thực hệ thống, cơ sở dữ liệu trung tâm và hàng đợi truyền tin RabbitMQ:

```ini
[database]
connection = mysql+pymysql://magnum:Tien123_db_pass@controller/magnum

[DEFAULT]
# Cấu hình kết nối RabbitMQ
transport_url = rabbit://openstack:Tien123_mq_pass@controller:5672/

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = magnum
password = Tien123_magnum_pass
```

### 2. Cấu hình Keystone Domain & Trust (Bắt buộc cho Magnum)

Tương tự như Heat, Magnum cần một Domain chuyên dụng và tài khoản Admin để tự động quản lý vòng đời của các tài nguyên tạm thời của cụm K8s và ủy quyền sinh certificate:

```ini
[trust]
# Tên của domain chuyên biệt của Magnum trong Keystone
trustee_domain_name = magnum
# User admin quản trị domain này
trustee_domain_admin = magnum_domain_admin
trustee_domain_admin_password = Tien123_domain_admin_pass
```

### 3. Tích hợp Barbican (TLS) và Octavia (LoadBalancer)

Để đảm bảo cụm Kubernetes được bảo mật tối đa và có thể điều phối tải tự động từ bên ngoài, Magnum tích hợp sâu sắc với Barbican và Octavia:

```ini
[certificates]
# Định nghĩa dịch vụ quản lý chứng chỉ TLS cho cụm Kubernetes
cert_manager_type = barbican

[octavia]
# Tên nhà cung cấp dịch vụ Load Balancer (mặc định: octavia)
octavia_provider = octavia
```

### 4. Định nghĩa các Driver hỗ trợ cụm container

Khai báo danh sách các driver được phép sử dụng để sinh ra cụm Kubernetes:

```ini
[drivers]
# Kích hoạt driver cho Fedora CoreOS và Ubuntu
enabled_drivers = k8s_fedora_coreos_v1,k8s_ubuntu_v1
```

## III. SYNC DATABASE VÀ KHỞI ĐỘNG SERVICE

Nếu deploy bằng phương pháp thủ công, sau khi cấu hình hoàn tất file `magnum.conf`, ta cần khởi tạo cơ sở dữ liệu và khởi động dịch vụ:

### 1. Đồng bộ cơ sở dữ liệu (Database Sync)

```bash
# Thực hiện tạo cấu trúc các bảng dữ liệu của Magnum:
magnum-db-manage upgrade
```

### 2. Khởi động các dịch vụ

Bật dịch vụ chạy cùng hệ thống và khởi động tiến trình:

```bash
# Khởi động dịch vụ API và Conductor:
systemctl enable magnum-api magnum-conductor
systemctl start magnum-api magnum-conductor
```

> [!NOTE]
> Đối với **Kolla-Ansible**, các container sẽ tự động thực hiện DB migration trong pha deploy. Ta không cần chạy lệnh nâng cấp DB thủ công mà chỉ cần kiểm tra trạng thái hoạt động của các container Docker trên node Controller:
>
> `docker ps | grep magnum`

## IV. KIỂM TRA SERVICE HOẠT ĐỘNG: OPENSTACK COE SERVICE LIST

Sau khi cài đặt xong, hãy xác minh xem các tiến trình Magnum đã đăng ký và hoạt động chính xác trong cụm chưa:

### 1. Kiểm tra trạng thái dịch vụ (Service List)

Sử dụng CLI COE (Container Orchestration Engine) để kiểm tra các conductor worker:

```bash
source /etc/kolla/admin-openrc

# Kiểm tra trạng thái hoạt động của Magnum Conductor:
openstack coe service list
```

**Output mong đợi**:

```text
+----+--------------+-------------------+-------+----------+-----------------+
| id | host         | binary            | state | disabled | updated_at      |
+----+--------------+-------------------+-------+----------+-----------------+
|  1 | controller01 | magnum-conductor  | up    | False    | 2026-06-01...   |
+----+--------------+-------------------+-------+----------+-----------------+
```

### 2. Kiểm tra tính năng API Endpoint

Đảm bảo endpoint API dịch vụ `container-infra` đã xuất hiện trong danh mục dịch vụ của Keystone:

```bash
# Kiểm tra danh mục dịch vụ trong hệ thống:
openstack catalog list | grep container-infra
```

### 3. Thử nghiệm liệt kê các template hiện có

```bash
# Lệnh kiểm tra danh sách ClusterTemplate hiện tại (mới cài đặt xong sẽ trống):
openstack coe cluster template list
```

Khi lệnh trên trả về kết quả rỗng không kèm theo thông báo lỗi kết nối API (`Connection Refused` hoặc `Unauthorized`), hệ thống cài đặt và cấu hình Magnum đã hoàn thành xuất sắc và sẵn sàng cho việc khai báo cụm Kubernetes.
