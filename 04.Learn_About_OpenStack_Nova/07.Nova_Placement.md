# TÌM HIỂU NOVA PLACEMENT

## I. TÌM HIỂU TỔNG QUAN VỀ NOVA PLACEMENT

### 1. Nova placement là gì?

**Placement** là **Placement HTTP API** , là service chịu trách nhiệm quản lí tài nguyên và quyết định compute node nào có đủ tài nguyên để chạy VM.

Service này được tách riêng từ OpenStack Nova từ phiên bản Ocata/Pike để cải thiện khả năng Scale. Và cũng để các project khác có thể dùng (Xưa chỉ có Project Nova có thể dùng)

Ví dụ: Các project có thể sử dụng placment:

- Nova (compute)
- OpenStack Neutron
- OpenStack Cyborg

Các project này có thể:

- Đăng ký tài nguyên
- Xoá tài nguyên
- Cập nhật tài nguyên

Placement lưu thông tin:

| Resource    | Ví dụ        |
| ----------- | ------------ |
| CPU         | VCPU         |
| RAM         | MEMORY_MB    |
| Disk        | DISK_GB      |
| Network     | SRIOV_NET_VF |
| Accelerator | FPGA         |

### 2. Placement dùng mô hình Resource Provider

=> Placement coi mỗi **nơi cung cấp tài nguyên** là một **Resource Provider**

Ví dụ:

| Resource Provider | Tài nguyên |
| ----------------- | ---------- |
| Compute Node      | CPU, RAM   |
| Storage Pool      | DISK       |
| Network Pool      | IP         |

Ví dụ: Khi VM dùng

```text
CPU  -> compute node
RAM  -> compute node
Disk -> storage pool
IP   -> IP pool
```

=> **Placement** sẽ ghi nhận **VM tiêu thụ tài nguyên từ nhiều Provider khác nhau.**.

### 3. Khái niệm Resource Class

Resource Class = loại tài nguyên

Ví dụ:

| Resource class | Ý nghĩa    |
| -------------- | ---------- |
| VCPU           | CPU        |
| MEMORY_MB      | RAM        |
| DISK_GB        | Disk       |
| SRIOV_NET_VF   | SR-IOV NIC |

Ngoài ra có thể tạo Custom:

```text
Custom_GPU
Custom_FPGA
```

### 4.Khái niệm Inventory

Inventory = **Số lượng tài nguyên mà provider có**.

Ví dụ: `VM1` dùng

```text
VCPU: 2
MEMORY_MB: 4096
DISK_GB: 40
```

=> **Placement lưu inventory này**

### 5. Allocation

**Allocation** = Tài nguyên cấp phát cho VM

Ví dụ: `VM1` dùng

```text
VCPU: 2
MEMORY_MB: 4096
DISK_GB: 40
```

Placement ghi:

```text
consumer = VM1
allocation = resources
```

### 6. Khái niệm Allocation

Allocation = **Tài nguyên đã cấp** cho VM.

Ví dụ: `VM1` dùng

```text
VCPU: 2
MEMORY_MB: 4096
DISK_GB: 40
```

Placement ghi:

```text
consumer = VM1
allocation = resources
```

### 7. Khái niệm Traits

Trait = **Đặc điểm của Resource Provider**

Ví dụ:

| Trait                       | Ý nghĩa             |
| --------------------------- | ------------------- |
| STORAGE_DISK_SSD            | disk là SSD         |
| HW_CPU_X86_AVX2             | CPU hỗ trợ AVX2     |
| COMPUTE_VOLUME_MULTI_ATTACH | hỗ trợ multi attach |

=> VM có thể yêu cầu Traits

VÍ dụ:

```text
required=STORAGE_DISK_SSD
```

### 8. `NUMA` Trong OpenStack Nova và OpenStack Placement

`NUMA` node được mô hình thành **resource provider con**.

Ví dụ:

```text
Compute Node
 ├── NUMA1
 │     └── VCPU
 └── NUMA2
       └── VCPU
```

Placement có thể cấp tài nguyên như:

```text
NUMA1 -> 2 VCPU
Compute node -> RAM
Shared storage -> Disk
```

#### Tại sao OpenStack phải quan tâm `NUMA`?

Một số workload yêu cầu:

- latency thấp
- CPU và RAM gần nhau

Ví dụ:

- NFV
- DPDK
- GPU workload

OpenStack có thể pin VM vào NUMA node:

```text
VM -> NUMA1
```

→ hiệu năng tốt hơn.

**Lưu ý**: **Placement** không **schedule trực tiếp** `VM` vào **Compute Node**, mà schedule vào `NUMA` node bên trong **Compute Node**.

### 9. Khái niệm Provider Tree

Placement hỗ trợ **cấu trúc cây tài nguyên**

Ví dụ:

```text
Compute Node
 ├── NUMA1
 │    └── VCPU
 └── NUMA2
      └── VCPU
```

**Hoặc**:

![Nova](./images/Nova_18.png)

![Nova](./images/Nova_19.png)

```text
Compute Node
 ├── NIC
 ├── GPU
 └── FPGA
```

Mục đích hỗ trợ các mô hình:

- mô hình NUMA
- SRIOV
- accelerator

### 10. Khái niệm Sharing Provider

Provider có thể chia sẻ tài nguyên giữa nhiều ComputeNode

Ví dụ:

![Nova](./images/Nova_17.png)

```text
Shared Storage
   │
 ┌─┴─────┐
CN1     CN2
```

-> Disk dùng chung.

-> Trait dùng để bật sharing:

```text
MISC_SHARES_VIA_AGGREGATE
```

### 11. Nova dùng Placement như thế nào

Có 2 component của OpenStack Nova Tương tác với Placement:

#### `nova-compute`

Nhiệm vụ:

- tạo resource provider
- cập nhật inventory
- cập nhật traits

#### `nova-scheduler`

Khi tạo VM:

`Bước1`: Scheduler gửi request tới Placement

```bash
GET /allocation_candidates
```

`Bước 2`: Placement trả về:

```text
list compute node có đủ resource
```

`Bước 3`: Scheduler chọn host tốt nhất.

### 12. Allocation Candidates (Ứng viên cấp tài nguyên)

API quan trọng nhất:

```bash

```

Ví dụ:

```bash
GET /allocation_candidates?
resources=VCPU:1,MEMORY_MB:512,DISK_GB:500
```

=> Placement trả về các host có thể chạy VM.

### 13. Aggregates

Aggregate = nhóm host.

Ví dụ:

```text

 ├─ compute1
 └─ compute2
```

VM có thể yêu cầu:

```text
member_of=aggA
```

### 14. Filtering

Placement cho phép lọc host theo nhiều điều kiện.

**theo resource**:

- VCPU
- RAM
- DISK

**theo trait**:

```bash
required=SSD
```

**theo aggregate**:

```bash
member_of=aggA
```

**theo provider tree**:

```bash
in_tree=<uuid>
```

### 18. Cơ chế `allocations` và `consumer_generation`

Trong **OpenStack Placement**, mỗi **VM (consumer)** sẽ có **allocations** – tức tài nguyên mà nó đang sử dụng.

Để tránh lỗi **ghi đè đồng thời (concurrent write)**, Placement dùng:

`consumer_generation`

**Ý nghĩa**:

- Mỗi lần allocation thay đổi → generation tăng
- Client phải gửi generation hiện tại khi update allocation

Nếu generation không khớp:

```bash
HTTP 409 Conflict
```

→ Client phải:

- đọc lại allocations
- gửi request lại

**Mục đích**: tránh **race condition** khi nhiều service cùng sửa allocation.

#### 19. `API PUT /allocations/{consumer_uuid}`

**API này** dùng để **thay thế allocations** của một **consumer (VM)**.

Đặc điểm:

- Gửi toàn bộ **allocation mới**
- Có thể gửi **empty allocations**

Ví dụ:

```bash
allocations: {}
```

→ **xoá toàn bộ allocation** của VM (Cách này an toàn hơn DELETE vì có kiểm tra generation)

### 20. Cảnh báo microversion (< 1.28)

Cảnh báo nhấn mạnh:

`Không được dùng API allocation với microversion < 1.28`

Lý do:

- Không kiểm tra generation
- Dễ gây **allocation corruption**

Do đó:

`luôn dùng microversion >= 1.28`

### 21. Allocation Candidates với Nested Provider (v1.29)

Từ version Rocky:

API:

```bash
GET /allocation_candidates
```

-> có thể trả về resource từ **nested resource providers**

Ví dụ:

```text
Compute node
 ├─ NUMA1
 ├─ NUMA2
 └─ NIC
```

Placement có thể combine:

```text
NUMA1 + Disk + NIC
```

-> để tạo allocation.

### 22. `API /reshaper` (v1.30)

API:

```bash
POST /reshaper
```

=> Dùng để thay đổi cấu trúc **resource provider**.

Ví dụ:

- Trước:

```text
Compute Node
   └── DISK
```

- Sau:

```text
Compute Node
   └── Storage Provider
          └── DISK
```

`reshaper` sẽ:

- chuyển inventory
- cập nhật allocations

**Lưu ý quan trọng**: Chỉ dùng khi topology thay đổi.

### 23. `in_tree` query parameter (v1.31)

API:

```bash
GET /allocation_candidates
```

=> Có thể giới hạn resource trong **một provider tree**.

API:

```bash
GET /allocation_candidates
```

-> Có thể giới hạn resource trong một provider tree.

Ví dụ:

```bash
?resources=VCPU:1
&in_tree=<compute_uuid>
```

-> Chỉ lấy resource trong compute đó.

### 24. Forbidden Aggregates (v1.32)

Placement hỗ trợ **loại trừ aggregate**.

Ví dụ:

```bash
member_of=!agg4
```

→ host không được nằm trong agg4

Kết hợp:

```bash
member_of=in:agg1,agg2
member_of=agg3
member_of=!agg4
```

Ý nghĩa:

host phải:

`(agg1 OR agg2) AND agg3 AND NOT agg4`

### 25. Request Group Suffix (v1.33)

Placement hỗ trợ **group request theo tên** thay vì số.

Giả sử:

- Trước:

```bash
resources1
resources2
```

- Sau:

```bash
resources_COMPUTE
resources_NETWORK
```

-> Giúp nhiều service(`nova`,`neutron`,...) gửi request chung.

### 26. `mappings` trong `allocation_candidates` (v1.34)

Response của API:

```bash
GET /allocation_candidates
```

có thêm:`mappings`(đường map dẫn đến)

Nó cho biết:

```text
request group -> resource provider
```

Ví dụ:

```text
compute -> CN1
network -> NIC1
disk -> storage1
```

### 27. `root_required` filter (v1.35)

Filter **Trait của root Provider**.(Bộ lọc Traits)

Ví dụ:

```text
root_required=HW_CPU_X86_AVX2
```

-> Chỉ có ComputeNode có trait này.

### 28. `same_subtree` (v1.36)

Đảm bảo nhiều resource phải nằm trong **cùng subtree**.

Ví dụ:

`CPU+GPU`

-> Phải nằm trong cùng Compute Node.

### 29. Re-parenting Resource Provider(v1.37)

Có thể đổi parent của resource provider.

API:

```bash
PUT /resource_providers/{uuid}
```

Ví dụ:

- NIC provider:

  - chuyển từ:`Compute1`
  - sang:`Compute2`

Hoặc:

```bash
parent_provider_uuid = null
```

→ trở thành root provider.

## II. CLI TOOl CỦA PLACEMENT

### 1. Placement-manage

-> Là 1 admin tool

Ví dụ:

`placement-manage db sync`

→ upgrade database.

`placement-manage db online_data_migrations`

→ migrate dữ liệu.

### 2. Placement-status

-> Tool kiểm tra hệ thống.

Ví dụ:

`placement-status upgrade check`

→ kiểm tra readiness trước khi upgrade.

### 3. File cấu hình

Gồm 2 file chính:

- `placement.conf` -> Chứa config Service
- `policy.yaml`    -> Quy định **RBAC** cho **API**

### 4. Placement API Policy (Quyền truy cập API)

Ví dụ:

```bash
GET /resource_providers/{uuid}/usages
```

-> lấy **resource usage** của một **resource provider**

Ta có Policy:

```bash
rule:admin_or_service_api
```

Nghĩa là chỉ:

- admin
- service (như Nova)

-> mới gọi được.

### 5. Logging Configuration (Các option trong `placement.conf`)

Các Option quan trọng:

- **Debug**:

```bash
debug=True
```

-> Bật log DEBUG

- **log_file**:

```bash
log_file=/var/log/placement/placement.log
```

-> Add direct file log.

- **log_rotation_type**(Có 3 kiểu rotate log):

| Type     | Meaning                |
| -------- | ---------------------- |
| interval | rotate theo thời gian  |
| size     | rotate theo dung lượng |
| none     | không rotate           |

- **max_logfile_size_mb**:

```ini
max_logfile_size_mb=200
```

-> Add dung lượng tối đa file log

=> Còn rất nhiều cấu hình khác liên quan đến Databases,Optimizations, Advance config trong file `placement.conf`. Ta có thể tham khảo ở tài liệu [sau](https://docs.openstack.org/placement/latest).

## III. DEPLOYMENT PLACEMENT

Theo tài liệu có 3 bước chính:

1. Deploy API service
2. Sync database
3. Tạo user + endpoint trong Keystone + v.v

### `Bước 1` — Deploy Placement API

Placement chạy như **WSGI application**.

- `WSGI` = Web Server Gateway Interface.

-> Nó cho phép Python app chạy trong web server.

Placement cung cấp script: `placement-api`

Nó có thể chạy trên nhiều web server:

| Web server | Module          |
| ---------- | --------------- |
| Apache     | mod_wsgi        |
| Apache     | mod_proxy_uwsgi |
| Nginx      | uwsgi           |
| Nginx      | gunicorn        |

Ví dụ: Deploy **bằng DevStack**

DevStack mount Placement ở:

`http://host/placement`

-> Không dùng port riêng.

### `Bước 2` — Synchronize Database

Placement có database riêng.

Ví dụ:

`placement`

Tạo database:

`CREATE DATABASE placement;`

Tạo user:

`GRANT ALL PRIVILEGES ON placement.* TO 'placement'@'localhost'
IDENTIFIED BY 'password';`

Config DB trong `placement.conf`:

```bash
[placement_database]
connection = mysql+pymysql://placement:PASS@controller/placement
```

Tạo bảng DB: Chạy

`placement-manage db sync`

Lệnh này:

- tạo tables
- chạy migrations
- update schema

### `Bước 3` — Tạo User trong Keystone

Placement cần authenticate với: **OpenStack Keystone**.

Tạo user:

`openstack user create placement`

Gán role:

`openstack role add --project service --user placement admin`

### Tạo Service trong Service Catalog

-> Trong Keystone mỗi service phải đăng ký.

Tạo service:

`openstack service create placement`

Service catalog:

```bash
+-------------+
| Service     |
+-------------+
| nova        |
| neutron     |
| glance      |
| cinder      |
| placement   |
+-------------+
```

### Tạo Endpoint

**Endpoint** = **URL API**.

Tạo 3 endpoint:

```bash
public
internal
admin
```

Ví dụ:

`http://controller:8778`

Lệnh:

`openstack endpoint create placement public http://controller:8778`

#### Config `placement.conf`

File:

`/etc/placement/placement.conf`

DB config:

```bash
[placement_database]
connection = mysql+pymysql://placement:pass@controller/placement

Keystone auth
[api]
auth_strategy = keystone

Keystone token middleware
[keystone_authtoken]
auth_url = http://controller:5000
username = placement
password = PASS
project_name = service
```

=> Placement dùng token của Keystone để xác thực request.

### Start Placement Service

Ví dụ chạy bằng:

`uwsgi`

Command:

```bash
uwsgi -M --http :8778 \
--wsgi-file /usr/local/bin/placement-api \
--processes 2 --threads 10
```

#### Verify Placement

Test bằng curl:

`curl http://controller:8778`

Output:

```JSON
{
 "versions": [
   {
     "id": "v1.0",
     "status": "CURRENT"
   }
 ]
}
```

### Kiểm tra trạng thái Placement

Command:

`placement-status upgrade check`

Kiểm tra:

- database schema
- consumer state
- root provider

### Kiểm tra resource classes

Command:

`openstack resource class list`

### Kiểm tra traits

Command:

`openstack trait list`

## IV. Tại sao Service Nova Placement lại quan trọng ?

### 1. Placement là trung tâm quản lý tài nguyên của cloud

Trong cloud OpenStack có nhiều compute node:

- Compute1
- Compute2
- Compute3

Mỗi node có tài nguyên:

```text
CPU
RAM
Disk
PCI
NUMA
GPU
Network bandwidth
```

Placement lưu toàn bộ thông tin này dưới dạng:

```text
Resource Provider
Inventory
Allocation
```

Ví dụ:

```yaml
Compute1
  VCPU: 16
  RAM: 64GB
  DISK: 1TB
```

Placement biết:

- Đã dùng bao nhiêu
- Còn lại bao nhiêu

### 2. Placement giúp Nova Scheduler chọn đúng host

Khi user tạo VM:

```bash
openstack server create
```

Flow thực tế:

```text
User
 ↓
Nova API
 ↓
Nova Scheduler
 ↓
Placement
 ↓
Candidate hosts
 ↓
Nova chọn host
 ↓
Nova Compute tạo VM
```

Nova Scheduler sẽ hỏi Placement:

```text
host nào còn đủ:
CPU
RAM
Disk
```

Placement trả về:

- Compute1
- Compute3

Scheduler mới chạy tiếp:

```text
filter
weigher
```

→ chọn host tốt nhất.

### 3. Placement tracking resource chính xác

Trước phiên bản OpenStack Newton, Nova tự quản lý resource.

Nhược điểm:

```sql
race condition
over allocation
state không đồng bộ
```

Ví dụ:

```text
Compute1
CPU: 16
```

Hai request VM cùng lúc:

```rust
VM1 -> 8 CPU
VM2 -> 8 CPU
```

Scheduler có thể thấy:

```text
CPU free = 16
```

→ schedule cả hai.

Kết quả:

```text
CPU overcommit
```

Placement giải quyết bằng:

```text
atomic allocation
```

Placement database đảm bảo:

```text
resource usage luôn consistent
```

### 4 Placement hỗ trợ tài nguyên phức tạp

Cloud hiện đại không chỉ có CPU và RAM.

Placement quản lý:

```text
GPU
SRIOV NIC
FPGA
NUMA topology
network bandwidth
shared storage
```

Ví dụ VM yêu cầu:

```text
2 vCPU
4GB RAM
1 GPU
```

Nova Scheduler sẽ hỏi Placement:

```text
host nào có GPU + CPU + RAM
```

-> Placement trả host phù hợp.

### 5 Placement cho phép mô hình tài nguyên phức tạp

Placement hỗ trợ **Provider tree**.

Ví dụ:

```text
Compute Node
 ├── NUMA1
 │    └── GPU
 ├── NUMA2
 └── NIC
```

Placement có thể allocate:

```text
CPU từ NUMA1
GPU từ GPU provider
RAM từ compute
```

Điều này rất quan trọng với:

```text
NUMA pinning
SRIOV
accelerator
```

### 6. Placement giúp cloud scale lớn

Trong cloud lớn:

```text
1000+ compute node
```

->Scheduler cần query resource rất nhanh.

Placement cung cấp API:

```bash
GET /allocation_candidates
```

Nó trả candidate host cực nhanh vì:

```text
resource index trong DB
```

Nếu Nova tự track resource thì:

```text
scheduler phải query từng compute node
```

→ không scale được.

### 7. Placement dùng chung cho nhiều service

Placement không chỉ phục vụ Nova.

Các service khác có thể dùng:

- OpenStack Neutron (network bandwidth)
- OpenStack Cyborg (accelerator)
- OpenStack Ironic (bare metal)

=> Placement trở thành resource registry của cloud.

### 8. Placement tách scheduling logic khỏi Nova

Kiến trúc hiện đại của OpenStack:

```bash
Nova Scheduler
      |
      v
Placement
```

Nova chỉ:

```nginx
ask resource
```

Placement:

```nginx
track resource
```

Kiến trúc này giúp:

- modular
- scalable
- maintainable

### 9. Nếu không có Placement

Nếu Placement down:

-> Nova Scheduler không tìm được host

Khi tạo VM sẽ lỗi:

-> `No valid host found` (Vì Nova không biết host nào còn tài nguyên).
