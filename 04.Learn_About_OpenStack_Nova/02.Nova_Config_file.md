# NOVA CONFIG FILE

> Tài liệu này cập nhật theo **OpenStack 2026.1 Gazpacho**. Trọng tâm là `/etc/nova/nova.conf`, cấu hình controller node, compute node, Cells v2, Placement, Neutron, VNC console và các option cũ không nên dùng nữa.

## 1. File cấu hình chính

Nova dùng các file chính sau:

| File | Nằm ở đâu | Vai trò |
|------|-----------|---------|
| `/etc/nova/nova.conf` | Controller và Compute | File cấu hình chính của Nova |
| `/etc/nova/nova-compute.conf` | Compute | Cấu hình riêng cho hypervisor/libvirt trên một số distro |
| `/etc/nova/api-paste.ini` | Controller | WSGI/API pipeline, thường giữ mặc định |
| `/etc/nova/policy.yaml` | Controller | RBAC policy, chỉ chỉnh khi cần thay đổi quyền |
| `/var/log/nova/*.log` | Controller và Compute | Log debug service |

Trong OpenStack hiện đại, **không nên copy nguyên file mẫu rất dài**. Cách tốt hơn là chỉ thêm hoặc sửa các section cần thiết, giữ default còn lại của package.

## 2. Các option cũ cần bỏ

Nếu tài liệu/lab cũ còn các dòng sau, không nên dùng cho OpenStack 2026.1:

```ini
[DEFAULT]
rpc_backend = rabbit
dhcpbridge_flagfile = /etc/nova/nova.conf
dhcpbridge = /usr/bin/nova-dhcpbridge
force_dhcp_release = True
libvirt_use_virtio_for_bridges = True
verbose = True
ec2_private_dns_show_ip = True
enabled_apis = ec2,osapi_compute,metadata
use_neutron = True
firewall_driver = nova.virt.firewall.NoopFirewallDriver

[oslo_messaging_rabbit]
rabbit_host = controller
rabbit_userid = openstack
rabbit_password = RABBIT_PASS

[keystone_authtoken]
auth_uri = http://controller:5000
auth_url = http://controller:35357

[vnc]
vncserver_listen = 0.0.0.0
vncserver_proxyclient_address = $my_ip
```

Lý do:

- `rpc_backend` và `[oslo_messaging_rabbit] rabbit_host` đã được thay bằng `transport_url`.
- Keystone admin port `35357` không còn dùng trong Keystone v3 hiện đại.
- EC2 API không còn là API baseline trong Nova.
- `nova-network` đã được thay bằng Neutron trong triển khai mới.
- Các option VNC cũ đổi thành `server_listen` và `server_proxyclient_address`.
- `firewall_driver` kiểu Nova firewall không còn là hướng cấu hình chính khi dùng Neutron security group.

## 4. Cấu hình Keystone, database và endpoint cho Nova

Thực hiện trên Controller.

### 4.1. Tạo database

```bash
mysql
```

```sql
CREATE DATABASE nova_api;
CREATE DATABASE nova;
CREATE DATABASE nova_cell0;

GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'localhost' IDENTIFIED BY 'Tien123';
GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'%' IDENTIFIED BY 'Tien123';

GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'localhost' IDENTIFIED BY 'Tien123';
GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'%' IDENTIFIED BY 'Tien123';

GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'localhost' IDENTIFIED BY 'Tien123';
GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'%' IDENTIFIED BY 'Tien123';

FLUSH PRIVILEGES;
EXIT;
```

### 4.2. Tạo user, service, endpoint

```bash
source /root/admin-openrc

openstack user create --domain default --password Tien123 nova
openstack role add --project service --user nova admin

# Khuyến nghị cho service user token. Nếu role service đã tồn tại thì bỏ qua lỗi conflict.
openstack role create service
openstack role add --project service --user nova service

openstack service create --name nova \
  --description "OpenStack Compute" compute

openstack endpoint create --region RegionOne \
  compute public http://controller:8774/v2.1

openstack endpoint create --region RegionOne \
  compute internal http://controller:8774/v2.1

openstack endpoint create --region RegionOne \
  compute admin http://controller:8774/v2.1
```

## 5. Cấu hình Controller Node

Cài package:

```bash
apt update
apt -y install nova-api nova-conductor nova-novncproxy nova-scheduler
```

Mở file:

```bash
nano /etc/nova/nova.conf
```

Cấu hình tối thiểu nên có:

```ini
[api_database]
connection = mysql+pymysql://nova:Tien123@controller/nova_api

[database]
connection = mysql+pymysql://nova:Tien123@controller/nova

[DEFAULT]
transport_url = rabbit://openstack:Tien123@controller:5672/
my_ip = 10.0.0.5

[keystone_authtoken]
www_authenticate_uri = http://controller:5000/
auth_url = http://controller:5000/
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = nova
password = Tien123

[service_user]
send_service_user_token = true
auth_url = http://controller:5000/v3
auth_type = password
project_domain_name = Default
project_name = service
user_domain_name = Default
username = nova
password = Tien123

[vnc]
enabled = true
server_listen = $my_ip
server_proxyclient_address = $my_ip
novncproxy_base_url = http://192.168.122.5:6080/vnc_auto.html

[glance]
api_servers = http://controller:9292

[oslo_concurrency]
lock_path = /var/lib/nova/tmp

[placement]
region_name = RegionOne
project_domain_name = Default
project_name = service
auth_type = password
user_domain_name = Default
auth_url = http://controller:5000/v3
username = placement
password = Tien123

[neutron]
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
region_name = RegionOne
project_name = service
username = neutron
password = Tien123
service_metadata_proxy = true
metadata_proxy_shared_secret = Tien123

[cinder]
region_name = RegionOne

[scheduler]
discover_hosts_in_cells_interval = 300
```

> Nếu browser trên máy host không resolve được hostname `controller`, đặt `novncproxy_base_url` bằng IP mà browser truy cập được. Trong lab này là `192.168.122.5`.

## 6. Đồng bộ database và tạo Cells v2

Thực hiện trên Controller:

```bash
su -s /bin/sh -c "nova-manage api_db sync" nova
su -s /bin/sh -c "nova-manage cell_v2 map_cell0" nova
su -s /bin/sh -c "nova-manage cell_v2 create_cell --name=cell1 --verbose" nova
su -s /bin/sh -c "nova-manage db sync" nova
su -s /bin/sh -c "nova-manage cell_v2 list_cells" nova
```

Kỳ vọng thấy ít nhất:

```text
cell0
cell1
```

Restart service:

```bash
systemctl restart nova-api nova-scheduler nova-conductor nova-novncproxy
systemctl enable nova-api nova-scheduler nova-conductor nova-novncproxy
```

Kiểm tra:

```bash
systemctl status nova-api nova-scheduler nova-conductor nova-novncproxy --no-pager -l
openstack compute service list
```

## 8. Cấu hình hypervisor KVM/QEMU

Kiểm tra compute node có hỗ trợ ảo hóa phần cứng không:

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```

Nếu kết quả `>= 1`, thường dùng KVM mặc định.

Nếu kết quả `0`, mở:

```bash
nano /etc/nova/nova-compute.conf
```

Thêm hoặc sửa:

```ini
[libvirt]
virt_type = qemu
```

Restart:

```bash
systemctl restart nova-compute
systemctl enable nova-compute
systemctl status nova-compute --no-pager -l
```

## 9. Đưa Compute vào Cell

Sau khi `nova-compute` chạy, quay lại Controller:

```bash
source /root/admin-openrc

openstack compute service list --service nova-compute
su -s /bin/sh -c "nova-manage cell_v2 discover_hosts --verbose" nova
openstack compute service list
openstack hypervisor list
```

Nếu có nhiều compute node mới, mỗi lần thêm node nên chạy lại:

```bash
su -s /bin/sh -c "nova-manage cell_v2 discover_hosts --verbose" nova
```

Hoặc dùng tự động:

```ini
[scheduler]
discover_hosts_in_cells_interval = 300
```

## 10. Giải thích các section quan trọng

### 10.1. `[api_database]` và `[database]`

```ini
[api_database]
connection = mysql+pymysql://nova:Tien123@controller/nova_api

[database]
connection = mysql+pymysql://nova:Tien123@controller/nova
```

- `nova_api`: DB cho API layer, request spec, cell mapping, host mapping.
- `nova`: DB chính của cell mặc định, chứa instance và state compute.
- `nova_cell0`: DB cho instance build lỗi, được map bằng `nova-manage cell_v2 map_cell0`.

### 10.2. `[DEFAULT] transport_url`

```ini
[DEFAULT]
transport_url = rabbit://openstack:Tien123@controller:5672/
```

Đây là connection string tới RabbitMQ. Nova dùng RabbitMQ cho RPC giữa API, scheduler, conductor và compute.

Nếu compute log báo:

```text
AMQP server on controller:5672 is unreachable
```

hãy kiểm tra DNS/hosts, firewall, RabbitMQ user/password và port `5672`.

### 10.3. `[keystone_authtoken]`

```ini
[keystone_authtoken]
www_authenticate_uri = http://controller:5000/
auth_url = http://controller:5000/
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = nova
password = Tien123
```

Section này giúp Nova xác thực token user gửi vào Nova API. Không dùng `auth_uri`, không dùng port `35357`.

### 10.4. `[service_user]`

```ini
[service_user]
send_service_user_token = true
auth_url = http://controller:5000/v3
auth_type = password
project_domain_name = Default
project_name = service
user_domain_name = Default
username = nova
password = Tien123
```

Service user token rất quan trọng với các operation chạy lâu như live migration, snapshot, attach/detach volume. Nếu user token hết hạn giữa chừng, Nova vẫn có service token để gọi Neutron/Cinder/Glance làm cleanup hoặc post-action.

### 10.5. `[placement]`

```ini
[placement]
region_name = RegionOne
project_domain_name = Default
project_name = service
auth_type = password
user_domain_name = Default
auth_url = http://controller:5000/v3
username = placement
password = Tien123
```

Nova dùng Placement để query và claim tài nguyên. Nếu section này sai, scheduler có thể lỗi `NoValidHost` hoặc `Placement API` fail trong:

```bash
nova-status upgrade check
```

### 10.6. `[neutron]`

```ini
[neutron]
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
region_name = RegionOne
project_name = service
username = neutron
password = Tien123
service_metadata_proxy = true
metadata_proxy_shared_secret = Tien123
```

Nova gọi Neutron để tạo port và lấy thông tin network cho instance. Hai dòng metadata phải khớp với `/etc/neutron/metadata_agent.ini`:

```ini
[DEFAULT]
metadata_proxy_shared_secret = Tien123
```

Nếu secret không khớp, metadata thường trả `403 Forbidden`.

### 10.7. `[vnc]`

```ini
[vnc]
enabled = true
server_listen = 0.0.0.0
server_proxyclient_address = $my_ip
novncproxy_base_url = http://192.168.122.5:6080/vnc_auto.html
```

- `server_listen`: địa chỉ VNC server trên compute lắng nghe.
- `server_proxyclient_address`: địa chỉ mà `nova-novncproxy` dùng để kết nối tới compute.
- `novncproxy_base_url`: URL mà user/browser truy cập.

Nếu browser không vào console được nhưng VM vẫn chạy, kiểm tra dòng `novncproxy_base_url` trước.

### 10.8. `[glance]`

```ini
[glance]
api_servers = http://controller:9292
```

Nova cần Glance để lấy image khi boot instance từ image.

### 10.9. `[cinder]`

```ini
[cinder]
region_name = RegionOne
```

Nên cấu hình để Nova biết region của Cinder khi attach/detach volume hoặc boot-from-volume.

### 10.10. `[oslo_concurrency]`

```ini
[oslo_concurrency]
lock_path = /var/lib/nova/tmp
```

Thư mục lock file cho các tiến trình Nova.

## 11. Kiểm tra sau khi cấu hình

Trên Controller:

```bash
source /root/admin-openrc

openstack compute service list
openstack catalog list
openstack image list
openstack hypervisor list
nova-status upgrade check
```

Kết quả đẹp:

- `nova-scheduler`, `nova-conductor` trên controller có `State = up`.
- `nova-compute` trên compute có `State = up`.
- `openstack hypervisor list` thấy compute node.
- `nova-status upgrade check` báo `Success` cho Cells v2 và Placement API.

## 12. Troubleshooting nhanh

| Lỗi | Kiểm tra |
|-----|----------|
| `NoValidHost` | Placement, flavor/image extra specs, compute disabled/down, resource thiếu |
| Không thấy compute node | `nova-compute` log, RabbitMQ, `discover_hosts`, cell mapping |
| Console trắng/lỗi token | `[vnc]`, `nova-novncproxy`, firewall port `6080`, browser resolve hostname |
| VM không nhận IP | Neutron agent, DHCP namespace, provider mapping |
| Metadata 403 | `metadata_proxy_shared_secret` giữa Nova và Neutron không khớp |
| Attach volume fail | Cinder service, iSCSI/Ceph backend, `[cinder] region_name`, service user token |
| `Placement API` fail | `[placement]` auth, endpoint placement, service user/password |

Log thường xem:

```bash
journalctl -u nova-api -n 100 --no-pager
journalctl -u nova-scheduler -n 100 --no-pager
journalctl -u nova-conductor -n 100 --no-pager
journalctl -u nova-novncproxy -n 100 --no-pager
journalctl -u nova-compute -n 100 --no-pager

tail -n 100 /var/log/nova/nova-api.log
tail -n 100 /var/log/nova/nova-scheduler.log
tail -n 100 /var/log/nova/nova-conductor.log
tail -n 100 /var/log/nova/nova-compute.log
```
