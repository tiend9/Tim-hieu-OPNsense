# QUÁ TRÌNH QUẢN LÝ VÀ TRUY CẬP CONSOLE NOVA

> Tài liệu này cập nhật theo **OpenStack 2026.1 Gazpacho**. Trọng tâm là noVNC console, luồng token hiện đại, cấu hình `[vnc]`, cách debug lỗi console, và ghi chú thêm về serial console.

## I. CONSOLE TRONG OPENSTACK LÀ GÌ?

Console là kênh truy cập trực tiếp vào màn hình hoặc terminal của VM mà không cần SSH/RDP bên trong guest.

Console rất hữu ích khi:

- VM chưa có IP.
- Security group chưa mở SSH.
- Cloud-init lỗi.
- VM boot lỗi.
- Network của tenant đang hỏng.
- Cần nhìn màn hình cài đặt OS hoặc kernel panic.

OpenStack Nova hỗ trợ nhiều kiểu console:

| Kiểu console | Dùng cho | Ghi chú |
|--------------|----------|---------|
| noVNC | Console đồ họa qua browser | Phổ biến nhất trong lab và private cloud |
| SPICE | Console đồ họa nâng cao | Cần disable VNC nếu dùng SPICE |
| Serial | Console dạng text qua WebSocket | Hữu ích để xem boot log/kernel log |
| MKS | VMware vSphere | Dùng trong môi trường VMware |

Trong phần lớn lab KVM/QEMU, chỉ cần dùng **noVNC**.

## II. VNC VÀ noVNC LÀ GÌ?

**VNC** là giao thức truy cập màn hình từ xa. VNC truyền framebuffer, bàn phím và chuột giữa client và server.

Trong OpenStack:

- VNC server nằm ở compute node, do QEMU/libvirt tạo cho từng VM.
- User không kết nối trực tiếp tới VNC server đó.
- User mở console qua browser bằng **noVNC**.
- `nova-novncproxy` đứng giữa browser và VNC server của VM.

Mô hình ngắn gọn:

```text
Browser noVNC
  -> nova-novncproxy trên controller
  -> VNC server của VM trên compute node
  -> VM
```

## III. CÁC THÀNH PHẦN THAM GIA

| Thành phần | Vai trò |
|------------|---------|
| Horizon hoặc OpenStack CLI | Nơi user yêu cầu lấy console URL |
| `nova-api` | Nhận request lấy console URL |
| Nova database | Lưu thông tin token console hiện đại |
| `nova-novncproxy` | Proxy WebSocket/VNC giữa browser và compute |
| `nova-compute` | Quản lý instance và thông tin VNC của instance |
| libvirt/QEMU | Tạo VNC server thật cho VM |
| Browser noVNC client | Hiển thị console trong trình duyệt |

### Lưu ý về `nova-consoleauth`

Trong tài liệu cũ, luồng console thường có service `nova-consoleauth`.

Với Nova hiện đại:

- Token console đã được chuyển sang database từ Rocky.
- Service `nova-consoleauth` đã bị remove từ Train.
- Không cấu hình, không restart, không troubleshoot `nova-consoleauth` nữa.

Nếu gặp tài liệu còn nhắc `nova-consoleauth`, coi đó là tài liệu cũ.

## IV. LUỒNG TRUY CẬP noVNC CONSOLE

### Bước 1. User yêu cầu console URL

User mở console từ Horizon hoặc CLI:

```bash
openstack console url show --novnc <server>
```

Nova API nhận request:

```text
GET/POST console action
```

Nova kiểm tra:

- User có token Keystone hợp lệ không.
- User có quyền truy cập VM không.
- VM có tồn tại không.
- VM đang chạy trên compute nào.

### Bước 2. Nova tạo console token

Nova tạo token tạm thời cho console. Token này ánh xạ tới:

- Instance UUID.
- Compute host đang chạy instance.
- Console type, ví dụ `novnc`.
- Host/port VNC nội bộ.
- Thời gian sống của token.

Thời gian sống mặc định do option:

```ini
[consoleauth]
token_ttl = 600
```

`600` nghĩa là token sống 600 giây.

Nếu muốn proxy đóng session khi token hết hạn:

```ini
[consoleauth]
enforce_session_timeout = true
```

### Bước 3. Nova trả URL cho user

Ví dụ URL:

```text
http://192.168.122.5:6080/vnc_auto.html?path=%3Ftoken%3Dxxxx
```

Trong URL này:

- `192.168.122.5` là địa chỉ user/browser truy cập được.
- `6080` là port noVNC proxy.
- `token` là token console tạm thời.

### Bước 4. Browser kết nối tới `nova-novncproxy`

Browser mở noVNC client và kết nối tới:

```text
nova-novncproxy
```

Proxy kiểm tra token, tìm instance tương ứng, rồi xác định compute node và VNC port của VM.

### Bước 5. Proxy kết nối tới VNC server trên compute

Trên compute node, QEMU/libvirt tạo VNC server cho VM. Trong XML của VM có thể thấy dạng:

```xml
<graphics type='vnc' port='5901' listen='10.0.0.6'>
  <listen type='address' address='10.0.0.6'/>
</graphics>
```

`nova-novncproxy` sẽ kết nối tới địa chỉ compute được cấu hình bởi:

```ini
[vnc]
server_proxyclient_address = 10.0.0.6
```

### Bước 6. Dữ liệu console được proxy hai chiều

Sau khi kết nối thành công:

```text
Browser <-> nova-novncproxy <-> VNC server trên compute <-> VM
```

User nhìn thấy màn hình VM trong browser.

## V. CẤU HÌNH noVNC TRONG LAB

Ví dụ topology lab:

| Node | IP user/browser truy cập | IP management/internal |
|------|---------------------------|------------------------|
| Controller | `192.168.122.5` | `10.0.0.5` |
| Compute | `192.168.122.6` | `10.0.0.6` |

Trong lab này, browser trên máy thật thường truy cập controller qua mạng `192.168.122.0/24`, còn controller liên hệ compute qua mạng internal `10.0.0.0/24`.

### 1. Controller node

Service cần chạy:

```bash
systemctl status nova-novncproxy --no-pager -l
```

Kiểm tra port:

```bash
ss -lntp | grep 6080
```

Cấu hình thường nằm trong `/etc/nova/nova.conf`:

```ini
[vnc]
enabled = true
novncproxy_host = 0.0.0.0
novncproxy_port = 6080
```

Restart:

```bash
systemctl restart nova-novncproxy
```

### 2. Compute node

Trên compute node, cấu hình `/etc/nova/nova.conf`:

```ini
[vnc]
enabled = true
server_listen = 0.0.0.0
server_proxyclient_address = 10.0.0.6
novncproxy_base_url = http://192.168.122.5:6080/vnc_auto.html
```

Ý nghĩa:

| Option | Ý nghĩa |
|--------|---------|
| `enabled` | Bật VNC console cho instance |
| `server_listen` | Địa chỉ VNC server của QEMU lắng nghe trên compute |
| `server_proxyclient_address` | Địa chỉ mà `nova-novncproxy` dùng để kết nối tới compute |
| `novncproxy_base_url` | URL trả về cho user/browser |

Trong lab multi-node, lỗi hay gặp nhất là cấu hình `novncproxy_base_url` sai. Giá trị này phải là URL mà **browser của user truy cập được**, không nhất thiết là IP management nội bộ.

Restart compute:

```bash
systemctl restart nova-compute
```

## VI. KIỂM TRA noVNC

### 1. Lấy console URL

```bash
openstack console url show --novnc <server>
```

Kết quả ví dụ:

```text
+-------+------------------------------------------------------------+
| Field | Value                                                      |
+-------+------------------------------------------------------------+
| type  | novnc                                                      |
| url   | http://192.168.122.5:6080/vnc_auto.html?path=%3Ftoken...   |
+-------+------------------------------------------------------------+
```

Mở URL trong browser. Nếu URL dùng hostname như `controller` nhưng máy thật không resolve được, đổi `novncproxy_base_url` sang IP.

### 2. Kiểm tra service

Trên controller:

```bash
systemctl status nova-novncproxy --no-pager -l
journalctl -u nova-novncproxy -n 100 --no-pager
```

Trên compute:

```bash
systemctl status nova-compute --no-pager -l
journalctl -u nova-compute -n 100 --no-pager
```

### 3. Kiểm tra libvirt XML

Trên compute node:

```bash
virsh list --all
virsh dumpxml <instance-name-or-id> | grep -A3 "graphics type='vnc'"
```

Hoặc:

```bash
virsh dumpxml <instance-name-or-id> | grep -A5 graphics
```

Nếu không có `graphics type='vnc'`, kiểm tra lại `[vnc] enabled = true` và restart VM mới. Một số thay đổi console chỉ áp dụng cho instance tạo sau khi cấu hình đúng.

## VII. FIREWALL VÀ ROUTING CẦN MỞ

Luồng mạng của noVNC:

```text
User/browser
  -> controller:6080
  -> compute:5900+
```

Cần đảm bảo:

- User/browser truy cập được `novncproxy_base_url`.
- Controller chạy `nova-novncproxy` và mở port `6080`.
- Controller route được tới `server_proxyclient_address` của compute.
- Compute cho phép proxy kết nối tới VNC port nội bộ của instance.

Trong lab đơn giản, nếu dùng `ufw`:

```bash
ufw allow 6080/tcp
```

Trong production, nên giới hạn nguồn truy cập và dùng HTTPS cho console public endpoint.

## VIII. BẢO MẬT noVNC

Nếu public-facing noVNC chạy HTTP thuần, traffic giữa user và proxy có thể bị nghe lén. Nên đặt noVNC sau HTTPS endpoint hoặc load balancer TLS.

Cần phân biệt hai đoạn:

```text
User/browser -> nova-novncproxy
nova-novncproxy -> compute VNC server
```

HTTPS thường chỉ bảo vệ đoạn user tới proxy. Đoạn proxy tới compute vẫn có thể không mã hóa nếu chưa bật VNC proxy security.

Với QEMU/KVM, Nova hỗ trợ VeNCrypt để bảo vệ đoạn proxy tới compute. Ví dụ cấu hình trên proxy:

```ini
[vnc]
auth_schemes = vencrypt,none
vencrypt_client_key = /etc/pki/nova-novncproxy/client-key.pem
vencrypt_client_cert = /etc/pki/nova-novncproxy/client-cert.pem
vencrypt_ca_certs = /etc/pki/nova-novncproxy/ca-cert.pem
```

Trên compute/libvirt cần certificate tương ứng trong `/etc/pki/libvirt-vnc/` và bật TLS trong libvirt. Với lab học cơ bản có thể chưa cần bật phần này, nhưng production nên thiết kế bảo mật console cẩn thận.

## IX. SERIAL CONSOLE

**Serial console** là console dạng text. Nó hữu ích khi muốn xem boot log, kernel output hoặc login text console mà không cần giao diện đồ họa.

Luồng serial console:

```text
User
  -> nova-api lấy serial URL
  -> nova-serialproxy
  -> port serial trên compute
  -> VM
```

### 1. Cấu hình serial proxy

Trên node chạy proxy:

```ini
[serial_console]
serialproxy_host = 0.0.0.0
serialproxy_port = 6083
```

Trên compute:

```ini
[serial_console]
enabled = true
base_url = ws://192.168.122.5:6083/
proxyclient_address = 10.0.0.6
port_range = 10000:20000
```

Ý nghĩa:

| Option | Ý nghĩa |
|--------|---------|
| `enabled` | Bật serial console cho instance |
| `base_url` | URL WebSocket trả về cho user |
| `proxyclient_address` | Địa chỉ proxy dùng để kết nối tới compute |
| `port_range` | Dải port serial mà compute dùng cho instance |

### 2. Lấy serial console URL

```bash
openstack console url show --serial <server>
```

### 3. Xem console log không tương tác

Nếu chỉ cần xem log boot:

```bash
openstack console log show --lines 100 <server>
```

Không nên nhầm:

- `openstack console url show --novnc`: mở console đồ họa.
- `openstack console url show --serial`: mở serial console tương tác.
- `openstack console log show`: xem output console dạng log.

## X. TROUBLESHOOTING noVNC

| Triệu chứng | Nguyên nhân thường gặp | Cách kiểm tra |
|-------------|------------------------|---------------|
| Browser không mở được URL | Sai `novncproxy_base_url`, DNS không resolve, firewall chặn 6080 | Mở URL từ browser, `ss -lntp | grep 6080` |
| Console báo token invalid/expired | Token hết hạn, clock lệch, proxy/API lỗi | Lấy lại URL, kiểm tra NTP, `nova-novncproxy.log` |
| Console trắng | Proxy không kết nối được compute, VNC listen sai IP | `journalctl -u nova-novncproxy`, `virsh dumpxml` |
| All-in-one chạy được, multi-node lỗi | `server_proxyclient_address` hoặc route controller-compute sai | Ping/telnet từ controller tới compute |
| URL trả về hostname nội bộ | `novncproxy_base_url` dùng hostname user không resolve được | Đổi sang IP/VIP public |
| HTTPS console báo Origin mismatch | `novncproxy_base_url` không khớp scheme HTTP/HTTPS | Đặt URL đúng `https://...` |
| Không có VNC trong XML | `[vnc] enabled` sai hoặc VM tạo trước khi cấu hình | Kiểm tra `nova.conf`, tạo VM mới test |

Các lệnh debug nhanh:

```bash
openstack server show <server>
openstack console url show --novnc <server>
openstack console log show --lines 100 <server>
journalctl -u nova-novncproxy -n 100 --no-pager
journalctl -u nova-compute -n 100 --no-pager
```

## XI. TỔNG KẾT

noVNC trong Nova là cơ chế proxy console, không phải SSH và cũng không yêu cầu VM có network. User nhận một URL có token từ Nova API, browser kết nối tới `nova-novncproxy`, rồi proxy kết nối tới VNC server của VM trên compute node.

Các điểm cần nhớ:

- `nova-consoleauth` không còn là service trong Nova hiện đại.
- `novncproxy_base_url` là URL browser truy cập được.
- `server_proxyclient_address` là IP compute mà proxy kết nối tới được.
- Controller cần mở port noVNC, thường là `6080`.
- Nếu cần boot log dạng text, dùng `openstack console log show` hoặc serial console.
