# KEYSTONE SERVICE & ENDPOINT — CEILOMETER, AODH, GNOCCHI

> **Phiên bản tham chiếu**: OpenStack **2026.1 Gazpacho**

## I. TELEMETRY VÀ CEILOMETER — ĐĂNG KÝ KEYSTONE VÀ CẤU HÌNH XÁC THỰC

Từ các phiên bản OpenStack gần đây, dịch vụ Ceilometer API (`ceilometer-api`) đã bị loại bỏ hoàn toàn. Toàn bộ dữ liệu đo lường được đẩy thẳng sang Gnocchi API. Do đó, Ceilometer **không còn yêu cầu** khai báo Endpoint (Public/Internal/Admin) trong Service Catalog của Keystone nữa.

Tuy nhiên, các Agent của Ceilometer (`ceilometer-polling`, `ceilometer-notification`) vẫn cần một tài khoản định danh để xác thực với Keystone khi thu thập dữ liệu từ các dịch vụ khác.

### 1. Đăng ký Keystone User và Role cho Ceilometer

Ta tiến hành tạo tài khoản dịch vụ hệ thống cho Ceilometer trên Keystone Node:

```bash
source /etc/kolla/admin-openrc

# 1. Tạo tài khoản người dùng "ceilometer" trong project "service":
openstack user create --domain default --project service --password SECRET_PASS ceilometer

# 2. Gán vai trò "admin" cho tài khoản ceilometer để có quyền cào metric hệ thống:
openstack role add --project service --user ceilometer admin
```

### 2. Cấu hình xác thực: Section `[keystone_authtoken]`

Trong tệp cấu hình `/etc/ceilometer/ceilometer.conf`, các Agent sử dụng cấu hình sau để tự động xin cấp phát Token từ Keystone:

```ini
[service_credentials]
auth_type = password
auth_url = http://controller:5000/v3
username = ceilometer
password = SECRET_PASS
project_name = service
project_domain_name = Default
user-domain-name = Default
interface = internalInterface

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = ceilometer
password = SECRET_PASS
```

## II. GNOCCHI — ĐĂNG KÝ KEYSTONE VÀ CẤU HÌNH XÁC THỰC CHI TIẾT

Gnocchi cung cấp dịch vụ REST API hoạt động trên cổng mặc định **`8041`** để tiếp nhận dữ liệu đo lường. Hệ thống này bắt buộc phải đăng ký đầy đủ Service và Endpoint trong Keystone.

### 1. Đăng ký Keystone User, Service và Endpoint cho Gnocchi

Thực hiện chạy bộ lệnh khởi tạo thông tin đăng ký dịch vụ trên Controller:

```bash
source /etc/kolla/admin-openrc

# 1. Tạo tài khoản người dùng "gnocchi" trong project "service":
openstack user create --domain default --project service --password SECRET_PASS gnocchi

# 2. Gán vai trò "admin" cho tài khoản gnocchi:
openstack role add --project service --user gnocchi admin

# 3. Đăng ký loại dịch vụ (Service Type) là "metric" trong hệ thống:
openstack service create --name gnocchi --description "Metric Service" metric

# 4. Khởi tạo 3 Endpoint (Public, Internal, Admin) trỏ tới cổng 8041:
openstack endpoint create --region RegionOne metric public http://controller:8041
openstack endpoint create --region RegionOne metric internal http://controller:8041
openstack endpoint create --region RegionOne metric admin http://controller:8041
```

### 2. Cấu hình xác thực: Section `[api]` và `[keystone_authtoken]`

Tệp cấu hình `/etc/gnocchi/gnocchi.conf` cần khai báo chế độ xác thực Keystone để bảo vệ cổng API:

```ini
[api]
# Kích hoạt xác thực thông qua keystone middleware:
auth_mode = keystone

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = gnocchi
password = SECRET_PASS
```

## III. AODH — ĐĂNG KÝ KEYSTONE VÀ CẤU HÌNH XÁC THỰC CHI TIẾT

Aodh API lắng nghe trên cổng mặc định **`8042`** để tiếp nhận các yêu cầu quản lý quy tắc cảnh báo (Alarms).

### 1. Đăng ký Keystone User, Service và Endpoint cho Aodh

Tiến hành đăng ký dịch vụ Alarming trong Service Catalog của Keystone:

```bash
source /etc/kolla/admin-openrc

# 1. Tạo tài khoản người dùng "aodh" trong project "service":
openstack user create --domain default --project service --password SECRET_PASS aodh

# 2. Gán vai trò "admin" cho tài khoản aodh:
openstack role add --project service --user aodh admin

# 3. Đăng ký loại dịch vụ (Service Type) là "alarming" trong hệ thống:
openstack service create --name aodh --description "Telemetry Alarming Service" alarming

# 4. Khởi tạo 3 Endpoint (Public, Internal, Admin) trỏ tới cổng 8042:
openstack endpoint create --region RegionOne alarming public http://controller:8042
openstack endpoint create --region RegionOne alarming internal http://controller:8042
openstack endpoint create --region RegionOne alarming admin http://controller:8042
```

### 2. Cấu hình xác thực

Trong `/etc/aodh/aodh.conf`, cấu hình xác thực cho cổng API chạy qua middleware của Keystone:

```ini
[api]
auth_mode = keystone

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = aodh
password = SECRET_PASS
```
