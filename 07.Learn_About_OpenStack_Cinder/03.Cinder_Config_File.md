## 1. Tổng quan về file cấu hình Cinder

### 1.1. Vị trí và danh sách file

```bash
/etc/cinder/
├── cinder.conf              # File cấu hình CHÍNH (quan trọng nhất)
├── api-paste.ini            # Cấu hình WSGI middleware pipeline
├── policy.yaml              # Quy tắc phân quyền RBAC (từ Wallaby trở đi)
├── rootwrap.conf            # Cấu hình quyền root cho các lệnh đặc quyền
└── rootwrap.d/              # Thư mục chứa các filter rootwrap
    ├── volume.filters
    └── lvm.filters
```

> **Lưu ý:** File `policy.json` đã bị thay thế bởi `policy.yaml` từ phiên bản **Wallaby (2021)**. Trong Dalmatian 2024.2, chỉ dùng `policy.yaml`.

### 1.2. Cấu trúc file INI

`cinder.conf` dùng định dạng INI với các section:

```ini
[section_name]
key = value
# Đây là comment
```

- **Section `[DEFAULT]`**: Cấu hình toàn cục áp dụng cho mọi thành phần.
- **Các section khác**: Ghi đè hoặc bổ sung cấu hình cho từng subsystem.
- **Section backend**: Mỗi storage backend có một section riêng.

### 1.3. Ba thành phần đọc file cấu hình

Cả 3 daemon đều đọc cùng file `/etc/cinder/cinder.conf`:

| Daemon | Đọc section chính |
| ------ | ----------------- |
| `cinder-api` | `[DEFAULT]`, `[keystone_authtoken]`, `[database]` |
| `cinder-scheduler` | `[DEFAULT]`, `[database]`, `[scheduler]` |
| `cinder-volume` | `[DEFAULT]`, `[database]`, `[<backend_sections>]` |
| `cinder-backup` | `[DEFAULT]`, `[database]`, `[backup]` |

## 2. Section [DEFAULT] - Cấu hình chung

### 2.1. Cấu hình mạng và API

```ini
[DEFAULT]
# Địa chỉ IP cinder-api lắng nghe
# 0.0.0.0 = lắng nghe tất cả interface
my_ip = 10.0.0.11

# Port API (mặc định 8776)
osapi_volume_listen_port = 8776

# Số worker process (mặc định = số CPU)
osapi_volume_workers = 4

# Địa chỉ IP Management của node (dùng để các component tìm thấy nhau)
host = cinder@controller
```

### 2.2. Message Queue (Transport URL)

```ini
[DEFAULT]
# URL kết nối tới RabbitMQ (quan trọng nhất)
# Cú pháp: rabbit://user:pass@host:port/vhost
transport_url = rabbit://openstack:RABBIT_PASS@controller:5672/

# Timeout kết nối RabbitMQ (giây)
rpc_response_timeout = 60
```

### 2.3. Cấu hình Storage Backend mặc định

```ini
[DEFAULT]
# Chỉ định backend mặc định khi không dùng multi-backend
# Trỏ tới tên section backend trong cùng file config
enabled_backends = lvm

# Volume Type mặc định (nếu user không chỉ định khi tạo volume)
default_volume_type = standard
```

### 2.4. Các tùy chọn Glance (khi tạo volume từ image)

```ini
[DEFAULT]
# Địa chỉ Glance API để Cinder tải image
glance_api_servers = http://controller:9292

# Timeout khi tải image từ Glance (giây)
glance_request_timeout = 300

# Số lần retry khi kết nối Glance thất bại
glance_num_retries = 3
```

### 2.5. Availability Zone

```ini
[DEFAULT]
# Availability Zone của storage node này
storage_availability_zone = nova

# Khi user không chỉ định AZ, dùng AZ nào mặc định
default_availability_zone = nova
```

### 2.6. Cấu hình Quota

```ini
[DEFAULT]
# Số volume tối đa mỗi project (mặc định: 10, -1 = không giới hạn)
quota_volumes = 10

# Số snapshot tối đa mỗi project
quota_snapshots = 10

# Tổng dung lượng (GB) tối đa mỗi project (-1 = không giới hạn)
quota_gigabytes = 1000

# Số backup tối đa mỗi project
quota_backups = 10

# Tổng dung lượng backup (GB) tối đa
quota_backup_gigabytes = 1000
```

### 2.7. Cấu hình bảo mật

```ini
[DEFAULT]
# Dùng Keystone limits thay vì Cinder quota nội bộ
use_keystone_limits = false

# Cho phép tạo volume với size=0 (không khuyến nghị)
allow_empty_volumes = false
```

## 3. Section [database] - Kết nối Database

```ini
[database]
# Connection string tới MariaDB/MySQL
# Cú pháp: mysql+pymysql://user:pass@host/dbname
connection = mysql+pymysql://cinder:CINDER_DBPASS@controller/cinder

# Kích thước connection pool (số kết nối đồng thời tới DB)
max_pool_size = 10

# Số kết nối tối đa kể cả overflow
max_overflow = 20

# Thời gian tái sử dụng connection (giây)
pool_recycle = 3600

# Timeout chờ kết nối từ pool (giây, -1 = chờ mãi)
pool_timeout = 30

# Số lần retry khi mất kết nối DB
max_retries = 10

# Thời gian chờ giữa các lần retry (giây)
retry_interval = 10
```

## 4. Section [keystone_authtoken] - Xác thực Keystone

```ini
[keystone_authtoken]
# Địa chỉ Keystone Identity API
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000

# Backend lưu cache token (tăng hiệu năng xác thực)
memcached_servers = controller:11211

# Loại xác thực (password = dùng username/password)
auth_type = password

# Thông tin service account của Cinder trong Keystone
project_domain_name = Default
user_domain_name = Default
project_name = service
username = cinder
password = CINDER_PASS

# Thời gian cache token (giây)
token_cache_time = 300

# Không log thông tin nhạy cảm
memcache_security_strategy = ENCRYPT
memcache_secret_key = MEMCACHE_SECRET
```

## 5. Section [oslo_messaging_rabbit] - Message Queue

```ini
[oslo_messaging_rabbit]
# Thời gian reconnect khi mất kết nối RabbitMQ (giây)
rabbit_retry_interval = 1

# Số lần retry kết nối RabbitMQ
rabbit_max_retries = 0

# Bật HA mode với RabbitMQ cluster
rabbit_ha_queues = false

# SSL cho RabbitMQ
ssl = false
# ssl_ca_file = /etc/cinder/certs/ca.crt
# ssl_cert_file = /etc/cinder/certs/client.crt
# ssl_key_file = /etc/cinder/certs/client.key
```

## 6. Section [oslo_concurrency] - Đồng thời hóa

```ini
[oslo_concurrency]
# Thư mục lưu lock files để tránh race condition
# Quan trọng khi nhiều worker chạy đồng thời
lock_path = /var/lib/cinder/tmp
```

## 7. Cấu hình Storage Backend

### 7.1. Backend LVM (iSCSI) — Phổ biến trong lab/dev

```ini
[DEFAULT]
enabled_backends = lvm-iscsi

[lvm-iscsi]
# Driver class cho LVM
volume_driver = cinder.volume.drivers.lvm.LVMVolumeDriver

# Tên Volume Group LVM đã tạo sẵn trên storage node
volume_group = cinder-volumes

# Giao thức iSCSI
target_protocol = iscsi

# Helper tool quản lý iSCSI target (tgtadm, lioadm, iscsictl)
target_helper = tgtadm

# IP của storage node để VM kết nối iSCSI
target_ip_address = 10.0.0.11

# Tên hiển thị của backend (tùy ý)
volume_backend_name = LVM-iSCSI

# Thin provisioning (mặc định: false = thick)
lvm_type = thin

# Tỉ lệ over-subscription khi dùng thin (mặc định: 20.0)
max_over_subscription_ratio = 20.0

# Dự trữ % dung lượng không dùng để tránh full
reserved_percentage = 5
```

### 7.2. Backend Ceph RBD — Khuyên dùng trong Production

```ini
[DEFAULT]
enabled_backends = ceph-rbd

[ceph-rbd]
# Driver Ceph RBD
volume_driver = cinder.volume.drivers.rbd.RBDDriver

# Tên pool trong Ceph để lưu volume
rbd_pool = volumes

# File cấu hình Ceph
rbd_ceph_conf = /etc/ceph/ceph.conf

# User Ceph (cần có quyền trên pool volumes)
rbd_user = cinder

# UUID của Libvirt secret (để Nova/KVM đọc được volume Ceph)
# Tạo bằng: uuidgen
rbd_secret_uuid = 457eb676-33da-42ec-9a8c-9293d545c337

# Tên hiển thị của backend
volume_backend_name = Ceph-RBD

# Kích thước block map cache của RBD (bytes)
rbd_store_chunk_size = 4

# Keyring file của user cinder (nếu không dùng file ceph.conf chung)
# rbd_keyring_conf = /etc/ceph/ceph.client.cinder.keyring

# Cho phép Ceph quản lý discard/trim
rbd_exclusive_cinder_pool = true

# Flat network (không tunnel qua iSCSI, kết nối trực tiếp librbd)
# Không cần cấu hình thêm, RBD driver dùng librbd tự động
```

**Chuẩn bị Ceph trước khi cấu hình:**

```bash
# Tạo pool volumes trên Ceph cluster
ceph osd pool create volumes 128
ceph osd pool application enable volumes rbd
rbd pool init volumes

# Tạo user cinder với quyền phù hợp
ceph auth get-or-create client.cinder \
    mon 'profile rbd' \
    osd 'profile rbd pool=volumes, profile rbd pool=vms, profile rbd-read-only pool=images' \
    mgr 'profile rbd pool=volumes' | \
    tee /etc/ceph/ceph.client.cinder.keyring
```

### 7.3. Backend NFS

```ini
[DEFAULT]
enabled_backends = nfs-backend

[nfs-backend]
volume_driver = cinder.volume.drivers.nfs.NfsDriver

# File chứa danh sách NFS shares
nfs_shares_config = /etc/cinder/nfs_shares

# Tùy chọn mount NFS
nfs_mount_options = vers=4,minorversion=1,sec=sys

# Thư mục mount point trên storage node
nfs_mount_point_base = /var/lib/cinder/mnt

volume_backend_name = NFS-Backend
```

Nội dung file `/etc/cinder/nfs_shares`:

```bash
# Mỗi dòng là một NFS share: host:/path
192.168.1.100:/mnt/nfs-cinder
192.168.1.101:/mnt/nfs-cinder-2
```

### 7.4. Backend iSCSI với NVMe-oF (hiệu năng cao)

```ini
[nvme-backend]
volume_driver = cinder.volume.drivers.nvme.NVMeOFDriver
target_protocol = nvmet_rdma
target_helper = nvmetcli
target_ip_address = 192.168.10.11
volume_backend_name = NVMe-RDMA
```

## 8. Cấu hình Multi-Backend

Cinder hỗ trợ nhiều backend cùng lúc trên một node, phân biệt bằng Volume Type.

```ini
[DEFAULT]
# Liệt kê tất cả backend, cách nhau bằng dấu phẩy
enabled_backends = ceph-ssd,ceph-hdd,lvm-local

[ceph-ssd]
volume_driver = cinder.volume.drivers.rbd.RBDDriver
rbd_pool = volumes-ssd
rbd_ceph_conf = /etc/ceph/ceph.conf
rbd_user = cinder
rbd_secret_uuid = 457eb676-33da-42ec-9a8c-9293d545c337
volume_backend_name = Ceph-SSD

[ceph-hdd]
volume_driver = cinder.volume.drivers.rbd.RBDDriver
rbd_pool = volumes-hdd
rbd_ceph_conf = /etc/ceph/ceph.conf
rbd_user = cinder
rbd_secret_uuid = 457eb676-33da-42ec-9a8c-9293d545c337
volume_backend_name = Ceph-HDD

[lvm-local]
volume_driver = cinder.volume.drivers.lvm.LVMVolumeDriver
volume_group = cinder-local
target_protocol = iscsi
target_helper = tgtadm
volume_backend_name = LVM-Local
```

Sau đó tạo Volume Type tương ứng:

```bash
# Tạo Volume Type cho SSD
openstack volume type create Ceph-SSD
openstack volume type set --property volume_backend_name=Ceph-SSD Ceph-SSD

# Tạo Volume Type cho HDD
openstack volume type create Ceph-HDD
openstack volume type set --property volume_backend_name=Ceph-HDD Ceph-HDD

# Dùng khi tạo volume
openstack volume create --type Ceph-SSD --size 100 my-ssd-volume
```

### 8.1. Cấu hình Scheduler cho Multi-Backend

```ini
[DEFAULT]
# Scheduler driver (mặc định FilterScheduler, không cần thay đổi)
scheduler_driver = cinder.scheduler.filter_scheduler.FilterScheduler

# Danh sách filter áp dụng (thứ tự quan trọng)
scheduler_default_filters = AvailabilityZoneFilter,CapacityFilter,CapabilitiesFilter

# Thuật toán chọn backend tốt nhất sau khi filter
scheduler_default_weighers = CapacityWeigher

# Khi CapacityWeigher: backend có nhiều dung lượng trống được ưu tiên hơn
# Hệ số nhân (càng lớn = càng ưu tiên backend dung lượng cao)
capacity_weight_multiplier = 1.0
```

## 9. Section [coordination] và [barbican]

### 9.1. Section [coordination] — Distributed Lock

```ini
[coordination]
# Backend lưu distributed lock (quan trọng khi có nhiều cinder-volume nodes)
# Dùng Tooz library
# redis: backend phổ biến
backend_url = redis://controller:6379

# etcd: backend ổn định hơn cho production
# backend_url = etcd3+http://controller:2379
```

### 9.2. Section [barbican] — Mã hóa Volume

```ini
[barbican]
# Địa chỉ Barbican Key Manager API
barbican_endpoint_type = internal
barbican_api_version = v1
```

Sau khi cấu hình Barbican, tạo Encrypted Volume Type:

```bash
# Tạo Volume Type cho encrypted volume
openstack volume type create encrypted-lvm

# Gắn encryption provider vào Volume Type
openstack volume encryption type create \
    --cipher aes-xts-plain64 \
    --key-size 256 \
    --control-location front-end \
    encrypted-lvm \
    nova.volume.encryptors.luks.LuksEncryptor
```

### 9.3. Section [backup] — Cấu hình Backup

```ini
[DEFAULT]
# Driver backup (swift, ceph, nfs, posix)
backup_driver = cinder.backup.drivers.swift.SwiftBackupDriver

# Địa chỉ Swift API (nếu dùng Swift backend)
backup_swift_url = http://controller:8080/v1/AUTH_

# Thông tin xác thực Swift
backup_swift_auth = single_user
backup_swift_user = cinder
backup_swift_tenant = service
backup_swift_key = SWIFT_PASS

# Container Swift lưu backup
backup_swift_container = volumebackups

# Kích thước mỗi chunk khi backup (bytes, mặc định 32MB)
backup_swift_object_size = 52428800

# Số worker backup đồng thời
backup_workers = 1

# Tự động xóa backup khi xóa volume (mặc định: false)
backup_use_temp_snapshot = false
```

**Dùng Ceph làm backup backend:**

```ini
[DEFAULT]
backup_driver = cinder.backup.drivers.ceph.CephBackupDriver
backup_ceph_conf = /etc/ceph/ceph.conf
backup_ceph_user = cinder-backup
backup_ceph_pool = backups
```

## 10. Cấu hình Logging

```ini
[DEFAULT]
# File log chính
log_file = /var/log/cinder/cinder-api.log
# (mỗi daemon có file log riêng: cinder-volume.log, cinder-scheduler.log)

# Thư mục log (dùng khi log_file là đường dẫn tương đối)
log_dir = /var/log/cinder

# Bật debug (ghi chi tiết mọi thao tác, SQL query...)
# Chỉ bật khi troubleshoot, KHÔNG dùng production
debug = false

# Gửi log tới systemd Journal
use_journal = false

# Gửi log tới Syslog
use_syslog = false

# Format log có context (request_id, user, project)
logging_context_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [%(global_request_id)s %(request_id)s %(user_identity)s] %(instance)s%(message)s

# Format log không có context (nội bộ)
logging_default_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [-] %(instance)s%(message)s

# Log level mặc định cho từng thư viện (giảm noise)
default_log_levels = amqp=WARN,sqlalchemy=WARN,oslo.messaging=INFO,keystonemiddleware=WARN,stevedore=WARN
```

## 11. Ví dụ cấu hình hoàn chỉnh

Ví dụ file `/etc/cinder/cinder.conf` cho môi trường production với Ceph backend:

```ini
[DEFAULT]
# ==== Network & API ====
my_ip = 10.0.0.11
osapi_volume_workers = 4
host = cinder@controller

# ==== Message Queue ====
transport_url = rabbit://openstack:RABBIT_PASS@controller:5672/

# ==== Backend ====
enabled_backends = ceph-volumes
default_volume_type = ceph-standard
glance_api_servers = http://controller:9292

# ==== Quota ====
quota_volumes = 50
quota_gigabytes = 5000
quota_snapshots = 50

# ==== Logging ====
log_dir = /var/log/cinder
debug = false

# ==== Backup (dùng Ceph) ====
backup_driver = cinder.backup.drivers.ceph.CephBackupDriver
backup_ceph_conf = /etc/ceph/ceph.conf
backup_ceph_user = cinder-backup
backup_ceph_pool = backups

[database]
connection = mysql+pymysql://cinder:CINDER_DBPASS@controller/cinder
max_pool_size = 10
pool_recycle = 3600

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = cinder
password = CINDER_PASS
token_cache_time = 300

[oslo_concurrency]
lock_path = /var/lib/cinder/tmp

[oslo_messaging_rabbit]
rabbit_ha_queues = false

[coordination]
backend_url = redis://controller:6379

# ==== Ceph Backend ====
[ceph-volumes]
volume_driver = cinder.volume.drivers.rbd.RBDDriver
rbd_pool = volumes
rbd_ceph_conf = /etc/ceph/ceph.conf
rbd_user = cinder
rbd_secret_uuid = 457eb676-33da-42ec-9a8c-9293d545c337
volume_backend_name = Ceph-RBD
rbd_exclusive_cinder_pool = true
max_over_subscription_ratio = 10.0
reserved_percentage = 5
```

Sau khi chỉnh sửa cấu hình, khởi động lại các dịch vụ:

```bash
sudo systemctl restart cinder-api cinder-scheduler cinder-volume cinder-backup
sudo systemctl status cinder-api cinder-scheduler cinder-volume

# Xác nhận backend đã kết nối
openstack volume service list
```

## Tóm tắt các Section quan trọng

| Section | Vai trò | Bắt buộc? |
| ------- | ------- | --------- |
| `[DEFAULT]` | Cấu hình chung: network, MQ, backend, quota, logging | Có |
| `[database]` | Kết nối MariaDB lưu metadata volume | Có |
| `[keystone_authtoken]` | Xác thực request qua Keystone | Có |
| `[oslo_messaging_rabbit]` | Cấu hình chi tiết RabbitMQ | Tùy chọn |
| `[oslo_concurrency]` | Thư mục lock files | Có |
| `[<backend_name>]` | Cấu hình chi tiết từng storage backend | Có (ít nhất 1) |
| `[coordination]` | Distributed lock (multi-node) | Tùy chọn |
| `[barbican]` | Mã hóa volume | Tùy chọn |
| `[backup]` (trong DEFAULT) | Cấu hình backup driver | Tùy chọn |
