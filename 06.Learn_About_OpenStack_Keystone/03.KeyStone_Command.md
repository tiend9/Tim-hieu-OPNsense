# KEYSTONE COMMANDS - HƯỚNG DẪN CHI TIẾT

Tài liệu này tổng hợp các lệnh quản trị Identity Service (Keystone) trong OpenStack, từ giai đoạn cài đặt đến vận hành hàng ngày.

## 1. Nhóm lệnh Cài đặt và Khởi tạo (Bootstrap)

Các lệnh này thường chỉ chạy một lần khi thiết lập hệ thống hoặc khi bảo trì backend.

### 1.1 Khởi tạo cơ sở dữ liệu

```bash
# Đồng bộ hóa cấu trúc database cho Keystone
keystone-manage db_sync

# Dùng trong trường hợp khi ta tạo database keystone và cấp quyền cho user keystone, ta phải chạy lệnh này để KeyStone tự động tạo ra hàng chục cái bảng cần thiết(như bảng user, project, role, token...) để service chạy trơn tru.
# Dùng trong trường hợp nâng cấp OpenStack lên bản mới hơn (vd: từ Yoga -> Zed) để service keystone update lên phiên bản tương ứng với các thay đổi của phiên bản OpenStack mới. Nếu không chạy lệnh này, keystone sẽ không hoạt động được.
# Dùng trong trường hợp dự án cá nhân mà có thiệp vào code KeyStone để thêm 1 trường thông tin mới (filed) cho User (vd: PhoneNumber ), ta phải tạo 1 file Migration mới và chạy db_sync để database nhận diện thay đổi đó.
```

### 1.2 Thiết lập Fernet Keys (Xác thực Token)

```bash
# Khởi tạo repository chứa key cho Fernet tokens
keystone-manage fernet_setup --keystone-user keystone --keystone-group keystone
# => Ta cần cái FernetKeys này để mã hoá xác thực tạo ra Token (FernetToken)
# => Lệnh này tạo ra 1 thư mục /etc/keystone/fernet-keys/ và tạo ra các file khóa bên trong.
# => Nếu không chạy lệnh này. Mỗi khi đăng nhập, hệ thống sẽ báo lỗi 500 Internal Server Error vì nó không tìm thấy Token để xác thực đăng nhập

# Khởi tạo repository cho credential keys (mã hóa mật khẩu hệ thống)
keystone-manage credential_setup --keystone-user keystone --keystone-group keystone
# => Keystone lưu thẳng các mật khẩu (credential) vào Database (dạng text thuần), nếu database bị hack thì mất hết.
# => Nó tạo ra một bộ chìa khóa riêng (thường ở /etc/keystone/credential-keys/) để mã hóa các credential trước khi ghi vào Database.
# => Nếu không chạy lệnh này, Keystone sẽ không thể đọc được các thông tin nhạy cảm (như API key của các service khác) khi cần thiết.
```

### 1.3 Bootstrap hệ thống

Lệnh này cực kỳ quan trọng, nó tạo sẵn User `admin`, Project `admin`, Role `admin` và các Endpoint ban đầu.

```bash
keystone-manage bootstrap --bootstrap-password <ADMIN_PASS> \
  --bootstrap-admin-url http://<CONTROLLER_IP>:5000/v3/ \
  --bootstrap-internal-url http://<CONTROLLER_IP>:5000/v3/ \
  --bootstrap-public-url http://<CONTROLLER_IP>:5000/v3/ \
  --bootstrap-region-id RegionOne
```

## 2. Nhóm lệnh Quản lý Domain & Project

### 2.1 Quản lý Domain

Domain là cấp quản lý cao nhất.

- **Tạo domain:** `openstack domain create --description "Mô tả" <NAME>`
- **Liệt kê:** `openstack domain list`
- **Xem chi tiết:** `openstack domain show <NAME|ID>`

### 2.2 Quản lý Project (Tenant)

Nơi chứa các tài nguyên như VM, Network.

- **Tạo project:** `openstack project create --domain <DOMAIN_NAME> --description "Mô tả" <NAME>`
- **Liệt kê:** `openstack project list`
- **Xóa project:** `openstack project delete <NAME|ID>`

## 3. Nhóm lệnh Quản lý User & Group

### 3.1 Quản lý User

- **Tạo user:**

  ```bash
  openstack user create --domain <DOMAIN> --project <PROJECT> --password <PASSWORD> <USERNAME>
  ```

- **Đổi mật khẩu:**

  ```bash
  openstack user set --password <NEW_PASS> <USERNAME>
  ```

- **Khóa/Mở khóa user:**

  ```bash
  openstack user set --disable <USERNAME> # Khóa
  openstack user set --enable <USERNAME>  # Mở
  ```

### 3.2 Quản lý Group

- **Tạo nhóm:** `openstack group create <GROUP_NAME>`
- **Thêm user vào nhóm:** `openstack group add user <GROUP_NAME> <USER_NAME>`

## 4. Nhóm lệnh Quản lý Role (Phân quyền)

Đây là phần kết nối User với Project.

- **Liệt kê các Role có sẵn:** `openstack role list`
- **Tạo Role mới:** `openstack role create <ROLE_NAME>`
- **Gán quyền (Role Assignment):**

  ```bash
  # Gán user 'alice' làm 'admin' trong project 'dev'
  openstack role add --project <PROJECT_NAME> --user <USER_NAME> <ROLE_NAME>
  ```

- **Kiểm tra quyền của một User:**

  ```bash
  openstack role assignment list --user <USER_NAME> --project <PROJECT_NAME> --names
  ```

## 5. Nhóm lệnh Quản lý Service & Endpoint

Dùng để đăng ký các dịch vụ khác (Nova, Neutron...) vào Keystone.

### 5.1 Quản lý Service

- **Tạo service:**

  ```bash
  openstack service create --name <SERVICE_NAME> --description "Mô tả" <SERVICE_TYPE>
  # Ví dụ: openstack service create --name nova --description "OpenStack Compute" compute
  ```

### 5.2 Quản lý Endpoint

Mỗi service cần có 3 loại endpoint (public, internal, admin).

- **Tạo endpoint:**

  ```bash
  openstack endpoint create --region RegionOne <SERVICE_NAME> <INTERFACE_TYPE> <URL>
  # INTERFACE_TYPE: public, internal, hoặc admin
  ```

## 6. Nhóm lệnh Kiểm tra & Debug (Token/Catalog)

### 6.1 Kiểm tra Token hiện tại

```bash
# Xem thông tin về token đang sử dụng trong môi trường hiện tại
openstack token issue
```

### 6.2 Xem danh mục dịch vụ

```bash
# Liệt kê tất cả dịch vụ và URL mà user hiện tại có thể gọi
openstack catalog list
```

## 7. Các tham số (Options) quan trọng cần nhớ

Khi chạy lệnh OpenStack, thường mày phải kèm theo các thông tin xác thực.

| Tham số             | Ý nghĩa                                                |
| ------------------- | ------------------------------------------------------ |
| `--os-auth-url`     | URL của Keystone (thường là port 5000)                 |
| `--os-project-name` | Tên Project muốn thao tác                              |
| `--os-username`     | Tên User đăng nhập                                     |
| `--os-password`     | Mật khẩu                                               |
| `--os-domain-name`  | Tên Domain (thường là Default)                         |
| `-f value`          | Chỉ lấy giá trị của một cột cụ thể (tiện cho script)   |
| `-c Column`         | Chỉ hiển thị cột mong muốn                             |
| `--long`            | Hiển thị thêm các thông tin chi tiết khác              |

## 8. Mẹo sử dụng: File biến môi trường (OpenRC)

Thay vì nhập tham số dài dòng cho mỗi lệnh, ta tạo file `admin-openrc` và `source` nó.

**Nội dung file `admin-openrc` mẫu:**

```bash
export OS_PROJECT_DOMAIN_NAME=Default
export OS_USER_DOMAIN_NAME=Default
export OS_PROJECT_NAME=admin
export OS_USERNAME=admin
export OS_PASSWORD=matkhaucuamay
export OS_AUTH_URL=http://controller:5000/v3
export OS_IDENTITY_API_VERSION=3
export OS_IMAGE_API_VERSION=2
```

**Sử dụng:**

```bash
source admin-openrc
# Sau đó chỉ cần gõ:
openstack user list
```
