## 1. Tổng quan về hệ thống Log trong Cinder

Cinder sử dụng thư viện **oslo.log** — thư viện logging chuẩn của toàn bộ OpenStack. Oslo.log build trên Python standard `logging` module và bổ sung thêm:

- **Context-aware logging**: Tự động đính kèm `request_id`, `project_id`, `user_id` vào mỗi dòng log
- **Log level chuẩn**: DEBUG / INFO / WARNING / ERROR / CRITICAL
- **Nhiều output target**: File, stderr, syslog, journal
- **Global Request ID**: Cho phép trace một request xuyên qua nhiều service (Cinder → Nova → Glance)

Mỗi Cinder service ghi log **độc lập** vào file riêng của nó, trên node mà service đó chạy:

| Service            | Chức năng chính được log                                |
|--------------------|---------------------------------------------------------|
| `cinder-api`       | Nhận/trả HTTP request, xác thực token, validate input   |
| `cinder-scheduler` | Chọn backend, filter/weigher result                     |
| `cinder-volume`    | Tạo/xóa/attach volume vật lý, gọi driver                |
| `cinder-backup`    | Tạo/restore backup                                      |

## 2. Vị trí File Log theo kiểu Deploy

### 2.1. Cài tay (Manual / Package-based)

Đây là vị trí mặc định khi cài bằng `apt` / `yum` trên Ubuntu hoặc CentOS/RHEL.

```text
/var/log/cinder/
├── cinder-api.log        # log của cinder-api (chạy trên controller node)
├── cinder-scheduler.log  # log của cinder-scheduler (chạy trên controller node)
├── cinder-volume.log     # log của cinder-volume (chạy trên storage node)
└── cinder-backup.log     # log của cinder-backup (chạy trên backup node)
```

> Mỗi service chạy trên node nào thì file log nằm trên node đó.  
> Với mô hình HA, log phân tán trên nhiều node — cần tập trung về hệ thống log trung tâm (ELK, Graylog...).

Kiểm tra cấu hình log đang dùng:

```bash
grep -E "log_dir|log_file" /etc/cinder/cinder.conf
```

### 2.2. Kolla-Ansible (Docker Container)

Log nằm bên trong container, nhưng được mount ra host:

```text
# Trong container
/var/log/kolla/cinder/

# Trên host (mount point)
/var/log/kolla/cinder/
├── cinder-api.log
├── cinder-scheduler.log
├── cinder-volume.log
└── cinder-backup.log
```

Cách truy cập:

```bash
# Xem log qua docker
docker logs cinder_api
docker logs cinder_volume
docker logs cinder_scheduler
docker logs cinder_backup

# Xem trực tiếp file trong container
docker exec -it cinder_volume tail -f /var/log/kolla/cinder/cinder-volume.log

# Xem từ host (nếu đã mount)
tail -f /var/log/kolla/cinder/cinder-volume.log
```

### 2.3. Systemd / Journald

Khi Cinder chạy qua systemd (không ghi file log riêng, ghi vào journal):

```bash
# Xem log theo service
journalctl -u cinder-api
journalctl -u cinder-volume
journalctl -u cinder-scheduler
journalctl -u cinder-backup

# Xem real-time
journalctl -u cinder-volume -f

# Lọc theo thời gian
journalctl -u cinder-volume --since "2025-05-01 08:00:00" --until "2025-05-01 09:00:00"

# Lọc theo khoảng giờ gần đây
journalctl -u cinder-volume --since "1 hour ago"
```

Để chuyển sang ghi file (khuyến nghị cho production):

```ini
# /etc/cinder/cinder.conf
[DEFAULT]
log_dir = /var/log/cinder
```

### 2.4. DevStack (Development)

```text
$DEST/logs/
├── c-api.log       # cinder-api
├── c-sch.log       # cinder-scheduler
├── c-vol.log       # cinder-volume
└── c-bak.log       # cinder-backup
```

### 2.5. OpenStack-Ansible (OSA)

```text
/openstack/log/<container-name>/cinder/
├── cinder-api.log
├── cinder-scheduler.log
└── cinder-volume.log
```

### 2.6. So sánh nhanh

| Phương thức deploy | Vị trí log                                 | Cách xem                                 |
|--------------------|--------------------------------------------|------------------------------------------|
| Manual (apt/yum)   | `/var/log/cinder/*.log`                    | `tail`, `grep`, `less`                   |
| Kolla-Ansible      | `/var/log/kolla/cinder/*.log`              | `docker logs` hoặc file trực tiếp        |
| Systemd only       | journald                                   | `journalctl -u cinder-*`                 |
| DevStack           | `$DEST/logs/c-*.log`                       | `tail`, `grep`                           |
| OSA                | `/openstack/log/<container>/cinder/`       | `tail`, `grep`                           |

## 3. Cấu trúc một dòng Log

Cinder dùng `oslo.log` — format mặc định của một dòng log:

```text
<timestamp> <pid> <level> <logger> [<req-id> <user> <project>] <message>
```

### 3.1. Ví dụ log thực tế

**Log INFO bình thường:**

```text
2025-05-07 10:23:41.512 1234 INFO cinder.api.v3.volumes \
  [req-a1b2c3d4-e5f6-7890-abcd-ef1234567890 abc123 proj456] \
  Create volume of 100 GB
```

**Log ERROR khi tạo volume thất bại:**

```text
2025-05-07 10:24:01.881 1234 ERROR cinder.volume.manager \
  [req-a1b2c3d4-e5f6-7890-abcd-ef1234567890 abc123 proj456] \
  Failed to create volume: No valid host was found.
```

**Log DEBUG (chỉ xuất hiện khi bật debug=True):**

```text
2025-05-07 10:23:40.100 1234 DEBUG cinder.scheduler.filter_scheduler \
  [req-a1b2c3d4-...] Filtered [cinder@ceph#ceph-ssd] by CapacityFilter
```

### 3.2. Giải thích từng trường

| Trường      | Ví dụ                     | Ý nghĩa                                   |
|-------------|---------------------------|-------------------------------------------|
| `timestamp` | `2025-05-07 10:23:41.512` | Thời điểm chính xác tới ms                |
| `pid`       | `1234`                    | Process ID của service                    |
| `level`     | `INFO`, `ERROR`, `DEBUG`  | Mức độ nghiêm trọng                       |
| `logger`    | `cinder.volume.manager`   | Module Python tạo ra log                  |
| `req-id`    | `req-a1b2c3...`           | Request ID duy nhất cho mỗi request       |
| `user`      | `abc123`                  | User ID thực hiện thao tác                |
| `project`   | `proj456`                 | Project ID                                |
| `message`   | `Failed to create volume` | Nội dung log                              |

### 3.3. Các Log Level

| Level      | Khi nào xuất hiện                                              |
|------------|----------------------------------------------------------------|
| `DEBUG`    | Thông tin chi tiết nội bộ — chỉ khi `debug=True`               |
| `INFO`     | Hoạt động bình thường (tạo volume, attach, delete...)          |
| `WARNING`  | Cảnh báo — chưa lỗi nhưng cần chú ý                            |
| `ERROR`    | Lỗi xảy ra nhưng service vẫn chạy                              |
| `CRITICAL` | Lỗi nghiêm trọng, service có thể dừng                          |

## 4. Log theo từng Service và Hoạt động

### 4.1. cinder-api.log

Ghi lại toàn bộ HTTP request/response đến Cinder API endpoint.

**Những gì được log:**

- Mỗi API request đến (method, URL, response code)
- Xác thực token với Keystone thành công/thất bại
- Validate input (thiếu param, sai format)
- Tạo record volume ban đầu trong DB

**Ví dụ log khi tạo volume:**

```text
2025-05-07 10:23:41.200 5678 INFO cinder.api.v3.volumes \
  [req-abc123 user01 proj01] \
  POST /v3/proj01/volumes HTTP/1.1 RESPONSE: 202
```

**Ví dụ log khi xác thực thất bại:**

```text
2025-05-07 10:23:41.350 5678 WARNING cinder.api.middleware.auth \
  [req-abc123 - -] \
  Authorization failed: Token not found
```

### 4.2. cinder-scheduler.log

Ghi quá trình chọn backend storage phù hợp.

**Những gì được log:**

- Nhận request tạo volume từ MQ
- Danh sách backend đang active
- Kết quả từng Filter (backend nào pass, backend nào bị loại và lý do)
- Backend cuối cùng được chọn
- Lỗi "No valid host" khi không backend nào thỏa mãn

**Ví dụ log scheduler chọn backend:**

```text
2025-05-07 10:23:42.100 2345 DEBUG cinder.scheduler.filter_scheduler \
  [req-abc123 user01 proj01] \
  Running filters on 3 host(s)

2025-05-07 10:23:42.120 2345 DEBUG cinder.scheduler.filters.capacity_filter \
  [req-abc123 user01 proj01] \
  Host cinder@lvm#LVM filtered: free_capacity_gb=10 < requested=100

2025-05-07 10:23:42.130 2345 DEBUG cinder.scheduler.filter_scheduler \
  [req-abc123 user01 proj01] \
  Choosing cinder@ceph#ceph-ssd for volume vol-xyz
```

**Ví dụ lỗi không tìm được backend:**

```text
2025-05-07 10:23:42.500 2345 ERROR cinder.scheduler.filter_scheduler \
  [req-abc123 user01 proj01] \
  No valid host was found. There are not enough hosts available.
```

### 4.3. cinder-volume.log

File log quan trọng nhất — ghi toàn bộ thao tác thực thi trên storage backend.

**Những gì được log:**

- Nhận task từ MQ (create, delete, attach, extend...)
- Gọi Storage Driver (Ceph RBD driver, LVM driver...)
- Phản hồi từ driver (thành công / lỗi cụ thể)
- Cập nhật trạng thái volume trong DB
- Thông tin kết nối iSCSI / Ceph keyring

**Ví dụ log tạo volume thành công:**

```text
2025-05-07 10:23:43.000 7890 INFO cinder.volume.manager \
  [req-abc123 user01 proj01] \
  volume volume-xyz: creating

2025-05-07 10:23:43.800 7890 INFO cinder.volume.drivers.rbd \
  [req-abc123 user01 proj01] \
  Successfully created volume volume-xyz in pool cinder-volumes

2025-05-07 10:23:43.850 7890 INFO cinder.volume.manager \
  [req-abc123 user01 proj01] \
  volume volume-xyz: created successfully
```

**Ví dụ log attach volume:**

```text
2025-05-07 10:25:10.001 7890 INFO cinder.volume.manager \
  [req-def456 user01 proj01] \
  Attaching volume volume-xyz to instance vm-abc on host compute01

2025-05-07 10:25:10.500 7890 INFO cinder.volume.manager \
  [req-def456 user01 proj01] \
  volume volume-xyz: attach_status: attached
```

### 4.4. cinder-backup.log

Ghi toàn bộ quá trình backup và restore.

**Những gì được log:**

- Bắt đầu / kết thúc backup job
- Số chunk đã transfer
- Lỗi kết nối đến backup backend (Swift / Ceph)
- Restore progress

**Ví dụ log backup:**

```text
2025-05-07 11:00:01.000 9012 INFO cinder.backup.manager \
  [req-ghi789 user01 proj01] \
  Create backup started, backup: backup-xyz, volume: volume-abc

2025-05-07 11:02:35.000 9012 INFO cinder.backup.manager \
  [req-ghi789 user01 proj01] \
  Backup backup-xyz (of volume volume-abc) finished. 100GB backed up.
```

## 5. Cấu hình Log trong cinder.conf

Toàn bộ cấu hình log nằm trong section `[DEFAULT]` của `/etc/cinder/cinder.conf`.

### 5.1. Cấu hình cơ bản

```ini
[DEFAULT]
# Thư mục chứa file log
log_dir = /var/log/cinder

# Tên file log (mỗi service khai báo riêng)
# log_file = cinder-volume.log  # thường không cần, log_dir là đủ

# Bật DEBUG mode — CHỈ dùng khi troubleshoot, KHÔNG dùng production
debug = False

# Verbose thêm thông tin (deprecated từ Newton, hiện INFO là mặc định)
# verbose = True
```

### 5.2. Cấu hình Format Log

```ini
[DEFAULT]
# Format dòng log có context (user đã đăng nhập)
logging_context_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [%(request_id)s %(user_identity)s] %(instance)s%(message)s

# Format khi không có context
logging_default_format_string = %(asctime)s.%(msecs)03d %(process)d %(levelname)s %(name)s [-] %(instance)s%(message)s

# Format timestamp
log_date_format = %Y-%m-%d %H:%M:%S

# Hiển thị exception đầy đủ
logging_exception_prefix = ERROR %(name)s [%(request_id)s %(user_identity)s] 
```

### 5.3. Ghi Log ra Syslog

```ini
[DEFAULT]
use_syslog = True
syslog_log_facility = LOG_LOCAL0
```

### 5.4. Dùng file cấu hình logging riêng (Python logging config)

```ini
[DEFAULT]
# Append thêm file config logging tùy chỉnh
log_config_append = /etc/cinder/logging.conf
```

Ví dụ file `/etc/cinder/logging.conf` (định dạng Python logging):

```ini
[loggers]
keys=root,cinder

[handlers]
keys=file,console

[formatters]
keys=context

[logger_root]
level=WARNING
handlers=file

[logger_cinder]
level=INFO
handlers=file
qualname=cinder

[handler_file]
class=FileHandler
level=INFO
formatter=context
args=('/var/log/cinder/cinder-volume.log',)

[formatter_context]
class=oslo_log.formatters.ContextFormatter
```

### 5.5. Thay đổi Log Level runtime (không cần restart)

```bash
# Xem log level hiện tại của service
cinder service-get-log <host> cinder-volume

# Đổi sang DEBUG để debug tức thời
cinder service-set-log --log-level DEBUG <host> cinder-volume

# Trả về INFO sau khi xong
cinder service-set-log --log-level INFO <host> cinder-volume
```

## 6. Cách xem Log

### 6.1. Xem real-time

```bash
# Theo dõi log volume theo thời gian thực
tail -f /var/log/cinder/cinder-volume.log

# Theo dõi nhiều file cùng lúc
tail -f /var/log/cinder/cinder-api.log \
        /var/log/cinder/cinder-scheduler.log \
        /var/log/cinder/cinder-volume.log

# Chỉ hiển thị ERROR trở lên real-time
tail -f /var/log/cinder/cinder-volume.log | grep -E "ERROR|CRITICAL|WARNING"
```

### 6.2. Tìm kiếm theo Request ID

Đây là cách quan trọng nhất để trace một thao tác xuyên qua nhiều service:

```bash
# Lấy request_id từ output lệnh
openstack volume create --size 100 my-vol -f json | jq '.["x-openstack-request-id"]'
# hoặc nhìn vào cinder-api.log dòng đầu tiên của request

# Grep theo request_id qua tất cả log
REQ_ID="req-a1b2c3d4-e5f6-7890-abcd-ef1234567890"
grep "$REQ_ID" /var/log/cinder/cinder-api.log
grep "$REQ_ID" /var/log/cinder/cinder-scheduler.log
grep "$REQ_ID" /var/log/cinder/cinder-volume.log
```

### 6.3. Tìm kiếm theo Volume ID

```bash
VOLUME_ID="vol-12345678-abcd-efgh-ijkl-mnopqrstuvwx"
grep "$VOLUME_ID" /var/log/cinder/cinder-volume.log
grep "$VOLUME_ID" /var/log/cinder/*.log
```

### 6.4. Lọc theo mức độ lỗi

```bash
# Chỉ xem ERROR và CRITICAL
grep -E "^[0-9-]+ [0-9:]+ [0-9]+ (ERROR|CRITICAL)" /var/log/cinder/cinder-volume.log

# Đếm số lỗi trong ngày
grep "ERROR" /var/log/cinder/cinder-volume.log | grep "2025-05-07" | wc -l
```

### 6.5. Lọc theo khoảng thời gian

```bash
# Xem log trong khoảng thời gian (awk)
awk '/2025-05-07 10:00/,/2025-05-07 11:00/' /var/log/cinder/cinder-volume.log

# Xem log sau một thời điểm cụ thể
awk '/2025-05-07 10:30/' /var/log/cinder/cinder-volume.log
```

### 6.6. Dùng journalctl (nếu dùng systemd)

```bash
journalctl -u cinder-volume -f
journalctl -u cinder-volume --since "2025-05-07 10:00" --until "2025-05-07 11:00"
journalctl -u cinder-volume -p err    # chỉ error
journalctl -u cinder-volume -p debug  # tất cả
```

## 7. Các lỗi thường gặp và cách đọc Log

### 7.1. Lỗi: No valid host was found

**Triệu chứng:** Volume bị kẹt status `error`, message `No valid host was found`

**Log trong cinder-scheduler.log:**

```text
ERROR cinder.scheduler.filter_scheduler \
  No valid host was found. There are not enough hosts available.
```

**Log DEBUG cho thấy lý do:**

```text
DEBUG cinder.scheduler.filters.capacity_filter \
  Host cinder@ceph filtered: free_capacity_gb=5 < requested=100

DEBUG cinder.scheduler.filters.availability_zone_filter \
  Host cinder@lvm filtered: AZ mismatch (host=AZ1, requested=AZ2)
```

**Cách debug:**

```bash
# Xem scheduler message
openstack volume message list

# Xem pool còn dung lượng không
cinder get-pools --detail

# Bật debug để xem filter detail
cinder service-set-log --log-level DEBUG <scheduler-host> cinder-scheduler
```

### 7.2. Lỗi: Volume kẹt trạng thái `creating` hoặc `deleting`

**Log trong cinder-volume.log:**

```text
ERROR cinder.volume.manager \
  [req-xxx] Failed to create volume vol-abc: ConnectionError: \
  Failed to connect to Ceph cluster
```

**Nguyên nhân thường gặp:**

- Storage backend (Ceph/LVM) không kết nối được
- Driver bị lỗi
- RabbitMQ mất kết nối khiến message không đến cinder-volume

**Cách xử lý:**

```bash
# Xem log chi tiết
grep "vol-abc" /var/log/cinder/cinder-volume.log | tail -50

# Reset trạng thái
cinder reset-state --state error vol-abc
openstack volume delete vol-abc  # rồi tạo lại
```

### 7.3. Lỗi: Attach volume thất bại

**Log trong cinder-volume.log:**

```text
ERROR cinder.volume.manager \
  [req-yyy] Failed to initialize connection for vol-xyz: \
  ISCSITargetCreateFailed: Failed to create iSCSI target
```

**Log trong Nova compute (nova-compute.log) liên quan:**

```text
ERROR nova.virt.libvirt.volume.iscsi \
  [req-yyy] iSCSI volume attachment failed: could not connect
```

**Cách debug:**

```bash
# Kiểm tra iSCSI trên storage node
systemctl status tgt
iscsiadm -m session

# Với Ceph: kiểm tra keyring
ceph auth get client.cinder
ls /etc/ceph/
```

### 7.4. Lỗi: Token/Auth thất bại

**Log trong cinder-api.log:**

```text
WARNING cinder.api.middleware.auth \
  Authorization failed: The token is expired
```

**Nguyên nhân:** Token hết hạn hoặc Keystone không kết nối được.

**Cách debug:**

```bash
# Kiểm tra Keystone
openstack token issue

# Kiểm tra cấu hình auth trong cinder.conf
grep -A 10 "\[keystone_authtoken\]" /etc/cinder/cinder.conf
```

### 7.5. Lỗi: Database connection failed

**Log trong bất kỳ service nào:**

```text
ERROR cinder.db.sqlalchemy.api \
  (OperationalError) (2003, "Can't connect to MySQL server on '10.0.0.10'")
```

**Cách debug:**

```bash
# Test kết nối DB trực tiếp
mysql -h <db-host> -u cinder -p cinder -e "SELECT 1"

# Kiểm tra cấu hình
grep "connection" /etc/cinder/cinder.conf

# Xem Galera cluster status (nếu dùng MariaDB Galera)
mysql -e "SHOW STATUS LIKE 'wsrep%'"
```

### 7.6. Lỗi: RabbitMQ / Message Queue

**Log trong cinder-scheduler.log hoặc cinder-volume.log:**

```text
ERROR oslo_messaging._drivers.amqpdriver \
  AMQP server on 10.0.0.5:5672 is unreachable: \
  [Errno 111] Connection refused
```

**Cách debug:**

```bash
# Kiểm tra RabbitMQ
rabbitmqctl status
rabbitmqctl list_queues

# Kiểm tra cấu hình
grep "transport_url" /etc/cinder/cinder.conf
```

### 7.7. Lỗi: Backup thất bại

**Log trong cinder-backup.log:**

```text
ERROR cinder.backup.drivers.ceph \
  Failed to connect to Ceph cluster for backup: \
  [Errno 111] Connection refused
```

**Cách debug:**

```bash
# Kiểm tra backup pool
ceph -s
ceph osd pool ls | grep backup

# Reset backup state
cinder backup-reset-state --state error <backup-id>
```

## 8. Phân tích Log thực tế — Trace một request xuyên suốt

Ví dụ thực tế: User tạo volume `100GB` nhưng thất bại. Đây là cách trace toàn bộ flow.

### Bước 1: Lấy Request ID từ API log

```bash
# Chạy lệnh và lưu output
openstack volume create --size 100 --type ceph-ssd my-vol

# Tìm request_id trong cinder-api.log
grep "my-vol\|POST.*volumes" /var/log/cinder/cinder-api.log | tail -5
```

Output ví dụ:

```text
2025-05-07 10:23:41.200 5678 INFO cinder.api.v3.volumes \
  [req-a1b2c3d4-xxxx user01 proj01] Create volume of 100 GB
```

→ **Request ID: `req-a1b2c3d4-xxxx`**

### Bước 2: Trace trong cinder-api.log

```bash
grep "req-a1b2c3d4-xxxx" /var/log/cinder/cinder-api.log
```

Thấy: API nhận request, validate OK, ghi DB, đẩy message vào MQ → status `creating`

### Bước 3: Trace trong cinder-scheduler.log

```bash
grep "req-a1b2c3d4-xxxx" /var/log/cinder/cinder-scheduler.log
```

Thấy:

```text
DEBUG Filtered [cinder@lvm] by CapacityFilter: free=5GB < requested=100GB
DEBUG Filtered [cinder@ceph-hdd] by CapabilitiesFilter: volume_backend_name mismatch
ERROR No valid host was found
```

→ **Root cause: Cả 2 backend đều bị filter, không còn host nào**

### Bước 4: Xác nhận lỗi qua Volume Message

```bash
openstack volume message list
openstack volume message show <message-id>
```

Output:

```text
| message | No valid host was found. There are not enough hosts available. |
| detail  | Capacity filter: not enough free space on any backend.         |
```

### Bước 5: Kiểm tra pool dung lượng

```bash
cinder get-pools --detail | grep -E "name|free_capacity"
# → cinder@ceph#ceph-ssd: free_capacity_gb = 500  ← OK
# → Vấn đề là volume type không map đúng backend
```

### Bước 6: Xác định và fix

```bash
# Kiểm tra extra spec của volume type
openstack volume type show ceph-ssd | grep volume_backend_name
# → volume_backend_name = 'ceph-ssd'  ← đúng rồi

# Kiểm tra tên pool trong cinder.conf
grep "volume_backend_name" /etc/cinder/cinder.conf
# → volume_backend_name = ceph_ssd  ← SAI! thiếu dấu -

# Fix: sửa cinder.conf
volume_backend_name = ceph-ssd
systemctl restart cinder-volume
```

## 9. Điều chỉnh Log Level

### 9.1. Tĩnh — trong cinder.conf

```ini
[DEFAULT]
debug = True    # bật DEBUG cho toàn service
```

Restart service sau khi sửa:

```bash
systemctl restart cinder-volume
```

### 9.2. Động — không cần restart (API)

```bash
# Xem log level hiện tại
cinder service-get-log <host> cinder-volume

# Bật DEBUG
cinder service-set-log --log-level DEBUG storage01 cinder-volume

# Bật DEBUG cho cụ thể một module Python
cinder service-set-log --log-level DEBUG --prefix cinder.volume.drivers.rbd storage01 cinder-volume

# Trả về INFO sau khi troubleshoot xong
cinder service-set-log --log-level INFO storage01 cinder-volume
```

> Lưu ý: DEBUG mode tạo ra rất nhiều log — có thể làm đầy disk nếu để lâu trên production.

## 10. Log Rotation & Quản lý dung lượng Log

### 10.1. Cấu hình logrotate (thủ công)

File `/etc/logrotate.d/cinder`:

```bash
/var/log/cinder/*.log {
    daily
    missingok
    rotate 14
    compress
    delaycompress
    notifempty
    create 640 cinder cinder
    postrotate
        systemctl reload cinder-api >/dev/null 2>&1 || true
        systemctl reload cinder-volume >/dev/null 2>&1 || true
    endscript
}
```

### 10.2. Cấu hình rotation trong cinder.conf

```ini
[DEFAULT]
# Số file backup giữ lại
log_rotation_type = interval
log_rotate_interval = 1
log_rotate_interval_type = Days
max_logfile_count = 30

# Giới hạn kích thước file (bytes)
max_logfile_size_mb = 200
```

### 10.3. Tập trung Log về hệ thống trung tâm

Với hệ thống HA nhiều node, cần tập trung log:

**Option 1: Syslog + Graylog/ELK**:

```ini
[DEFAULT]
use_syslog = True
syslog_log_facility = LOG_LOCAL0
```

**Option 2: Filebeat → Elasticsearch**:

```yaml
# /etc/filebeat/filebeat.yml
filebeat.inputs:
  - type: log
    paths:
      - /var/log/cinder/*.log
    fields:
      service: cinder
      node: storage01
output.elasticsearch:
  hosts: ["elasticsearch:9200"]
```

## 11. Checklist Debug hàng ngày

```bash
#!/bin/bash
# daily_cinder_check.sh

echo "=== Cinder Service Status ==="
openstack volume service list

echo ""
echo "=== ERROR trong 1 giờ qua ==="
for log in /var/log/cinder/*.log; do
  echo "--- $log ---"
  grep "ERROR" "$log" | awk -v d="$(date -d '1 hour ago' '+%Y-%m-%d %H:%M')" '$0 >= d'
done

echo ""
echo "=== Volume bị kẹt status error ==="
openstack volume list --all-projects --status error

echo ""
echo "=== Snapshot bị lỗi ==="
openstack volume snapshot list --all-projects --status error

echo ""
echo "=== Scheduler messages ==="
openstack volume message list

echo ""
echo "=== Pool dung lượng ==="
cinder get-pools --detail | grep -E "name|free_capacity|total_capacity"

echo ""
echo "=== Backup đang chạy ==="
openstack volume backup list --all-projects --status backing-up

echo ""
echo "=== Quota check ==="
cinder-manage quota check 2>&1 | grep -v "^$"
```

## PHỤ LỤC: Các từ khóa grep quan trọng

| Keyword                    | Tìm trong log nào | Ý nghĩa                                 |
|----------------------------|-------------------|-----------------------------------------|
| `No valid host`            | scheduler         | Không tìm được backend                  |
| `Failed to create`         | volume            | Tạo volume thất bại                     |
| `Connection refused`       | volume, backup    | Backend không kết nối được              |
| `Token not found`          | api               | Auth thất bại                           |
| `OperationalError`         | bất kỳ            | DB connection lỗi                       |
| `AMQP server.*unreachable` | bất kỳ            | RabbitMQ down                           |
| `ISCSITargetCreateFailed`  | volume            | iSCSI target lỗi                        |
| `quota exceeded`           | api               | Hết quota                               |
| `status.*error`            | volume            | Volume chuyển sang error state          |
| `Traceback`                | bất kỳ            | Python exception — xem full stack trace |
