# CÁC LỆNH THƯỜNG DÙNG VỚI NOVA

> Tài liệu này dùng **OpenStackClient** với cú pháp `openstack ...`, phù hợp OpenStack 2026.1 Gazpacho. Client `nova ...` vẫn có thể tồn tại cho một số tác vụ nâng cao, nhưng trong vận hành hằng ngày nên ưu tiên `openstack` CLI.

## 1. Chuẩn bị môi trường

Nạp biến môi trường trước khi chạy lệnh:

```bash
source /root/admin-openrc
# hoặc:
source ~/demo-openrc
```

Kiểm tra token và project đang dùng:

```bash
openstack token issue
openstack configuration show
```

Nếu cần dùng microversion mới:

```bash
export OS_COMPUTE_API_VERSION=2.latest
openstack --os-compute-api-version 2.latest server list
```

## 2. Kiểm tra service Nova

Liệt kê các service Compute:

```bash
openstack compute service list
openstack compute service list --service nova-compute
```

Kỳ vọng:

```text
nova-scheduler   controller   enabled   up
nova-conductor   controller   enabled   up
nova-compute     compute      enabled   up
```

Kiểm tra hypervisor:

```bash
openstack hypervisor list
openstack hypervisor show <hypervisor-id-or-hostname>
openstack hypervisor stats show
```

Kiểm tra endpoint:

```bash
openstack catalog list
openstack endpoint list --service nova
```

Kiểm tra Cells v2, Placement, Cinder API:

```bash
nova-status upgrade check
```

Discover compute host mới:

```bash
su -s /bin/sh -c "nova-manage cell_v2 discover_hosts --verbose" nova
```

## 3. Flavor

Flavor là template tài nguyên cho VM: RAM, vCPU, disk, ephemeral, swap và extra specs.

Tạo flavor:

```bash
openstack flavor create m1.small \
  --id auto \
  --ram 2048 \
  --disk 20 \
  --vcpus 1 \
  --public
```

Trong đó:

- `--ram`: MB.
- `--disk`: GB.
- `--vcpus`: số vCPU.
- `--public`: project nào cũng thấy flavor.
- `--private`: chỉ project được gán quyền mới thấy.

Liệt kê và xem chi tiết:

```bash
openstack flavor list
openstack flavor show m1.small
```

Xóa flavor:

```bash
openstack flavor delete m1.small
```

> Xóa flavor không xóa VM đã boot từ flavor đó. VM vẫn giữ thông tin flavor đã copy vào instance metadata.

Tạo private flavor:

```bash
openstack flavor create m1.private \
  --id auto \
  --ram 4096 \
  --disk 40 \
  --vcpus 2 \
  --private

openstack flavor set m1.private --project <project-name-or-id>
```

Thêm extra specs:

```bash
openstack flavor set m1.small \
  --property hw:cpu_policy=shared

openstack flavor show m1.small -c properties
```

Gỡ extra specs:

```bash
openstack flavor unset m1.small --property hw:cpu_policy
```

## 4. Keypair

Tạo keypair mới và lưu private key:

```bash
openstack keypair create mykey > mykey.pem
chmod 600 mykey.pem
```

Import public key có sẵn:

```bash
openstack keypair create \
  --public-key ~/.ssh/id_rsa.pub \
  mykey
```

OpenStackClient mới có thể tạo key mặc định dạng `ssh-ed25519` nếu không truyền public key.

Liệt kê và xem keypair:

```bash
openstack keypair list
openstack keypair show mykey
```

Xóa keypair:

```bash
openstack keypair delete mykey
```

## 5. Server cơ bản

Liệt kê VM:

```bash
openstack server list
openstack server list --all-projects
openstack server list --long
```

Xem chi tiết VM:

```bash
openstack server show <vm-name-or-id>
openstack server show <vm-name-or-id> -c status -c addresses -c OS-EXT-SRV-ATTR:host
```

Tạo VM từ image:

```bash
openstack server create test-vm \
  --flavor m1.small \
  --image ubuntu-22.04 \
  --network provider \
  --security-group default \
  --key-name mykey \
  --wait
```

Nếu muốn dùng network ID:

```bash
NET_ID=$(openstack network show provider -f value -c id)

openstack server create test-vm \
  --flavor m1.small \
  --image cirros \
  --nic net-id=$NET_ID \
  --security-group default \
  --key-name mykey \
  --wait
```

Tạo VM với user-data:

```bash
openstack server create cloudinit-vm \
  --flavor m1.small \
  --image ubuntu-22.04 \
  --network provider \
  --key-name mykey \
  --user-data user-data.yaml \
  --wait
```

Tạo nhiều VM cùng lúc:

```bash
openstack server create web \
  --flavor m1.small \
  --image ubuntu-22.04 \
  --network provider \
  --key-name mykey \
  --min 2 \
  --max 2
```

## 6. Boot từ volume

Boot VM từ image nhưng tạo root disk bằng Cinder volume:

```bash
openstack server create vm-bfv \
  --flavor m1.small \
  --image ubuntu-22.04 \
  --boot-from-volume 20 \
  --network provider \
  --key-name mykey \
  --wait
```

Boot từ volume đã có sẵn:

```bash
openstack server create vm-from-volume \
  --flavor m1.small \
  --volume <volume-name-or-id> \
  --network provider \
  --key-name mykey \
  --wait
```

Boot từ volume snapshot:

```bash
openstack server create vm-from-snapshot \
  --flavor m1.small \
  --snapshot <snapshot-name-or-id> \
  --network provider \
  --key-name mykey \
  --wait
```

## 7. Vòng đời server

Tắt VM:

```bash
openstack server stop <vm>
```

Bật VM:

```bash
openstack server start <vm>
```

Reboot mềm:

```bash
openstack server reboot <vm>
```

Reboot cứng:

```bash
openstack server reboot --hard <vm>
```

Pause/unpause:

```bash
openstack server pause <vm>
openstack server unpause <vm>
```

Suspend/resume:

```bash
openstack server suspend <vm>
openstack server resume <vm>
```

Shelve/unshelve:

```bash
openstack server shelve <vm>
openstack server unshelve <vm>
```

Xóa VM:

```bash
openstack server delete <vm>
```

Xóa nhiều VM:

```bash
openstack server delete vm1 vm2 vm3
```

Khôi phục VM đang soft-delete nếu cloud bật reclaim:

```bash
openstack server restore <vm>
```

## 8. Console và log

Lấy console URL:

```bash
openstack console url show <vm>
openstack console url show --novnc <vm>
```

Xem console log:

```bash
openstack console log show <vm>
openstack console log show --lines 50 <vm>
```

SSH vào VM:

```bash
ssh -i mykey.pem ubuntu@<fixed-or-floating-ip>
ssh -i mykey.pem cirros@<fixed-or-floating-ip>
```

## 9. Snapshot VM

Tạo snapshot image từ VM:

```bash
openstack server image create \
  --name test-vm-snapshot \
  --wait \
  test-vm
```

Liệt kê snapshot vì snapshot server được lưu trong Glance:

```bash
openstack image list
openstack image show test-vm-snapshot
```

Xóa snapshot:

```bash
openstack image delete test-vm-snapshot
```

> Không dùng `openstack snapshot create` cho snapshot VM. Lệnh snapshot trong Cinder là cho volume, còn snapshot instance dùng `openstack server image create`.

## 10. Rebuild, resize, rescue

Rebuild VM từ image khác hoặc image hiện tại:

```bash
openstack server rebuild <vm> --image ubuntu-22.04
```

Resize VM sang flavor khác:

```bash
openstack server resize --flavor m1.medium <vm> --wait
openstack server resize confirm <vm>
```

Nếu resize lỗi hoặc không muốn giữ:

```bash
openstack server resize revert <vm>
```

Rescue VM:

```bash
openstack server rescue <vm>
openstack server unrescue <vm>
```

## 11. Volume attach/detach qua Nova

Tạo volume bằng Cinder:

```bash
openstack volume create --size 10 data-vol
```

Attach volume vào VM:

```bash
openstack server add volume <vm> data-vol
```

Kiểm tra volume attachment:

```bash
openstack server show <vm> -c volumes_attached
openstack volume show data-vol
```

Detach volume:

```bash
openstack server remove volume <vm> data-vol
```

Attach kèm delete-on-termination nếu API hỗ trợ:

```bash
openstack --os-compute-api-version 2.79 server add volume \
  --enable-delete-on-termination \
  <vm> data-vol
```

## 12. Network và floating IP

Gắn thêm network vào VM:

```bash
openstack server add network <vm> <network>
```

Gỡ network:

```bash
openstack server remove network <vm> <network>
```

Gắn port có sẵn:

```bash
openstack port create --network provider vm-port
openstack server add port <vm> vm-port
```

Gỡ port:

```bash
openstack server remove port <vm> vm-port
```

Tạo floating IP:

```bash
openstack floating ip create provider
```

Gán floating IP:

```bash
openstack server add floating ip <vm> <floating-ip>
```

Gỡ floating IP:

```bash
openstack server remove floating ip <vm> <floating-ip>
```

## 13. Security group

Tạo security group:

```bash
openstack security group create web-sg
```

Cho phép ICMP:

```bash
openstack security group rule create --proto icmp web-sg
```

Cho phép SSH:

```bash
openstack security group rule create \
  --proto tcp \
  --dst-port 22 \
  web-sg
```

Gán security group cho VM:

```bash
openstack server add security group <vm> web-sg
```

Gỡ security group:

```bash
openstack server remove security group <vm> web-sg
```

## 14. Server group

Server group dùng để điều khiển placement của nhiều VM.

Tạo anti-affinity group để các VM tránh cùng một compute host:

```bash
openstack server group create \
  --policy anti-affinity \
  web-anti-affinity
```

Boot VM vào server group:

```bash
GROUP_ID=$(openstack server group show web-anti-affinity -f value -c id)

openstack server create web01 \
  --flavor m1.small \
  --image ubuntu-22.04 \
  --network provider \
  --hint group=$GROUP_ID \
  --key-name mykey
```

Liệt kê:

```bash
openstack server group list
openstack server group show web-anti-affinity
```

## 15. Quota và limit

Xem quota project:

```bash
openstack quota show <project>
```

Set quota compute:

```bash
openstack quota set <project> \
  --instances 20 \
  --cores 40 \
  --ram 81920
```

Xem limit user đang thấy:

```bash
openstack limits show --absolute
```

## 16. Admin thao tác compute service

Disable compute host để bảo trì:

```bash
openstack compute service set \
  --disable \
  --disable-reason "maintenance" \
  <compute-host> nova-compute
```

Enable lại:

```bash
openstack compute service set \
  --enable \
  <compute-host> nova-compute
```

Live migrate VM sang host khác:

```bash
openstack server migrate \
  --live-migration \
  --host <target-compute-host> \
  <vm> \
  --wait
```

Cold migrate:

```bash
openstack server migrate <vm> --wait
openstack server migration confirm <vm>
```

Evacuate VM khi compute host chết:

```bash
openstack server evacuate <vm> --host <target-compute-host> --wait
```

> Evacuate chỉ dùng khi host cũ thật sự down và operator hiểu rõ storage backend của instance.

## 17. Debug nhanh khi VM lỗi

Xem lỗi tổng quan:

```bash
openstack server show <vm> \
  -c status \
  -c fault \
  -c OS-EXT-SRV-ATTR:host \
  -c addresses
```

Xem event/action của VM:

```bash
openstack server event list <vm>
openstack server event show <vm> <request-id>
```

Kiểm tra port:

```bash
openstack port list --server <vm>
openstack port show <port-id>
```

Kiểm tra Placement và compute:

```bash
openstack hypervisor list
openstack compute service list
nova-status upgrade check
```

Log thường xem:

```bash
journalctl -u nova-api -n 100 --no-pager
journalctl -u nova-scheduler -n 100 --no-pager
journalctl -u nova-conductor -n 100 --no-pager
journalctl -u nova-compute -n 100 --no-pager
```
