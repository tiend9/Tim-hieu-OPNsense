# TÌM HIỂU VỀ HOST AGGREGATE VÀ AVAILABILITY ZONE TRONG NOVA

![Nova](./images/Nova_20.png)

## A. TÌM HIỂU VỀ HOST AGGREGATE

### 1. Định nghĩa về Aggregate

**Host Aggregate** là nhóm logic của các compute host được tạo bởi admin để:

- Gom các host có cùng đặc điểm
- Điều khiển scheduler
- Hỗ trợ policy placement VM

Ví dụ:

```bash
Aggregate: GPU_HOSTS
  - compute01
  - compute02

Aggregate: SSD_HOSTS
  - compute03
  - compute04
```

**Host aggregate** thường dùng để:

- Grouping hardware
- Grouping hypervisor
- Grouping location
- Grouping storage

### 2. Đặc điểm của Aggregate

| Thuộc tính         | Host Aggregate |
| ------------------ | -------------- |
| visible to user    | ❌             |
| visible to admin   | ✔              |
| scheduler aware    | ✔              |
| metadata           | ✔              |
| host join multiple | ✔              |

-> Một host có thể nằm trong nhiều aggregates cùng lúc.

Ví dụ:

```bash
compute01

Aggregate:
- GPU
- SSD
- INTEL_CPU
```

### 3. Metadata trong Host Aggregate

Điểm mạnh của host aggregate là **metadata (key=value)**.

Ví dụ:

```bash
aggregate metadata:

ssd=true
gpu=true
cpu_type=intel
```

->Nova scheduler có thể filter host dựa vào metadata.

Ví dụ:

| Flavor extra spec | Aggregate metadata |
| ----------------- | ------------------ |
| disk=ssd          | ssd=true           |
| gpu=true          | gpu=true           |

### 4.Scheduler filters dùng với Aggregate

Một số filter quan trọng:

#### 4.1 AggregateInstanceExtraSpecsFilter

Match:

```bash
Flavor extra_specs
↔
Aggregate metadata
```

Ví dụ:

```bash
flavor:
gpu=true
```

Scheduler chỉ chọn host trong aggregate:

```bash
gpu=true
```

#### 4.2 AggregateImagePropertiesIsolation

Match:

```bash
image metadata
↔
aggregate metadata
```

Ví dụ:

Image:

```bash
os=windows
```

Aggregate:

```bash
os=windows
```

→ VM chỉ chạy trên host windows license.

#### 4.3 AggregateMultiTenancyIsolation

Giới hạn tenant chạy trên aggregate.

### 5. Config Host Agg and CLI Host Agg

#### 5.1 Config scheduler to support host

**Ví dụ**: Khi ta muốn hỗ trợ lập lịch các phiên bản cho một tập hợp con các host compute

- Chẳng hạn ta muốn cho phép user yêu cầu các compute host có SSD disks theo mong muốn của họ hoặc card GPU

- Để cấu hình scheduler các nhóm host, thì config option **filter_scheduler.enabled_filterst** phải chứa **AggregateInstanceExtraSpecsFilter**

- Thêm dòng sau vào `nova.conf` trên máy chủ chạy service `nova-scheduler` để bật tính năng lọc nhóm máy chủ (host agg):

```bash
[filter_scheduler]
enabled_filters=...,AggregateInstanceExtraSpecsFilter
```

```bash
aggregate_instance_extra_specs:ssd=true
```

`"Chỉ chọn host có metadata ssd=true"`

Nova Scheduler sẽ:

Dùng filter:

```bash
AggregateInstanceExtraSpecsFilter
```

Kết quả:

```text
Chỉ node 1, node2 được chọn
```

#### 5.2 Placement in this example

```bash
openstack resource provider aggregate set ...
```

Ý nghĩa:

- Add compute node (resource provider) vào aggregate trong Placement

Mục tiêu:

- Tăng tốc scheduling
- Filter ở level Placement (nhanh hơn Nova filter)

#### 5.3 Phân biệt Host Aggregate (Nova) và Placement Aggregate

**Host Aggregate (Nova)**:

- Thuộc Nova
- Dùng cho filter scheduling
- Có metadata (ssd=true)

**Placement Aggregate**:

- Thuộc Placement service
- Là group của resource providers
- Không dùng metadata kiểu Nova

=> Nhưng:

```text
Nova có thể sync Host Aggregate → Placement Aggregate
(tự động từ version nova 18+)
```

#### 5.4 Tenant Isolation (cô lập tenant)

Cách làm:

```bash
openstack aggregate set \
  --property filter_tenant_id=<tenant_id> myagg
```

Ý nghĩa:

`"Tenant này chỉ được chạy trên host trong aggregate"`

Bật config:

```ini
scheduler.limit_tenants_to_placement_aggregate=True
```

#### 5.5 Các Scheduler Filters liên quan

| Filter                            | Chức năng                 |
| --------------------------------- | ------------------------- |
| AggregateInstanceExtraSpecsFilter | match flavor vs aggregate |
| AggregateMultiTenancyIsolation    | cô lập tenant             |
| AggregateImagePropertiesIsolation | match image               |
| AggregateNumInstancesFilter       | limit VM                  |
| AggregateIoOpsFilter              | limit IO                  |
| AggregateTypeAffinityFilter       | affinity                  |

#### 5.6 CLI Host Agg

##### 5.6.1 Tạo aggregate và thêm host

Tạo một nhóm host:

```bash
openstack aggregate create my-aggregate
```

→ Tạo ra một “group” để gom các compute node lại.

Thêm host vào group:

```bash
openstack aggregate add host my-aggregate my-host
```

→ Đưa compute node vào nhóm đó.

##### 5.6.2. Xem thông tin

Xem danh sách aggregate:

```bash
openstack aggregate list
```

Xem chi tiết một aggregate:

```bash
openstack aggregate show my-aggregate
```

→ Dùng để kiểm tra:

- có những host nào
- có metadata gì

##### 5.6.3. Gán metadata (cái quan trọng nhất)

Gán:

```bash
openstack aggregate set --property pinned=true my-aggregate
```

→ Gắn “nhãn” cho group (ví dụ: SSD, GPU, pinned CPU…)

Xóa:

```bash
openstack aggregate unset --property pinned my-aggregate
```

##### 5.6.4. Đổi tên

```bash
openstack aggregate set --name my-awesome-aggregate my-aggregate
```

→ Đổi tên thôi, không ảnh hưởng logic.

##### 5.6.5 Xóa host và xóa aggregate

Gỡ host khỏi group:

```bash
openstack aggregate remove host my-aggregate my-host
```

Xóa luôn group:

```bash
openstack aggregate delete my-aggregate
```

## B. TÌM HIỂU VỀ AVAILABILITY ZONE

### 1. Định nghĩa Availability Zone

**Định nghĩa**:

**Availability Zone (AZ)** là logical partition của cloud dành cho user.

User có thể chọn AZ khi tạo VM.

Ví dụ:

```bash
AZ: zone1
AZ: zone2
AZ: zone3
```

VM có thể deploy:

```bash
openstack server create \
 --availability-zone zone1
```

### 2.Tác dụng của Availability Zone

AZ thường dùng để:

| mục đích       | ví dụ           |
| -------------- | --------------- |
| datacenter     | DC1 / DC2       |
| rack           | rack1 / rack2   |
| power domain   | powerA / powerB |
| network domain | netA / netB     |

AZ giúp:

- **Isolate failure domain**
- Phân tách **workload**
- **Multi datacenter**

Tuy nhiên AZ không tự tạo HA.

### 3. AZ thực chất được tạo từ Host Aggregate

Điểm rất quan trọng:

`"Availability Zone thực chất là metadata của Host Aggregate"`

Ví dụ:

```bash
aggregate metadata:

availability_zone=zone1
```

=> **Aggregate** sẽ trở thành AZ cho user.

### 4. Ví dụ

Tạo aggregate:

```bash
openstack aggregate create agg1 # Create nhóm máy chủ 1
```

set AZ:

```bash
openstack aggregate set \
  --property availability_zone=zone1 \
  agg1
add host
openstack aggregate add host agg1 compute01
```

→ user sẽ thấy:

```bash
AZ: zone1
```

### 5. Quy tắc giữa Host Agg và AZ (Quan trọng)

| Rule                           | Description |
| ------------------------------ | ----------- |
| host ∈ multiple aggregates     | ✔           |
| host ∈ multiple AZ             | ❌          |
| AZ visible to user             | ✔           |
| aggregate visible to user      | ❌          |
| AZ based on aggregate metadata | ✔           |

=> Một host chỉ được thuộc 1 AZ nhưng có thể thuộc nhiều aggregates.

### 6. Default Availability Zone

Nếu host không thuộc aggregate nào:

Nó sẽ thuộc:

```bash
default_availability_zone = nova
```

Config:

```bash
/etc/nova/nova.conf
default_availability_zone = nova
```

### C. TÌM HIỂU FLOW THỰC TẾ

#### 1. Flow khi tạo VM

`Step 1`:

User tạo VM

```bash
openstack server create
```

`Step 2`:

User có thể chọn AZ:

```bash
--availability-zone zone1
```

`Step 3`

Nova scheduler: lập lịch từng bước 1

```bash
Filter host

AvailabilityZoneFilter

Aggregate filters

resource filters
```

`Step 4`

Chọn compute host.

#### 2. Ví dụ thực tế trong production

`Scenario 1`: GPU workload

```bash
Aggregate: gpu_hosts
metadata:
gpu=true
```

Flavor:

```bash
gpu=true
```

→ VM chạy GPU host.

`Scenario 2`: SSD storage

```bash
Aggregate: ssd_hosts
metadata:
disk=ssd
```

Flavor:

```bash
disk=ssd
Scenario 3: Windows license host

metadata:

```

Image:

```bash
os=windows
```

```bash
AZ: dc1

```

