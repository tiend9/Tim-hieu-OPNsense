# API SERVER & WSGI CHO TELEMETRY, GNOCCHI & AODH

> **Phiên bản tham chiếu**: OpenStack **2026.1 Gazpacho**

## I. TELEMETRY VÀ CEILOMETER — LOẠI BỎ API VÀ KHỞI ĐỘNG CÁC AGENT SERVICE

Để đơn giản hóa và tối ưu hiệu suất thu thập dữ liệu trên diện rộng, kiến trúc của Ceilometer từ phiên bản 10.0 (Queens) trở đi đã loại bỏ hoàn toàn dịch vụ API Server riêng biệt.

### 1. Loại bỏ API Server riêng (No Ceilometer API)

- **Nguyên nhân**: Dịch vụ `ceilometer-api` trước đây xử lý các yêu cầu truy vấn thô trực tiếp từ Database SQL. Khi số lượng VM tăng cao, việc query dữ liệu chuỗi thời gian khổng lồ qua API này gây nghẽn RAM và sập luồng điều khiển.

- **Giải pháp**: Ceilometer chuyển dịch thành công cụ thu thập thuần túy. Toàn bộ dữ liệu sau khi thu thập được đẩy trực tiếp sang Gnocchi API. Nếu người dùng hoặc các dịch vụ khác (như Aodh) muốn xem metrics, họ sẽ gọi trực tiếp đến API của Gnocchi chứ không gọi qua Ceilometer.

### 2. Khởi động và vận hành các Agent Services

Ceilometer hoạt động dựa vào hai daemon chạy nền (Background Daemons) được khởi tạo bằng Systemd hoặc container:

#### a. Ceilometer Polling Agent (`ceilometer-polling`)

Cào dữ liệu định kỳ trên các Compute Node hoặc Controller Node:

```bash
# Khởi động dịch vụ Polling Agent trên Compute Node:
sudo systemctl enable --now ceilometer-agent-compute

# Kiểm tra trạng thái hoạt động:
sudo systemctl status ceilometer-agent-compute
```

#### b. Ceilometer Notification Agent (`ceilometer-agent-notification`)

Lắng nghe RabbitMQ để hứng sự kiện trên Controller Node:

```bash
# Khởi động dịch vụ Notification Agent trên Controller Node:
sudo systemctl enable --now ceilometer-agent-notification

# Kiểm tra trạng thái hoạt động:
sudo systemctl status ceilometer-agent-notification
```

## II. GNOCCHI — KIẾN TRÚC WSGI SERVER VÀ KHỞI ĐỘNG DỊCH VỤ

Gnocchi API chạy dưới dạng một ứng dụng Python chuẩn **WSGI (Web Server Gateway Interface)**, cho phép kết hợp với các Web Server hiệu năng cao của bên thứ ba để xử lý hàng ngàn request đồng thời.

### 1. Kiến trúc WSGI Server (uWSGI / Gunicorn)

Trong môi trường Production, Gnocchi API không chạy bằng lệnh kiểm thử tích hợp sẵn mà chạy bao bọc (wrapper) bởi **uWSGI** hoặc **Gunicorn** đặt sau một HTTP Reverse Proxy (như Apache hoặc Nginx).

```text
  [HTTP Request] ──► [HAProxy / Apache (Cổng 8041)] ──(Unix Socket)──► [uWSGI Application Server]
                                                                                │
  [Indexer / Storage] ◄──────────────(Xử lý qua api-paste.ini)──────────────────┘
```

- **Tệp tin `api-paste.ini`**: Định nghĩa cấu trúc pipeline phân lớp (Middleware) xử lý yêu cầu. Nó đảm bảo các request đi qua bộ lọc xác thực token của Keystone (`keystonemiddleware.auth_token`) trước khi đến mã nguồn xử lý REST của Gnocchi.

### 2. Cấu hình khởi động dịch vụ Gnocchi

Gnocchi chia làm hai tiến trình dịch vụ độc lập:

#### a. Gnocchi API (`gnocchi-api`)

Thường được uWSGI quản trị. File cấu hình uWSGI cho Gnocchi (`/etc/gnocchi/uwsgi.ini`) mẫu:

```ini
[uwsgi]
http = 192.168.100.10:8041
wsgi-file = /usr/bin/gnocchi-api
processes = 4
threads = 2
master = true
```

Khởi chạy dịch vụ API:

```bash
# Sử dụng systemd khởi động API:
sudo systemctl enable --now gnocchi-api
```

#### b. Gnocchi Metric Daemon (`gnocchi-metricd`)

Tiến trình xử lý bất đồng bộ gộp điểm dữ liệu chạy nền:

```bash
# Khởi chạy daemon metricd (nên chạy nhiều process trên các node khác nhau để scale-out):
sudo systemctl enable --now gnocchi-metricd
```

## III. AODH — KIẾN TRÚC WSGI SERVER VÀ KHỞI ĐỘNG DỊCH VỤ

Tương tự như Gnocchi, Aodh API cũng được đóng gói như một ứng dụng WSGI để tiếp nhận các yêu cầu quản trị Alarm từ người dùng.

### 1. Kiến trúc WSGI Server

Aodh API mặc định lắng nghe trên cổng **`8042`** thông qua cấu hình uWSGI.

- **uWSGI config (`/etc/aodh/aodh-api-uwsgi.ini`)**:

  - Quản lý các luồng xử lý (workers/threads) để tối ưu việc tiếp nhận các cú gọi Webhook trả về từ hệ thống.

- **api-paste.ini**:

  - Lọc xác thực phân quyền qua Keystone tương tự như Gnocchi, ngăn chặn các request nặc danh truy cập hoặc thay đổi trạng thái alarm của hệ thống.

### 2. Cấu hình khởi động dịch vụ Aodh

Hệ thống Aodh bao gồm 4 tiến trình dịch vụ cần khởi động trên Controller Node:

#### a. Aodh API (`aodh-api`)

```bash
# Khởi chạy WSGI API Server cổng 8042:
sudo systemctl enable --now aodh-api
```

#### b. Aodh Evaluator (`aodh-evaluator`)

```bash
# Tiến trình liên tục quét đối chiếu chỉ số từ Gnocchi để đánh giá báo động:
sudo systemctl enable --now aodh-evaluator
```

#### c. Aodh Notifier (`aodh-notifier`)

```bash
# Tiến trình thực thi gửi thông báo webhook/alarm đi khi có thay đổi trạng thái:
sudo systemctl enable --now aodh-notifier
```

#### d. Aodh Listener (`aodh-listener`)

```bash
# Tiến trình cắm vào MQ để bắt nhanh các sự kiện khẩn cấp từ Nova/Neutron:
sudo systemctl enable --now aodh-listener
```
