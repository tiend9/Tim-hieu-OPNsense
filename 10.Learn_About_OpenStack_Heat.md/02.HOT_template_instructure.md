# CÚ PHÁP & CẤU TRÚC HOT TEMPLATE

> **Phiên bản tham chiếu**: OpenStack **2026.1 Gazpacho** + Heat **21.x**

## I. CẤU TRÚC FILE HOT

**HOT (Heat Orchestration Template)** là ngôn ngữ cấu hình hạ tầng chuẩn của OpenStack Heat, sử dụng định dạng **YAML** để khai báo tài nguyên một cách rõ ràng, dễ đọc. Một file HOT hoàn chỉnh bao gồm **5 phần chính** (sections) được sắp xếp theo cấu trúc phân cấp:

```yaml
heat_template_version: 2021-04-16   # 1. Bắt buộc: Định nghĩa phiên bản cú pháp HOT

description: |
  2. Tùy chọn: Mô tả mục đích và vai trò của template này.

parameters:
  # 3. Tùy chọn: Khai báo các tham số đầu vào do người dùng cung cấp khi chạy stack

conditions:
  # Tùy chọn: Khai báo các điều kiện logic (equals, and, or...) để kiểm soát việc deploy

resources:
  # 4. Bắt buộc: Định nghĩa danh sách các tài nguyên hạ tầng sẽ được khởi tạo

outputs:
  # 5. Tùy chọn: Trả về kết quả đầu ra (IP, URL, ID...) sau khi stack deploy thành công
```

### Chi tiết vai trò của 5 phần chính:

1. **`heat_template_version`**: Chỉ định phiên bản tính năng của Heat engine sẽ dùng để biên dịch template. Phiên bản mới nhất và ổn định hiện tại là `2021-04-16`.
2. **`description`**: Tài liệu hóa template. Hỗ trợ viết nhiều dòng bằng ký tự pipe (`|`) trong YAML.
3. **`parameters`**: Biến số hóa template. Giúp tái sử dụng template cho nhiều môi trường (Dev, Staging, Production) mà không cần sửa code gốc.
4. **`resources`**: Trọng tâm của template. Liệt kê các đối tượng cloud thực tế cần tạo ra.
5. **`outputs`**: Expose thông tin cần thiết từ stack ra ngoài (ví dụ: Floating IP của Web Server) để người dùng hoặc các tool Automation khác sử dụng.

## II. PARAMETERS — INPUT CỦA TEMPLATE

Khai báo Parameters giúp thu thập thông tin cấu hình linh hoạt từ phía người dùng khi deploy stack.

### 1. Các kiểu dữ liệu được hỗ trợ (Type)

- `string`: Chuỗi ký tự thông thường (Tên VM, ID mạng, Image...).
- `number`: Kiểu số (Số lượng vCPU, kích thước volume, số cổng...).
- `boolean`: Kiểu logic (`true` hoặc `false`).
- `comma_delimited_list`: Danh sách các chuỗi phân tách bằng dấu phẩy (ví dụ: `8.8.8.8,1.1.1.1`).
- `json`: Cấu trúc dữ liệu phức tạp dạng JSON hoặc YAML map.

### 2. Các thuộc tính quan trọng

- `default`: Giá trị mặc định nếu người dùng bỏ qua tham số này.
- `hidden`: Nếu đặt là `true`, giá trị nhập vào sẽ bị ẩn đi trên log và Web UI (dùng cho password, API key).
- `constraints`: Tập hợp các quy tắc ràng buộc giá trị nhập vào để tránh lỗi runtime.

### 3. Ví dụ khai báo Parameters nâng cao

```yaml
parameters:
  key_name:
    type: string
    label: SSH Key Pair
    description: SSH Key đã đăng ký trong Nova để truy cập máy ảo.
    constraints:
      # Ràng buộc custom: Kiểm tra keypair có thực sự tồn tại trong Nova hay không
      - custom_constraint: nova.keypair

  instance_flavor:
    type: string
    label: Cấu hình phần cứng VM
    description: Chọn kích thước Flavor cho VM.
    default: m1.small
    constraints:
      # Giới hạn giá trị được phép nhập:
      - allowed_values: [m1.tiny, m1.small, m1.medium]
        description: Chỉ cho phép chọn m1.tiny, m1.small hoặc m1.medium.

  db_root_password:
    type: string
    label: Mật khẩu MySQL Root
    description: Mật khẩu quản trị cơ sở dữ liệu.
    hidden: true # Ẩn mật khẩu khi gõ và hiển thị
    constraints:
      # Kiểm tra độ dài mật khẩu:
      - length: { min: 8, max: 32 }
        description: Mật khẩu phải có độ dài từ 8 đến 32 ký tự.
      # Ràng buộc regex:
      - allowed_pattern: "[a-zA-Z0-9#@!]+"
        description: Mật khẩu chỉ chứa ký tự chữ, số và các ký tự đặc biệt #, @, !.

  dns_servers:
    type: comma_delimited_list
    label: DNS Servers
    default: "8.8.8.8,1.1.1.1"
```

## III. RESOURCES — KHAI BÁO HẠ TẦNG

Mỗi resource đại diện cho một đối tượng OpenStack. Dưới đây là cách thức khai báo thuộc tính chi tiết:

### 1. Thuộc tính cơ bản của một Resource

- **`type`**: Loại tài nguyên cần tạo (ví dụ: `OS::Nova::Server`, `OS::Neutron::Net`).
- **`properties`**: Các tham số cấu hình riêng biệt dành cho loại tài nguyên đó.
- **`depends_on`**: Định nghĩa tường minh thứ tự tạo tài nguyên (mặc dù Heat tự động tính toán dependency thông qua các hàm `get_resource`, nhưng đôi khi ta cần chỉ định thứ tự cụ thể cho các dịch vụ phần mềm).
- **`deletion_policy`**: Quyết định số phận của tài nguyên khi Stack bị xóa. Các giá trị hỗ trợ:
  - `Delete` (Mặc định): Xóa sạch tài nguyên vật lý.
  - `Retain`: Giữ lại tài nguyên vật lý trong OpenStack, chỉ xóa metadata quản lý của Heat.
  - `Snapshot`: Tạo bản backup của tài nguyên trước khi xóa (chỉ hỗ trợ đối với Volume của Cinder hoặc Database).

### 2. Ví dụ khai báo hạ tầng có phụ thuộc và deletion policy

```yaml
resources:
  # 1. Tạo mạng riêng (Private Network)
  app_network:
    type: OS::Neutron::Net
    properties:
      name: production-network

  # 2. Tạo Subnet (Phụ thuộc vào Network)
  app_subnet:
    type: OS::Neutron::Subnet
    properties:
      network: { get_resource: app_network }
      cidr: 10.200.0.0/24
      ip_version: 4
      dns_nameservers: { get_param: dns_servers }

  # 3. Tạo Cinder Volume lưu dữ liệu nhạy cảm
  database_volume:
    type: OS::Cinder::Volume
    deletion_policy: Retain # Đảm bảo khi stack bị xóa nhầm, ổ đĩa data cứng vẫn được giữ lại an toàn
    properties:
      name: db-production-volume
      size: 50 # 50 GB
      volume_type: ssd

  # 4. Tạo Web Server
  web_server:
    type: OS::Nova::Server
    # Bắt buộc chờ Subnet được tạo hoàn tất trước khi build VM, tránh lỗi gán port
    depends_on: app_subnet 
    properties:
      name: web-production-server
      image: Ubuntu-22.04
      flavor: { get_param: instance_flavor }
      key_name: { get_param: key_name }
      networks:
        - network: { get_resource: app_network }
```

## IV. INTRINSIC FUNCTIONS

Hàm nội tại (Intrinsic Functions) là các công cụ mạnh mẽ dùng để liên kết, tính toán và xử lý dữ liệu động bên trong template.

### 1. `get_param`

Lấy giá trị của một Parameter được người dùng nhập vào.

- *Cú pháp*: `{ get_param: <parameter_name> }` hoặc `{ get_param: [ <parameter_list>, <index> ] }`

- *Ví dụ*:

  ```yaml
  # Lấy DNS server thứ 2 trong danh sách:
  dns_server_2: { get_param: [ dns_servers, 1 ] }
  ```

### 2. `get_resource`

Lấy ID hoặc UUID vật lý của một resource khác đã được khai báo và tạo thành công trong stack.

- *Cú pháp*: `{ get_resource: <resource_logical_name> }`
- *Ví dụ*:

  ```yaml
  network_id: { get_resource: app_network }
  ```

### 3. `get_attr`

Lấy ra các thuộc tính runtime (thuộc tính động chỉ biết sau khi tài nguyên được tạo thành công) của một resource.

- *Cú pháp*: `{ get_attr: [ <resource_name>, <attribute_name>, <key/index_1>, ... ] }`

- *Ví dụ*:

  ```yaml
  # Lấy IP đầu tiên của máy ảo:
  server_ip: { get_attr: [ web_server, first_address ] }

  # Lấy địa chỉ IP cố định của Port cụ thể:
  port_fixed_ip: { get_attr: [ my_port, fixed_ips, 0, ip_address ] }
  ```

### 4. `str_replace`

Thay thế các từ khóa động trong một chuỗi văn bản mẫu. Hàm này cực kỳ hữu ích khi gỡ cấu hình hoặc truyền script cài đặt phần mềm (`user_data`) vào VM.

- *Cú pháp*:

  ```yaml
  str_replace:
    template: |
      Mẫu văn bản chứa từ khóa $VAR1 và $VAR2
    params:
      $VAR1: { get_param: param_name }
      $VAR2: { get_attr: [ resource_name, attribute ] }
  ```

- *Ví dụ thực tế truyền Script khởi tạo Nginx*:

  ```yaml
  user_data:
    str_replace:
      template: |
        #!/bin/bash
        echo "Cau hinh server $SERVER_NAME voi IP database $DB_IP" > /var/www/html/index.html
        systemctl restart nginx
      params:
        $SERVER_NAME: { get_attr: [ web_server, name ] }
        $DB_IP: "10.200.0.15"
  ```

### 5. `list_join`

Nối một danh sách các chuỗi thành một chuỗi duy nhất bằng ký tự phân tách tự định nghĩa.

- *Cú pháp*: `{ list_join: [ '<kí_tự_phân_tách>', [ <danh_sách_chuỗi> ] ] }`

- *Ví dụ*:

  ```yaml
  host_list: { list_join: [ ';', [ 'server1', 'server2', 'server3' ] ] }
  # Kết quả trả về chuỗi: "server1;server2;server3"
  ```

### 6. `if`

Trả về giá trị khác nhau dựa trên điều kiện logic đã khai báo trước.

- *Cú pháp*: `{ if: [ <condition_name>, <value_if_true>, <value_if_false> ] }`
- *Ví dụ*:

  ```yaml
  # Chọn Flavor to nếu môi trường là production, ngược lại chọn Flavor nhỏ
  flavor: { if: [ is_production, 'm1.large', 'm1.small' ] }
  ```

## V. OUTPUTS — LẤY KẾT QUẢ SAU DEPLOY

Mục `outputs` định nghĩa các thông tin trả về cho người dùng sau khi stack chuyển sang trạng thái `CREATE_COMPLETE`.

### 1. Cấu trúc khai báo Outputs

```yaml
outputs:
  server_public_ip:
    description: Địa chỉ Floating IP công cộng dùng để truy cập vào Web Server.
    value: { get_attr: [ my_floating_ip, floating_ip_address ] }

  web_server_id:
    description: ID định danh duy nhất của Web Server.
    value: { get_resource: web_server }
```

### 2. Các lệnh CLI truy vấn Outputs

Khi stack đã chạy xong, ta có thể lấy các thông tin này bằng các lệnh:

```bash
# 1. Liệt kê toàn bộ outputs của stack:
openstack stack output list test-stack

# Output mẫu:
# +------------------+------------------+------------------------------------+
# | output_key       | description      | output_value                       |
# +------------------+------------------+------------------------------------+
# | server_public_ip | Dia chi IP...    | 192.168.100.105                    |
# | web_server_id    | ID cua server    | 5c8f89e2-34ab-41c2-bd12-f8c0e29b12 |
# +------------------+------------------+------------------------------------+

# 2. Truy vấn riêng biệt giá trị của 1 key output cụ thể:
openstack stack output show test-stack server_public_ip -f value -c output_value
# Sẽ in ra màn hình trực tiếp: 192.168.100.105
```

## VI. CONDITIONS — DEPLOY CÓ ĐIỀU KIỆN

Conditions giúp kiểm soát việc khai báo tài nguyên một cách linh hoạt dựa trên tham số đầu vào.

### 1. Các toán tử logic được hỗ trợ trong Conditions

- `equals`: So sánh bằng giữa hai giá trị.
- `not`: Phủ định một biểu thức logic.
- `and`: Trả về `true` khi tất cả các biểu thức con đều đúng.
- `or`: Trả về `true` khi chỉ cần ít nhất một biểu thức con đúng.

### 2. Ví dụ áp dụng Conditions

Trong ví dụ dưới đây, ta sẽ chỉ khởi tạo tài nguyên mạng ảo và máy ảo cấu hình cao nếu người dùng truyền vào tham số môi trường là `production`:

```yaml
parameters:
  environment:
    type: string
    default: development
    constraints:
      - allowed_values: [development, production]

conditions:
  # Kiểm tra xem tham số environment có bằng "production" hay không
  is_production: { equals: [ { get_param: environment }, "production" ] }

resources:
  # Máy ảo Web thông thường (Luôn luôn được tạo)
  web_server:
    type: OS::Nova::Server
    properties:
      name: web-dev
      image: Ubuntu-22.04
      flavor: m1.small

  # Máy ảo Monitoring chỉ được khởi tạo trong môi trường Production
  monitoring_server:
    type: OS::Nova::Server
    condition: is_production # Chỉ tạo tài nguyên này khi điều kiện is_production là True
    properties:
      name: monitoring-production
      image: Ubuntu-22.04
      flavor: m1.medium
```

## VII. VALIDATE TEMPLATE TRƯỚC KHI DEPLOY

Trước khi tiến hành deploy một stack thực tế, việc kiểm tra lỗi chính tả (syntax) và cấu trúc logic của file HOT là cực kỳ quan trọng nhằm tránh mất thời gian tạo tài nguyên nửa chừng rồi bị rollback do lỗi cú pháp.

### 1. Sử dụng lệnh kiểm thử mẫu (Validation CLI)

Hãy sử dụng công cụ kiểm định được tích hợp sẵn của OpenStack:

```bash
openstack orchestration template validate --template /path/to/your-template.yaml
```

- **Khi template hoàn toàn hợp lệ**: Output trả về sẽ liệt kê danh sách các Parameter mà template yêu cầu cùng mô tả chi tiết:

  ```text
  Description: Web server voi network và floating IP
  Parameters:
    key_name:
      Description: SSH key pair de truy cap server
      Type: String
    image:
      Default: Ubuntu-22.04
      Type: String
  ```

- **Khi template bị lỗi**: CLI sẽ dừng biên dịch và chỉ ra cụ thể vị trí dòng bị lỗi cú pháp cùng mã lỗi HTTP tương ứng.

### 2. Các lỗi cú pháp thường gặp khi viết HOT

- **Lỗi Tab thay vì dấu cách (Tab Indentation)**: YAML tuyệt đối không được dùng phím `Tab` để thụt đầu dòng. Hãy dùng 2 hoặc 4 dấu cách (spaces).
- **Thiếu dấu cách sau dấu hai chấm (`:`)**: Cú pháp YAML yêu cầu phải có ít nhất 1 dấu cách sau dấu hai chấm.
  - *Sai*: `type:OS::Nova::Server`
  - *Đúng*: `type: OS::Nova::Server`
- **Gọi sai tên hàm nội tại**:
  - *Sai*: `network: { get_attr: app_network }` (Hàm `get_attr` bắt buộc phải là một danh sách chứa ít nhất 2 thuộc tính).
  - *Đúng*: `network: { get_resource: app_network }` hoặc `{ get_attr: [ web_server, first_address ] }`
- **Khác biệt về định dạng phiên bản**: Khai báo sai định dạng ngày tháng của `heat_template_version`. Ví dụ viết sai thành `heat_template_version: 2026-06-01` (Heat engine sẽ báo lỗi vì không nhận dạng được API version này).
