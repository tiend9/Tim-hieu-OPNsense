## 1. Tổng quan về file cấu hình

### 1.1. File cấu hình nằm ở đâu?

File cấu hình chính của Glance là `glance-api.conf`, thường nằm tại:

```bash
/etc/glance/glance-api.conf
```

Ngoài ra còn có các file phụ trợ:

| File                                    |          Mục đích               |
|-----------------------------------------|---------------------------------|
|         `/etc/glance/glance-api.conf`   | File cấu hình chính             |
|       `/etc/glance/policy.yaml`         | Quy tắc phân quyền (RBAC)       |
| `/etc/glance/property-protections.conf` | Bảo vệ các thuộc tính image     |
| `/etc/glance/glance-image-import.conf`  | Cấu hình quá trình import image |

### 1.2. Cấu trúc file

File `glance-api.conf` theo chuẩn **INI**, được chia thành nhiều **section** (nhóm cấu hình), mỗi section bắt đầu bằng tên trong dấu ngoặc vuông `[tên_section]`:

```ini
[DEFAULT]
bind_host = 0.0.0.0
bind_port = 9292

[database]
connection = mysql+pymysql://glance:password@controller/glance

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
```

> **Lưu ý quan trọng:** Kể từ OpenStack Dalmatian (2024.2), thành phần `glance-registry` đã bị **loại bỏ hoàn toàn**. File `glance-registry.conf` không còn được sử dụng. Tất cả cấu hình chỉ nằm trong `glance-api.conf`.

## 2. Section [DEFAULT] - Cấu hình chung

Section này chứa các tùy chọn cốt lõi ảnh hưởng đến toàn bộ dịch vụ Glance API.

### 2.1. Cấu hình Network (Mạng)

```ini
[DEFAULT]
# Địa chỉ IP mà Glance API lắng nghe
# 0.0.0.0 = lắng nghe trên tất cả các interface
bind_host = 0.0.0.0

# Port mà Glance API phục vụ
bind_port = 9292

# URL công khai (dùng khi đứng sau proxy/load balancer)
# Nếu không set, Glance sẽ dùng IP của host
public_endpoint = http://controller:9292

# URL của worker này (dùng trong triển khai multi-node)
# Các worker khác cần biết địa chỉ này để proxy request import
worker_self_reference_url = <None>
```

### 2.2. Cấu hình Worker (Tiến trình)

```ini
[DEFAULT]
# Số lượng tiến trình con (worker) xử lý request song song
# Mặc định: bằng số CPU, tối đa 8
# workers = 0 => chạy 1 tiến trình với greenthread pool
workers = 4

# Số kết nối TCP đang chờ được xếp hàng
backlog = 4096

# HTTP Keep-Alive: giữ kết nối TCP sau mỗi request
http_keepalive = true

# Timeout cho socket kết nối client (giây), 0 = chờ mãi
client_socket_timeout = 900

# Kích thước tối đa của header HTTP (byte)
# Tăng khi dùng Keystone v3 với token lớn
max_header_line = 16384
```

### 2.3. Cấu hình Quota & Giới hạn

```ini
[DEFAULT]
# Giới hạn dung lượng tối đa của 1 image (byte)
# Mặc định: 1099511627776 = 1 TiB
image_size_cap = 1099511627776

# Giới hạn tổng dung lượng lưu trữ của 1 tenant (project)
# Giá trị 0 = không giới hạn
# Đơn vị: B, KB, MB, GB, TB (ví dụ: 50GB)
user_storage_quota = 0

# Sử dụng giới hạn được đăng ký trong Keystone thay vì cấu hình tĩnh
# Khi True: các giới hạn tĩnh trong file này sẽ bị bỏ qua
use_keystone_limits = false

# Số members tối đa có thể share 1 image
image_member_quota = 128

# Số properties metadata tối đa trên 1 image
image_property_quota = 128

# Số tags tối đa trên 1 image
image_tag_quota = 128

# Số locations tối đa của 1 image
image_location_quota = 10

# Số kết quả trả về mặc định cho các request list
limit_param_default = 25

# Số kết quả tối đa cho phép trong 1 request
api_limit_max = 1000
```

### 2.4. Cấu hình Bảo mật Image

```ini
[DEFAULT]
# Cho phép user không xác thực (anonymous) truy cập API ở chế độ read-only
# Nên để False trong production
allow_anonymous_access = false

# Hiện URL trực tiếp của image data khi trả về thông tin image
# CẢNH BÁO BẢO MẬT: URL có thể chứa credentials => giữ False
show_image_direct_url = false

# Tính toán hash và checksum khi thêm location mới cho image
do_secure_hash = true

# Thuật toán hash được dùng để tính os_hash_value của image
# Dùng sha512 (mặc định) để đảm bảo tính toàn vẹn
hashing_algorithm = sha512

# Thuật toán digest cho chữ ký số (không liên quan đến image signing)
# DEPRECATED từ Dalmatian - sẽ bị xóa
# digest_algorithm = sha256
```

### 2.5. Cấu hình Xóa trễ (Delayed Delete)

```ini
[DEFAULT]
# Bật/tắt tính năng xóa trễ
# Khi True: image chuyển sang pending_delete thay vì bị xóa ngay
delayed_delete = false

# Thời gian (giây) image ở trạng thái pending_delete trước khi scrubber xử lý
scrub_time = 0

# Số luồng song song để xóa image data (scrubbing)
scrub_pool_size = 1
```

> **Lưu ý:** Khi bật `delayed_delete = true`, bắt buộc phải chạy dịch vụ **glance-scrubber** như một tác vụ định kỳ (cron job), nếu không storage backend sẽ bị đầy dần.

### 2.6. Cấu hình Image Import

```ini
[DEFAULT]
# Thư mục staging tạm thời cho quá trình import image
# Phải là filesystem được chia sẻ nếu chạy multi-node
node_staging_uri = file:///tmp/staging/

# Các phương thức import được kích hoạt
# glance-direct: upload trực tiếp qua API
# web-download:  Glance tự tải image từ URL
# copy-image:    sao chép image sang store khác
# glance-download: tải từ Glance instance khác (cần federated setup)
enabled_import_methods = glance-direct,web-download,copy-image
```

### 2.7. Cấu hình Property Protection

```ini
[DEFAULT]
# Đường dẫn tới file bảo vệ properties của image
# Nếu không set, tất cả properties đều không được bảo vệ
property_protection_file = <None>

# Định dạng rule trong file bảo vệ: 'roles' hoặc 'policies'
property_protection_rule_format = roles
```

### 2.8. Cấu hình Message Queue (Notification)

```ini
[DEFAULT]
# URL kết nối tới message broker (RabbitMQ)
transport_url = rabbit://openstack:password@controller:5672/

# ID định danh nguồn gốc notification từ Glance
default_publisher_id = image.localhost

# Danh sách các loại notification bị tắt (để trống = bật tất cả)
disabled_notifications = []
```

## 3. Section [database] - Cấu hình Database

Glance dùng database để lưu **metadata** của image (tên, định dạng, trạng thái, ...).

```ini
[database]
# Chuỗi kết nối SQLAlchemy tới database chính
# Cú pháp: dialect+driver://user:password@host/dbname
connection = mysql+pymysql://glance:GLANCE_DBPASS@controller/glance

# Kết nối tới database slave (replica) - dùng cho read queries
# slave_connection = mysql+pymysql://glance:pass@slave-controller/glance

# Kích thước pool kết nối tối đa (0 = không giới hạn)
max_pool_size = 5

# Số kết nối tăng thêm khi pool đầy
max_overflow = 50

# Thời gian (giây) 1 kết nối trong pool được tái sử dụng
connection_recycle_time = 3600

# Số lần thử kết nối lại khi khởi động (-1 = thử mãi mãi)
max_retries = 10

# Khoảng cách giữa các lần thử kết nối lại (giây)
retry_interval = 10

# SQL mode cho MySQL
mysql_sql_mode = TRADITIONAL
```

## 4. Section [keystone_authtoken] - Xác thực Keystone

Section này cấu hình Glance xác thực mọi request API thông qua Keystone.

```ini
[keystone_authtoken]
# URL công khai của Keystone để client dùng để xác thực
www_authenticate_uri = http://controller:5000

# URL nội bộ của Keystone để Glance dùng để validate token
auth_url = http://controller:5000

# Plugin xác thực (password = dùng username/password)
auth_type = password

# Project mà Glance service account thuộc về
project_domain_name = Default
user_domain_name = Default
project_name = service

# Thông tin service account của Glance trong Keystone
username = glance
password = GLANCE_PASS

# Bật cache token để giảm request tới Keystone
memcached_servers = controller:11211
```

> **Tại sao cần section này?** Mỗi khi user/Nova gửi request tới Glance, Glance sẽ lấy token từ header `X-Auth-Token` và gọi Keystone để xác minh tính hợp lệ. Nếu token hợp lệ, Glance mới xử lý request đó.

## 5. Section [glance_store] - Cấu hình Storage Backend

Section này quyết định **file image vật lý sẽ được lưu ở đâu**.

```ini
[glance_store]
# Danh sách các backend được bật (định nghĩa theo cú pháp tên:loại)
# Ví dụ: default_backend = fs1
# Trong [DEFAULT]: enabled_backends = fs1:file,ceph1:rbd
default_backend = fs1

[DEFAULT]
# Khai báo các backend và loại của chúng
# Cú pháp: <tên>:<loại>, phân cách bằng dấu phẩy
# Các loại: file, rbd, swift, cinder, s3, vmware
enabled_backends = fs1:file
```

## 6. Cấu hình các Storage Backend chi tiết

### 6.1. Filesystem Backend (Local File System)

Lưu image trực tiếp trên ổ cứng của server. Phù hợp cho **môi trường dev/test** hoặc single-node.

```ini
[fs1]
# Thư mục lưu file image
filesystem_store_datadir = /var/lib/glance/images/

# Quyền truy cập file image (octal)
# 0 = dùng quyền mặc định của hệ thống
filesystem_store_file_perm = 0

# Cấu hình nhiều thư mục với độ ưu tiên khác nhau
# Cú pháp: <đường_dẫn>:<độ_ưu_tiên>
# Glance ưu tiên thư mục có số lớn hơn, nếu bằng nhau thì chọn nhiều dung lượng nhất
# filesystem_store_datadirs = /mnt/disk1/images:100,/mnt/disk2/images:200
```

### 6.2. Ceph RBD Backend

Backend phổ biến nhất trong **môi trường production**. Cho phép Nova clone image cực nhanh (Copy-on-Write).

```ini
[ceph1]
# Tên Ceph pool chứa image
rbd_store_pool = images

# User Ceph có quyền đọc/ghi vào pool
rbd_store_user = glance

# Địa chỉ Ceph Monitor
rbd_store_ceph_conf = /etc/ceph/ceph.conf

# Kích thước mỗi chunk khi ghi vào Ceph (byte)
# Mặc định: 8388608 = 8 MiB
rbd_store_chunk_size = 8
```

> **Ưu điểm của Ceph:** Nova có thể tạo máy ảo từ image Glance bằng cơ chế **thin clone** (không cần copy toàn bộ file), giúp tốc độ tạo máy ảo rất nhanh.

### 6.3. Swift Backend

Lưu image trong OpenStack Object Storage (Swift). Phù hợp cho lưu trữ lâu dài, an toàn cao.

```ini
[swift1]
# Địa chỉ Auth endpoint của Swift
swift_store_auth_address = http://controller:5000/v3

# User xác thực với Swift
swift_store_user = service:glance
swift_store_key = SWIFT_KEY

# Container trong Swift để lưu image
swift_store_container = glance

# Kích thước object lớn (byte) - chia nhỏ nếu vượt quá
swift_store_large_object_size = 5368709120

# Kích thước mỗi chunk khi upload large object
swift_store_large_object_chunk_size = 209715200

# Tạo container tự động nếu chưa tồn tại
swift_store_create_container_on_put = true
```

### 6.4. S3 Backend

Lưu image trên Amazon S3 hoặc bất kỳ object storage tương thích S3 (MinIO, Ceph RadosGW).

```ini
[s3_store]
# Endpoint URL của S3
s3_store_host = s3.amazonaws.com

# Access key và secret key
s3_store_access_key = ACCESS_KEY
s3_store_secret_key = SECRET_KEY

# Tên bucket S3 để lưu image
s3_store_bucket = glance-images

# Tạo bucket tự động nếu chưa tồn tại
s3_store_create_bucket_on_put = false

# Kích thước tối đa cho upload thông thường (byte)
# Quá mức này sẽ dùng multipart upload
s3_store_large_object_size = 104857600

# Kích thước mỗi part trong multipart upload
s3_store_large_object_chunk_size = 10485760
```

### 6.5. Cinder Backend

Lưu image dưới dạng Cinder volume. Phù hợp khi muốn tận dụng hạ tầng block storage.

```ini
[cinder_store]
# Địa chỉ Cinder API
cinder_catalog_info = volumev3:cinderv3:publicURL

# Volume type dùng cho image store
cinder_volume_type = image-store

# Kích thước store volume (GiB)
cinder_store_volume_size = 20

# Cho phép multi-attach
cinder_do_extend_volume = true
```

## 7. Section [image_cache] - Cấu hình Image Cache

**Image Cache** giúp lưu bản sao image tại local, tăng tốc các lần tải xuống tiếp theo.

```ini
[DEFAULT]
# Thư mục gốc lưu cache image
image_cache_dir = /var/lib/glance/image-cache/

# Kích thước cache tối đa (byte) trước khi cache-pruner dọn dẹp
# Mặc định: 10737418240 = 10 GiB
image_cache_max_size = 10737418240

# Thời gian tối đa (giây) 1 image chưa hoàn chỉnh được giữ trong cache
# Mặc định: 86400 = 24 giờ
image_cache_stall_time = 86400

# Driver quản lý cache (Dalmatian+: centralized_db là mặc định)
# centralized_db: dùng database chung cho tất cả Glance nodes
# xattr: dùng extended attributes của filesystem
image_cache_driver = centralized_db
```

**Cấu trúc thư mục cache:**

```ini
/var/lib/glance/image-cache/
├── <image-id-1>          # Image đã được cache hoàn chỉnh
├── <image-id-2>
├── incomplete/           # Image đang được tải về (chưa hoàn chỉnh)
├── invalid/              # Image bị lỗi khi tải
└── queue/                # Image đang xếp hàng để được cache trước (prefetch)
```

**Các tiến trình quản lý cache:**

| Tiến trình                | Chức năng                                           |
|---------------------------|-----------------------------------------------------|
| `glance-cache-pruner`     | Dọn dẹp khi cache vượt quá `image_cache_max_size`   |
| `glance-cache-cleaner`    | Xóa các image chưa hoàn chỉnh (incomplete)          |
| `glance-cache-prefetcher` | Tải trước image từ hàng đợi (queue)                 |

> **Lưu ý (Dalmatian 2024.2+):** Driver `sqlite` cho cache đã bị **deprecated** và sẽ bị xóa hoàn toàn. Hãy chuyển sang dùng `centralized_db`.

## 8. Section [barbican] - Quản lý Key/Bí mật

Barbican là dịch vụ quản lý khóa bí mật trong OpenStack. Glance dùng Barbican để **mã hóa image** (image encryption).

```ini
[barbican]
# URL endpoint của Barbican
barbican_endpoint = http://controller:9311/

# Phiên bản API Barbican
barbican_api_version = v1

# URL Keystone để Barbican xác thực
auth_endpoint = http://controller:5000/identity/v3

# Loại endpoint Barbican sẽ dùng
barbican_endpoint_type = public

# Region của Barbican
barbican_region_name = RegionOne

# Xác thực SSL khi kết nối tới Barbican
verify_ssl = true

# Số lần thử lại khi tạo key
number_of_retries = 60
retry_delay = 1
```

## 9. Section [cors] - Cấu hình CORS

CORS (Cross-Origin Resource Sharing) cần thiết khi Horizon Dashboard hoặc các ứng dụng web gọi trực tiếp API Glance từ browser.

```ini
[cors]
# Domain được phép gửi cross-origin request
# Ví dụ: http://horizon.example.com
allowed_origin = http://horizon.example.com

# Cho phép gửi kèm credentials (cookie, auth header)
allow_credentials = true

# Thời gian cache kết quả preflight (giây)
max_age = 3600

# Các HTTP method được phép
allow_methods = GET,PUT,POST,DELETE,PATCH

# Các header được phép trong request
allow_headers = Content-MD5,X-Auth-Token,X-Identity-Status,X-Roles
```

## 10. Cấu hình Logging

Logging được cấu hình trong section `[DEFAULT]`.

```ini
[DEFAULT]
# ---- Cấu hình cơ bản ----

# Bật chế độ debug (log level = DEBUG thay vì INFO)
debug = false

# File log đầu ra (nếu không set => log ra stderr)
log_file = /var/log/glance/glance-api.log

# Thư mục chứa file log (dùng khi log_file là đường dẫn tương đối)
log_dir = /var/log/glance

# ---- Ghi log bằng Syslog / Journald ----

# Gửi log tới syslog
use_syslog = false

# Gửi log tới systemd journal (khuyên dùng trên hệ thống systemd)
use_journal = false

# Facility của syslog
syslog_log_facility = LOG_USER

# ---- Định dạng log ----

# Xuất log theo định dạng JSON
use_json = false

# Log ra stderr
use_stderr = false

# Format timestamp trong log
log_date_format = %Y-%m-%d %H:%M:%S

# ---- Luân chuyển file log (Log Rotation) ----

# Kiểu rotation: none | interval | size
log_rotation_type = none

# Kích thước tối đa file log (MB) - chỉ dùng khi log_rotation_type = size
max_logfile_size_mb = 200

# Số file log tối đa giữ lại
max_logfile_count = 30

# Khoảng thời gian rotation - chỉ dùng khi log_rotation_type = interval
log_rotate_interval = 1
log_rotate_interval_type = days   # Seconds, Minutes, Hours, Days, Weekday, Midnight
```

## 11. Ví dụ cấu hình hoàn chỉnh

Dưới đây là ví dụ file `glance-api.conf` hoàn chỉnh cho môi trường production với Ceph backend:

```ini
[DEFAULT]
# Mạng
bind_host = 0.0.0.0
bind_port = 9292
workers = 4

# Backend
enabled_backends = ceph1:rbd

# Import
node_staging_uri = file:///var/lib/glance/staging/
enabled_import_methods = glance-direct,web-download,copy-image

# Quota & Giới hạn
image_size_cap = 1099511627776    # 1 TiB
user_storage_quota = 0            # Không giới hạn

# Bảo mật
allow_anonymous_access = false
show_image_direct_url = false
hashing_algorithm = sha512

# Cache image
image_cache_dir = /var/lib/glance/image-cache/
image_cache_max_size = 10737418240  # 10 GiB
image_cache_driver = centralized_db

# Logging
log_file = /var/log/glance/glance-api.log
debug = false

# Message Queue
transport_url = rabbit://openstack:RABBIT_PASS@controller:5672/

[database]
connection = mysql+pymysql://glance:GLANCE_DBPASS@controller/glance
max_pool_size = 5
max_overflow = 50
max_retries = 10
retry_interval = 10

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = glance
```

## Tóm tắt các Section quan trọng

| Section                | Vai trò                                            | Bắt buộc?   |
|------------------------|----------------------------------------------------|-------------|
| `[DEFAULT]`            | Cấu hình chung: network, worker, quota, bảo mật    | Có          |
| `[database]`           | Kết nối database lưu metadata image                | Có          |
| `[keystone_authtoken]` | Xác thực request qua Keystone                      | Có          |
| `[glance_store]`       | Chọn backend lưu trữ file image                    | Có          |
| `[<tên_backend>]`      | Cấu hình chi tiết từng backend (file/rbd/swift...) | Có          |
| `[image_cache]`        | Cấu hình bộ nhớ đệm image                          | Tùy chọn    |
| `[barbican]`           | Mã hóa image với Barbican Key Manager              | Tùy chọn    |
| `[cors]`               | Cấu hình cross-origin request                      | Tùy chọn    |
