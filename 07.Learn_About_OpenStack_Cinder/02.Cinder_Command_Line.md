## 1. Lưu ý về CLI

| CLI                  | Khi nào dùng                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------- |
| `openstack volume *` | Lệnh hàng ngày cho user và operator. **Dùng ưu tiên.**                                   |
| `cinder *`           | Các lệnh admin nâng cao chưa migrate sang openstack CLI (get-pools, get-capabilities,...)|
| `cinder-manage *`    | Chạy trực tiếp trên node Cinder — migrate DB, sync quota, diagnose nội bộ                |

**Xác thực môi trường trước khi chạy lệnh:**

```bash
source /etc/kolla/admin-openrc.sh   # hoặc openrc của project tương ứng
openstack volume service list        # kiểm tra service đang up
```

## 2. Quản lý Volume

### 2.1. Tạo Volume

```bash
# Tạo volume rỗng
openstack volume create --size <GB> <tên-volume>

# Tạo volume với volume type cụ thể (map vào backend)
openstack volume create --size 100 --type ceph-ssd my-volume

# Tạo volume từ image (boot volume)
openstack volume create --size 50 --image <image-id> --bootable boot-vol

# Tạo volume từ snapshot
openstack volume create --size 100 --snapshot <snapshot-id> vol-from-snap

# Tạo volume từ một volume khác (clone)
openstack volume create --size 100 --source <volume-id> vol-cloned

# Tạo volume trong availability zone cụ thể
openstack volume create --size 100 --availability-zone nova --type ceph-ssd my-vol-az

# Tạo volume với metadata
openstack volume create --size 100 --property env=prod --property team=infra my-vol-meta

# Tạo nhiều volume cùng lúc
openstack volume create --size 50 --count 3 bulk-vol
```

### 2.2. Liệt kê & Xem thông tin Volume

```bash
# Liệt kê tất cả volume trong project
openstack volume list

# Liệt kê tất cả volume toàn hệ thống (admin)
openstack volume list --all-projects

# Liệt kê với filter
openstack volume list --status available
openstack volume list --name my-volume
openstack volume list --long          # hiển thị thêm cột (type, bootable...)

# Xem chi tiết một volume
openstack volume show <volume-id hoặc tên>

# Lấy tóm tắt số lượng và dung lượng (admin)
cinder summary --all-tenants
```

### 2.3. Sửa Volume

```bash
# Đổi tên
openstack volume set --name new-name <volume-id>

# Thêm/sửa description
openstack volume set --description "Volume production DB" <volume-id>

# Đánh dấu bootable
openstack volume set --bootable <volume-id>
openstack volume set --non-bootable <volume-id>

# Thêm metadata
openstack volume set --property key=value <volume-id>

# Xóa metadata
openstack volume unset --property key <volume-id>
```

### 2.4. Mở rộng Volume (Extend)

```bash
# Extend volume — volume phải ở trạng thái available hoặc in-use (tùy backend)
openstack volume set --size <new-size-GB> <volume-id>

# Cách dùng với cinder CLI (tương đương)
cinder extend <volume-id> <new-size>
```

> Lưu ý: Sau khi extend volume đang gắn vào VM, cần resize filesystem bên trong VM:

```bash
# Trong VM (với ext4)
sudo resize2fs /dev/vdb

# Với xfs
sudo xfs_growfs /mount/point
```

### 2.5. Xóa Volume

```bash
# Xóa volume thông thường (phải ở trạng thái available)
openstack volume delete <volume-id>

# Xóa nhiều volume
openstack volume delete <vol-id-1> <vol-id-2> <vol-id-3>

# Force delete — bỏ qua trạng thái (admin)
cinder force-delete <volume-id>

# Xóa volume và snapshot liên quan
openstack volume delete --purge <volume-id>
```

### 2.6. Migrate Volume

```bash
# Migrate volume sang host/backend khác (admin)
cinder migrate <volume-id> <destination-host>

# Ví dụ
cinder migrate my-vol cinder@lvm#LVM_iSCSI

# Đổi volume type (retype) — có thể kéo theo migrate backend
cinder retype --migration-policy on-demand <volume-id> <new-volume-type>
```

### 2.7. Revert Volume về Snapshot

```bash
# Revert volume về trạng thái của snapshot (volume phải available, snapshot là mới nhất)
openstack volume revert <volume-id> --snapshot <snapshot-id>
```

### 2.8. Transfer Volume giữa Project

```bash
# Tạo transfer request (phía project nguồn)
openstack volume transfer request create <volume-id>
# Lấy transfer_id và auth_key từ output

# Chấp nhận transfer (phía project đích)
openstack volume transfer request accept <transfer-id> --auth-key <auth-key>

# Liệt kê các transfer đang chờ
openstack volume transfer request list
```

## 3. Quản lý Snapshot

### 3.1. Tạo & Liệt kê Snapshot

```bash
# Tạo snapshot (volume có thể đang in-use với --force)
openstack volume snapshot create --volume <volume-id> <snapshot-name>
openstack volume snapshot create --volume <volume-id> --force snap-of-attached-vol

# Liệt kê snapshot
openstack volume snapshot list
openstack volume snapshot list --volume <volume-id>
openstack volume snapshot list --all-projects   # admin

# Xem chi tiết
openstack volume snapshot show <snapshot-id>
```

### 3.2. Sửa & Xóa Snapshot

```bash
# Đổi tên / description
openstack volume snapshot set --name new-snap-name <snapshot-id>
openstack volume snapshot set --description "Daily backup" <snapshot-id>

# Thêm metadata vào snapshot
openstack volume snapshot set --property key=value <snapshot-id>

# Xóa snapshot
openstack volume snapshot delete <snapshot-id>

# Force delete snapshot (admin)
cinder snapshot-force-delete <snapshot-id>

# Reset trạng thái snapshot kẹt (admin)
cinder snapshot-reset-state --state available <snapshot-id>
```

## 4. Attach / Detach Volume vào VM

```bash
# Attach volume vào VM (Nova sẽ xử lý phía compute)
openstack server add volume <vm-id> <volume-id>

# Attach với device path cụ thể
openstack server add volume <vm-id> <volume-id> --device /dev/vdc

# Detach volume khỏi VM
openstack server remove volume <vm-id> <volume-id>

# Kiểm tra volume đang attach vào VM nào
openstack volume show <volume-id> | grep attachments

# Xem danh sách volume đang attach của VM
openstack server show <vm-id> | grep volumes
```

## 5. Volume Type & Extra Specs

Volume Type là cơ chế map yêu cầu của user đến backend storage cụ thể.

### 5.1. Tạo & Quản lý Volume Type

```bash
# Tạo volume type
openstack volume type create ceph-ssd
openstack volume type create lvm-local

# Liệt kê volume type
openstack volume type list
openstack volume type list --long   # hiển thị extra specs

# Xem chi tiết
openstack volume type show ceph-ssd

# Xóa volume type
openstack volume type delete ceph-ssd

# Set default volume type cho project (admin)
cinder default-type-set --volume-type ceph-ssd <project-id>
```

### 5.2. Extra Specs — Map Volume Type vào Backend

```bash
# Set extra spec để map vào backend cụ thể
openstack volume type set --property volume_backend_name=ceph-ssd ceph-ssd
openstack volume type set --property volume_backend_name=LVM_iSCSI lvm-local

# Set các thông số khác
openstack volume type set --property replication_enabled=<is> True ceph-ssd
openstack volume type set --property multiattach=<is> True my-type

# Unset extra spec
openstack volume type unset --property volume_backend_name ceph-ssd

# Liệt kê tất cả volume type và extra specs (cinder CLI)
cinder extra-specs-list
```

### 5.3. Encryption Type (Admin)

```bash
# Tạo encryption cho volume type
cinder encryption-type-create --cipher aes-xts-plain64 --key_size 256 \
  --control_location front-end <volume-type-id> nova.volume.encryptors.luks.LuksEncryptor

# Liệt kê
cinder encryption-type-list

# Xóa
cinder encryption-type-delete <volume-type-id>
```

## 6. QoS Specs

QoS cho phép giới hạn IOPS, bandwidth cho volume.

```bash
# Tạo QoS spec
cinder qos-create high-iops consumer=front-end read_iops_sec=5000 write_iops_sec=3000

# Liệt kê QoS spec
cinder qos-list

# Xem chi tiết
cinder qos-show <qos-id>

# Set / update thông số
cinder qos-key <qos-id> action=set read_iops_sec=8000

# Gán QoS vào Volume Type
cinder qos-associate <qos-id> <volume-type-id>

# Gỡ QoS khỏi Volume Type
cinder qos-disassociate <qos-id> <volume-type-id>

# Xem Volume Type nào đang dùng QoS này
cinder qos-get-association <qos-id>

# Xóa QoS spec
cinder qos-delete <qos-id>
```

## 7. Backup & Restore

### 7.1. Tạo Backup

```bash
# Backup volume (volume có thể đang available hoặc in-use)
openstack volume backup create <volume-id>
openstack volume backup create --name daily-backup-prod <volume-id>

# Backup volume đang gắn vào VM (force)
openstack volume backup create --force <volume-id>

# Incremental backup (chỉ backup phần thay đổi)
openstack volume backup create --incremental <volume-id>

# Backup từ snapshot
openstack volume backup create --snapshot <snapshot-id> <volume-id>

# Backup vào container cụ thể (Swift backend)
cinder backup-create --container my-bucket <volume-id>
```

### 7.2. Liệt kê & Xem Backup

```bash
# Liệt kê backup
openstack volume backup list
openstack volume backup list --all-projects   # admin

# Xem chi tiết
openstack volume backup show <backup-id>

# Update tên/description của backup
cinder backup-update --name new-name <backup-id>
```

### 7.3. Restore Backup

```bash
# Restore backup vào volume mới
openstack volume backup restore <backup-id>

# Restore vào volume cụ thể (volume phải available)
openstack volume backup restore <backup-id> --volume <volume-id>
```

### 7.4. Xóa & Admin Backup

```bash
# Xóa backup
openstack volume backup delete <backup-id>

# Reset trạng thái backup kẹt (admin)
cinder backup-reset-state --state available <backup-id>

# Export metadata backup (để import sang hệ thống khác)
cinder backup-export <backup-id>

# Import backup metadata
cinder backup-import <backup-service> <backup-url>
```

## 8. Cinder Scheduler

**Scheduler** không có lệnh user trực tiếp, nhưng operator có thể tương tác qua các lệnh sau:

### 8.1. Xem Backend & Pool

```bash
# Xem danh sách backend và pool đang hoạt động (admin)
cinder get-pools
cinder get-pools --detail   # thêm thông số capacity, capabilities

# Xem stats của backend cụ thể (admin)
cinder get-capabilities <host@backend#pool>
# Ví dụ:
cinder get-capabilities cinder@ceph#ceph-ssd
```

### 8.2. Xem Filter & Weigher đang dùng

Kiểm tra trong `cinder.conf`:

```ini
[DEFAULT]
scheduler_driver = cinder.scheduler.filter_scheduler.FilterScheduler
scheduler_default_filters = AvailabilityZoneFilter,CapacityFilter,CapabilitiesFilter
scheduler_default_weighers = CapacityWeigher
```

```bash
# Xem danh sách filter đang enable (cinder CLI)
cinder list-filters
```

### 8.3. Kiểm tra lý do Scheduler từ chối Backend

Khi tạo volume thất bại, Cinder lưu message lý do:

```bash
# Xem tất cả error message
openstack volume message list

# Xem message của volume cụ thể
openstack volume message list --resource-id <volume-id>

# Xem chi tiết message
openstack volume message show <message-id>

# Xóa message sau khi xử lý xong
openstack volume message delete <message-id>
```

## 9. Quản lý Service & Host

### 9.1. Xem Trạng thái Service

```bash
# Xem tất cả Cinder service đang chạy
openstack volume service list

# Filter theo host hoặc binary
openstack volume service list --host storage01
openstack volume service list --binary cinder-volume

# Xem availability zone
openstack availability zone list
openstack availability zone list --volume
```

### 9.2. Enable / Disable Service

```bash
# Disable service (để bảo trì)
openstack volume service set --disable <host> <binary>
openstack volume service set --disable --reason "Maintenance" storage01 cinder-volume

# Enable lại service
openstack volume service set --enable <host> <binary>

# Với cinder CLI (tương đương)
cinder service-disable <host> <binary>
cinder service-enable <host> <binary>
```

### 9.3. Cluster (Active-Active cinder-volume)

```bash
# Liệt kê cluster
cinder cluster-list

# Xem chi tiết cluster
cinder cluster-show <cluster-name>

# Enable / Disable cả cluster
cinder cluster-enable <cluster-name> cinder-volume
cinder cluster-disable <cluster-name> cinder-volume
```

### 9.4. Replication (Admin)

```bash
# Failover sang replica khi primary storage bị lỗi
cinder failover-host <host> --backend_id <replica-id>

# Freeze host (dừng nhận request mới)
cinder freeze-host <host>

# Thaw host (mở lại sau khi sửa xong)
cinder thaw-host <host>
```

## 10. Volume Group & Group Snapshot

Volume Group cho phép quản lý nhiều volume như một đơn vị — tạo snapshot đồng nhất (consistent group snapshot).

```bash
# Tạo group type
cinder group-type-create consistent-group
cinder group-type-key consistent-group action=set consistent_group_snapshot_enabled="<is> True"

# Tạo group
cinder group-create --name my-group <group-type-id> <volume-type-id>

# Liệt kê group
cinder group-list

# Thêm / gỡ volume vào/khỏi group
cinder group-update --add-volumes <vol-id-1>,<vol-id-2> <group-id>
cinder group-update --remove-volumes <vol-id> <group-id>

# Tạo group snapshot (snapshot đồng thời tất cả volume trong group)
cinder group-snapshot-create --name gs-prod <group-id>

# Liệt kê group snapshot
cinder group-snapshot-list

# Restore group từ group snapshot
cinder group-create-from-src --group-snapshot <group-snapshot-id> --name restored-group

# Xóa group
cinder group-delete <group-id>
cinder group-delete --delete-volumes <group-id>   # xóa cả volume bên trong
```

## 11. Quota

```bash
# Xem quota của project hiện tại
openstack quota show

# Xem quota của project khác (admin)
openstack quota show <project-id>

# Set quota (admin)
openstack quota set --volumes 50 --gigabytes 2000 --snapshots 100 <project-id>

# Set quota backup
openstack quota set --backups 20 --backup-gigabytes 1000 <project-id>

# Reset quota về default
openstack quota delete <project-id>

# Xem default quota
openstack quota show --default
```

## 12. Troubleshooting & Admin

### 12.1. Reset Trạng thái Volume / Snapshot bị Kẹt

```bash
# Reset volume về trạng thái available (admin)
openstack volume set --state available <volume-id>

# Với cinder CLI (đầy đủ tùy chọn hơn)
cinder reset-state --state available <volume-id>
cinder reset-state --state error <volume-id>
cinder reset-state --attach-status detached <volume-id>

# Reset snapshot
cinder snapshot-reset-state --state available <snapshot-id>

# Reset backup
cinder backup-reset-state --state available <backup-id>
```

### 12.2. Force Delete

```bash
# Force xóa volume bất kể trạng thái (admin)
cinder force-delete <volume-id>

# Force detach volume khỏi VM (admin — khi VM đã mất)
cinder force-detach <volume-id> <attachment-id>
```

### 12.3. Manage / Unmanage Volume

Cho phép đưa volume vật lý có sẵn trên backend vào quản lý của Cinder mà không cần tạo mới.

```bash
# Liệt kê volume vật lý chưa được Cinder quản lý
cinder manageable-list <host@backend#pool>

# Đưa volume vào quản lý
cinder manage <host@backend#pool> <reference>

# Gỡ volume khỏi Cinder (nhưng không xóa dữ liệu vật lý)
cinder unmanage <volume-id>

# Tương tự với snapshot
cinder manageable-snapshot-list <host@backend#pool>
cinder snapshot-manage <host@backend#pool> <volume-id> <reference>
cinder snapshot-unmanage <snapshot-id>
```

### 12.4. Xem Error Message từ Scheduler

```bash
openstack volume message list
openstack volume message show <message-id>
openstack volume message delete <message-id>
```

### 12.5. Attachment API (Low-level — dùng khi tích hợp với compute tùy chỉnh)

```bash
# Xem danh sách attachment
cinder attachment-list

# Xem chi tiết attachment
cinder attachment-show <attachment-id>

# Tạo attachment thủ công
cinder attachment-create <volume-id> <connector-id>

# Xóa attachment
cinder attachment-delete <attachment-id>
```

## 13. cinder-manage — Quản trị Hệ thống

> Chạy trực tiếp trên node cài Cinder, cần quyền root hoặc user `cinder`.

### 13.1. Database

```bash
# Xem phiên bản database schema hiện tại
cinder-manage db version

# Migrate database lên phiên bản mới nhất (sau khi upgrade)
cinder-manage db sync

# Dọn dẹp các record đã xóa (soft delete) cũ hơn N ngày
cinder-manage db purge <số-ngày>
# Ví dụ: xóa record cũ hơn 30 ngày
cinder-manage db purge 30

# Chạy online data migration (cần thiết khi upgrade major version)
cinder-manage db online_data_migrations
cinder-manage db online_data_migrations --max_count 100

# Sửa service_uuid references bị lỗi (tính năng mới trong 2025.1)
cinder-manage db fix_volume_service_uuid
```

### 13.2. Service

```bash
# Liệt kê tất cả Cinder service đang đăng ký trong DB
cinder-manage service list
```

### 13.3. Quota

```bash
# Kiểm tra quota có bị lệch không
cinder-manage quota check
cinder-manage quota check --project-id <project-id>

# Đồng bộ lại quota (khi phát hiện lệch)
cinder-manage quota sync
cinder-manage quota sync --project-id <project-id>

# Cập nhật usage quota thực tế
cinder-manage quota update --project-id <project-id>
```

### 13.4. Upgrade

```bash
# Cập nhật RPC version sau khi upgrade offline
cinder-manage db online_data_migrations
```

## PHỤ LỤC: Các Trạng Thái Volume Quan Trọng

| Trạng thái           | Ý nghĩa                       |
|----------------------|-------------------------------|
| `creating`           | Đang được tạo                 |
| `available`          | Sẵn sàng, chưa gắn vào VM     |
| `in-use`             | Đang gắn vào VM               |
| `deleting`           | Đang bị xóa                   |
| `error`              | Lỗi trong quá trình tạo/xóa   |
| `error_deleting`     | Lỗi khi xóa                   |
| `backing-up`         | Đang tạo backup               |
| `restoring-backup`   | Đang restore từ backup        |
| `extending`          | Đang mở rộng dung lượng       |
| `maintenance`        | Đang trong quá trình migrate  |
| `retyping`           | Đang đổi volume type          |

## PHỤ LỤC: Lệnh Kiểm Tra Nhanh Hàng Ngày (Operator Checklist)

```bash
# 1. Kiểm tra tất cả service đang up
openstack volume service list

# 2. Xem pool còn dung lượng
cinder get-pools --detail | grep -E 'free|total|name'

# 3. Volume bị kẹt trạng thái error
openstack volume list --all-projects --status error

# 4. Snapshot bị kẹt
openstack volume snapshot list --all-projects --status error

# 5. Xem error message từ scheduler
openstack volume message list

# 6. Quota có lệch không
cinder-manage quota check

# 7. Backup đang chạy
openstack volume backup list --all-projects --status backing-up
```
