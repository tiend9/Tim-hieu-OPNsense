# CƠ CHẾ SCHEDULER, FILTER VÀ WEIGHTING TRONG NOVA

> Phiên bản tham chiếu: OpenStack `2026.1 Gazpacho` / Nova `33.x`.
> Phần này cập nhật lại theo kiến trúc scheduler mới: **Placement prefilter -> Nova filters -> Nova weighers**.

## I. TÌM HIỂU NOVA SCHEDULER

### 1. Nova Scheduler là gì?

`nova-scheduler` là service quyết định compute host nào sẽ chạy VM.

Nó trả lời câu hỏi:

```text
VM này nên chạy trên host nào?
```

Scheduler được dùng khi:

- tạo VM mới;
- resize;
- cold migrate;
- evacuate;
- unshelve sau khi shelve offload;
- một số luồng move instance khác.

### 2. Kiến trúc tổng thể

```text
User / Horizon / CLI
        |
        v
     nova-api
        |
        v
 nova-conductor
        |
        v
 nova-scheduler <--> Placement
        |
        v
 nova-conductor
        |
        v
 nova-compute
```

Vai trò:

| Component | Vai trò |
| --------- | ------- |
| `nova-api` | nhận và validate request |
| `nova-conductor` | điều phối workflow và DB |
| `nova-scheduler` | chọn host/cell phù hợp |
| Placement | quản lý inventory, allocation, trait, aggregate |
| `nova-compute` | tạo VM trên hypervisor |

### 3. Scheduler driver hiện nay

Từ Nova `23.0.0` (Wallaby), Nova đã bỏ custom scheduler drivers. Hiện tại chỉ còn **Filter Scheduler**.

Vì vậy không nên trình bày theo hướng cấu hình `scheduler_driver` như các bản rất cũ nữa.

Cách hiểu đúng:

```text
Nova dùng Filter Scheduler:
  1. Placement prefilter
  2. Nova filters
  3. Nova weighers
```

## II. FLOW SCHEDULING HIỆN ĐẠI

### 1. Flow tổng quát

```text
Request create VM
       |
       v
RequestSpec
       |
       v
Placement prefilters
       |
       v
Placement allocation candidates
       |
       v
Nova filters
       |
       v
Nova weighers
       |
       v
Selected host + alternate hosts
```

### 2. Giải thích từng bước

#### Bước 1: Nova nhận request

User tạo VM:

```bash
openstack server create \
  --image ubuntu-24.04 \
  --flavor m1.small \
  --network private \
  vm01
```

Nova tạo `RequestSpec` chứa:

- flavor;
- image;
- requested network;
- availability zone;
- scheduler hints;
- server group;
- flavor extra specs;
- image properties.

#### Bước 2: Scheduler hỏi Placement

Placement trả về các **allocation candidates** có đủ tài nguyên:

```text
VCPU
MEMORY_MB
DISK_GB
PCI / VGPU nếu có
traits
aggregates
```

Điểm khác tài liệu cũ:

```text
RamFilter/CoreFilter/DiskFilter không còn là cách chính để lọc tài nguyên cơ bản.
Placement làm phần "host có đủ resource không?" trước.
```

#### Bước 3: Nova chạy filters

Filters loại host không hợp lệ.

Ví dụ:

- compute service bị disabled;
- image properties không hợp;
- flavor extra specs không hợp;
- server group anti-affinity không đạt;
- host không thuộc aggregate/AZ phù hợp.

#### Bước 4: Nova chạy weighers

Nếu còn nhiều host hợp lệ, weighers chấm điểm.

Ví dụ:

- host còn nhiều RAM hơn;
- host còn nhiều CPU hơn;
- host ít build failure hơn;
- host ít I/O operation hơn;
- host cùng cell khi move instance;
- host có hypervisor version phù hợp.

#### Bước 5: Chọn host

Host có score cao nhất được chọn.

Nếu `host_subset_size > 1`, Nova có thể chọn ngẫu nhiên trong nhóm N host có điểm cao nhất để tránh dồn tải vào một host duy nhất.

## III. DEFAULT SCHEDULER TRONG NOVA 2026.1

Trong cấu hình mặc định, scheduler xem xét các host thỏa:

- nằm trong Availability Zone được yêu cầu thông qua Placement prefilter;
- compute service available và không bị disabled (`ComputeFilter`);
- thỏa flavor extra specs (`ComputeCapabilitiesFilter`);
- thỏa image properties (`ImagePropertiesFilter`);
- thỏa server group anti-affinity nếu user yêu cầu;
- thỏa server group affinity nếu user yêu cầu.

Default `enabled_filters` trong Nova 2026.1:

```ini
[filter_scheduler]
enabled_filters = ComputeFilter,ComputeCapabilitiesFilter,ImagePropertiesFilter,ServerGroupAntiAffinityFilter,ServerGroupAffinityFilter
```

Nếu cần host aggregate theo flavor extra specs, thêm:

```ini
[filter_scheduler]
enabled_filters = ComputeFilter,ComputeCapabilitiesFilter,ImagePropertiesFilter,ServerGroupAntiAffinityFilter,ServerGroupAffinityFilter,AggregateInstanceExtraSpecsFilter
```

## IV. PREFILTERS VÀ PLACEMENT

### 1. Prefilter là gì?

Prefilter là bước scheduler chuyển một số yêu cầu thành query cho Placement trước khi Nova filter.

Mục tiêu:

- giảm số host candidate;
- lọc sớm bằng dữ liệu Placement;
- tăng tốc scheduling;
- tránh kéo quá nhiều host về scheduler.

### 2. Một số prefilter quan trọng

| Prefilter/config | Ý nghĩa |
| ---------------- | ------- |
| Availability Zone -> Placement aggregate | AZ request được map sang aggregate trong Placement |
| `query_placement_for_image_type_support` | chỉ lấy host hỗ trợ disk format của image |
| `enable_isolated_aggregate_filtering` | cô lập aggregate bằng required traits |
| `image_metadata_prefilter` | chuyển well-known image metadata thành required traits |
| tenant isolation với Placement | giới hạn project vào Placement aggregate |
| routed network aggregates | lọc compute theo routed network segment |

Ví dụ config:

```ini
[scheduler]
query_placement_for_image_type_support = True
enable_isolated_aggregate_filtering = True
image_metadata_prefilter = True
limit_tenants_to_placement_aggregate = True
```

Không phải môi trường nào cũng cần bật tất cả. Chỉ bật khi bạn có nhu cầu và hiểu dữ liệu Placement/trait/aggregate đang được quản lý như nào.

### 3. `max_placement_results`

```ini
[scheduler]
max_placement_results = 1000
```

Ý nghĩa:

- giới hạn số candidate scheduler nhận từ Placement;
- default là `1000`;
- cloud rất lớn có thể giảm để tiết kiệm RAM/network cho scheduler;
- nếu set `1`, gần như để Placement quyết định theo kiểu "fit resource" rồi Nova ít có cơ hội weigh/filter thêm.

## V. FILTER TRONG NOVA

### 1. Filter là gì?

Filter là điều kiện loại host:

```text
Pass  -> host còn candidate
Fail  -> host bị loại
```

Nguyên tắc:

```text
Host phải pass tất cả enabled filters.
```

### 2. Filter mặc định

#### `ComputeFilter`

Loại host có `nova-compute` không available hoặc bị disabled.

Kiểm tra:

```bash
openstack compute service list --service nova-compute
```

#### `ComputeCapabilitiesFilter`

Match một số capability/extra spec của flavor với capability host.

Ví dụ:

```bash
openstack flavor set m1.large --property some_capability=value
```

Trong thực tế mới, nhiều yêu cầu phần cứng nên dùng Placement resource class/trait thay vì capability cũ.

#### `ImagePropertiesFilter`

Match image properties với host.

Ví dụ image có:

```bash
hw_architecture=x86_64
hypervisor_type=qemu
```

Scheduler chỉ chọn host phù hợp.

#### `ServerGroupAntiAffinityFilter`

Nếu user tạo server group anti-affinity, VM trong cùng group không chạy cùng host.

```bash
openstack server group create --policy anti-affinity app-aa
openstack server create --hint group=<server-group-id> ...
```

#### `ServerGroupAffinityFilter`

VM trong cùng group được schedule vào cùng tập host theo policy affinity.

### 3. Filter thường bật thêm

#### `AggregateInstanceExtraSpecsFilter`

Match flavor extra specs với host aggregate metadata.

```bash
openstack aggregate set --property ssd=true fast-io
openstack flavor set \
  --property aggregate_instance_extra_specs:ssd=true \
  ssd.large
```

#### `NUMATopologyFilter`

Dùng cho workload cần NUMA topology, hugepage, dedicated CPU, PCI passthrough.

Ví dụ flavor:

```bash
openstack flavor set nfv.large \
  --property hw:cpu_policy=dedicated \
  --property hw:mem_page_size=large
```

#### `PciPassthroughFilter`

Dùng khi request PCI device passthrough.

#### `AggregateNumInstancesFilter`

Giới hạn số instance theo host/aggregate.

#### `IoOpsFilter`

Loại host có quá nhiều tác vụ I/O đang chạy như build, resize, snapshot, migrate, rescue, unshelve.

### 4. Filter không nên lạm dụng

`JsonFilter` cho phép user truyền query dạng JSON qua scheduler hint, nhưng tài liệu Nova cảnh báo filter này không bật mặc định, không được test toàn diện và phụ thuộc attribute nội bộ của `HostState`.

Best practice:

```text
Ưu tiên Placement traits, flavor extra specs, image metadata chuẩn, aggregate rõ ràng.
```

## VI. WEIGHER TRONG NOVA

![Nova](./images/Nova_18.png)

### 1. Weigher là gì?

Sau khi filter xong, có thể còn nhiều host hợp lệ.

Weigher chấm điểm host để chọn host tốt nhất:

```text
weight = w1_multiplier * norm(w1) + w2_multiplier * norm(w2) + ...
```

Trong đó:

- `w1`, `w2` là điểm của từng weigher;
- `norm()` là điểm đã normalize;
- `multiplier` là hệ số ưu tiên;
- host có weight cao nhất thắng.

### 2. Config weigher

```ini
[filter_scheduler]
weight_classes = nova.scheduler.weights.all_weighers
host_subset_size = 1
```

Ý nghĩa:

| Option | Ý nghĩa |
| ------ | ------- |
| `weight_classes` | danh sách weigher scheduler dùng |
| `host_subset_size` | chọn ngẫu nhiên trong N host điểm cao nhất |

### 3. Các weigher phổ biến

#### `RAMWeigher`

Ưu tiên host còn nhiều RAM.

```ini
[filter_scheduler]
ram_weight_multiplier = 1.0
```

Nếu multiplier âm:

```ini
ram_weight_multiplier = -1.0
```

Scheduler sẽ có xu hướng **pack/stack** VM vào host ít RAM trống hơn.

#### `CPUWeigher`

Ưu tiên host còn nhiều vCPU.

```ini
[filter_scheduler]
cpu_weight_multiplier = 1.0
```

Số âm nghĩa là ưu tiên packing.

#### `DiskWeigher`

Ưu tiên host còn nhiều disk.

```ini
[filter_scheduler]
disk_weight_multiplier = 1.0
```

#### `IoOpsWeigher`

Ưu tiên host ít tác vụ I/O đang chạy.

Default multiplier:

```ini
[filter_scheduler]
io_ops_weight_multiplier = -1.0
```

Giá trị âm giúp scheduler có xu hướng chọn host nhẹ tải I/O hơn.

#### `BuildFailureWeigher`

Trừ điểm host có nhiều build failure gần đây.

Default multiplier rất lớn:

```ini
[filter_scheduler]
build_failure_weight_multiplier = 1000000.0
```

Mục tiêu là tránh host đang có dấu hiệu lỗi, nhưng nếu fail do lỗi user thì host vẫn có thể bị giảm điểm. Khi vận hành cần xem log trước khi kết luận host hỏng.

#### `PCIWeigher`

Ưu tiên host phù hợp với request PCI device.

Lưu ý:

- multiplier chỉ nhận giá trị không âm;
- có ích khi dùng `NUMATopologyFilter` hoặc `PciPassthroughFilter`.

#### `CrossCellWeigher`

Ưu tiên host trong cùng cell khi move instance cross-cell.

Default ưu tiên cùng cell vì cross-cell move phức tạp và rủi ro hơn.

#### `HypervisorVersionWeigher`

Từ Nova Bobcat, scheduler có thể weigh theo hypervisor version.

Default ưu tiên host có hypervisor mới hơn:

```ini
[filter_scheduler]
hypervisor_version_weight_multiplier = 1.0
```

Nếu muốn ưu tiên host cũ hơn trong giai đoạn upgrade:

```ini
[filter_scheduler]
hypervisor_version_weight_multiplier = -1000
```

#### `NumInstancesWeigher`

Weigh theo số instance trên host.

```ini
[filter_scheduler]
num_instances_weight_multiplier = 0.0
```

Default là `0.0`, tức chưa ảnh hưởng nếu bạn không chọn strategy.

- số dương: pack vào host có nhiều instance;
- số âm: spread sang host có ít instance.

#### `ImagePropertiesWeigher`

Từ Nova Epoxy, scheduler có thể weigh theo image properties của các instance đang có trên host.

Ví dụ:

```ini
[filter_scheduler]
image_props_weight_multiplier = 1000
image_props_weight_setting = os_distro=10,os_secure_boot=1
```

Use case:

- pack các VM cùng OS/image property lại để tận dụng cache;
- hoặc dùng multiplier âm để spread.

## VII. SPREAD VS PACK

### 1. Spread

Mục tiêu: phân tán VM ra nhiều host.

Ví dụ:

```ini
[filter_scheduler]
ram_weight_multiplier = 1.0
cpu_weight_multiplier = 1.0
disk_weight_multiplier = 1.0
io_ops_weight_multiplier = -1.0
```

Kết quả:

```text
Scheduler thích host còn nhiều resource và ít workload.
```

### 2. Pack

Mục tiêu: dồn VM vào một số host để tiết kiệm điện, gom workload hoặc để trống host khác.

Ví dụ:

```ini
[filter_scheduler]
ram_weight_multiplier = -1.0
cpu_weight_multiplier = -1.0
disk_weight_multiplier = -1.0
num_instances_weight_multiplier = 1000
```

Kết quả:

```text
Scheduler thích host đang được dùng nhiều hơn.
```

Cẩn thận:

- packing quá mạnh dễ tạo hot spot;
- cần giám sát CPU steal, memory pressure, I/O wait;
- không nên chỉ chỉnh multiplier mà bỏ qua capacity/Placement.

## VIII. ALLOCATION RATIO

Placement quản lý inventory của compute host.

Các resource chính:

```text
VCPU
MEMORY_MB
DISK_GB
```

Nova có các allocation ratio:

```ini
[DEFAULT]
cpu_allocation_ratio = <None>
ram_allocation_ratio = <None>
disk_allocation_ratio = <None>
```

Với compute node mới, initial allocation ratio mặc định từ Antelope trở đi:

```ini
initial_cpu_allocation_ratio = 4.0
initial_ram_allocation_ratio = 1.0
initial_disk_allocation_ratio = 1.0
```

Ý nghĩa:

| Ratio | Ý nghĩa |
| ----- | ------- |
| CPU `4.0` | có thể overcommit vCPU 4 lần theo inventory |
| RAM `1.0` | không overcommit RAM mặc định |
| Disk `1.0` | không overcommit disk mặc định |

Allocation ratio ảnh hưởng tới Placement inventory và scheduling.

## IX. VÍ DỤ THỰC TẾ

### 1. Chỉ cho VM chạy trên host SSD

```bash
openstack aggregate create fast-io
openstack aggregate set --property ssd=true fast-io
openstack aggregate add host fast-io compute01

openstack flavor create --ram 8192 --disk 80 --vcpus 4 ssd.large
openstack flavor set \
  --property aggregate_instance_extra_specs:ssd=true \
  ssd.large
```

Config scheduler:

```ini
[filter_scheduler]
enabled_filters = ComputeFilter,ComputeCapabilitiesFilter,ImagePropertiesFilter,ServerGroupAntiAffinityFilter,ServerGroupAffinityFilter,AggregateInstanceExtraSpecsFilter
```

### 2. Dùng Placement trait cho host có SSD

```bash
openstack resource provider trait set \
  --trait CUSTOM_DISK_SSD \
  <resource-provider-uuid>

openstack flavor set \
  --property trait:CUSTOM_DISK_SSD=required \
  ssd.large
```

Placement sẽ lọc host có trait `CUSTOM_DISK_SSD` trước khi Nova filters chạy.

### 3. Anti-affinity cho 2 web server

```bash
openstack server group create --policy anti-affinity web-aa
GROUP_ID=$(openstack server group show web-aa -f value -c id)

openstack server create \
  --hint group=$GROUP_ID \
  --image ubuntu-24.04 \
  --flavor m1.small \
  --network private \
  web01

openstack server create \
  --hint group=$GROUP_ID \
  --image ubuntu-24.04 \
  --flavor m1.small \
  --network private \
  web02
```

Scheduler sẽ cố đặt `web01` và `web02` khác host.

### 4. Chọn Availability Zone

```bash
openstack aggregate create --zone dc1 agg-dc1
openstack aggregate add host agg-dc1 compute01

openstack server create \
  --availability-zone dc1 \
  --image ubuntu-24.04 \
  --flavor m1.small \
  --network private \
  vm-dc1
```

Scheduler map `dc1` sang Placement aggregate rồi chỉ lấy candidate trong đó.

## X. TROUBLESHOOTING SCHEDULER

### 1. Lỗi `NoValidHost`

Đây là lỗi phổ biến nhất.

Kiểm tra service:

```bash
openstack compute service list --service nova-compute
openstack hypervisor list
```

Kiểm tra aggregate/AZ:

```bash
openstack availability zone list --compute
openstack aggregate list --long
openstack aggregate show <aggregate>
```

Kiểm tra flavor/image:

```bash
openstack flavor show <flavor>
openstack image show <image>
```

Kiểm tra Placement:

```bash
openstack resource provider list
openstack resource provider inventory list <resource-provider-uuid>
openstack resource provider trait list <resource-provider-uuid>
```

Log:

```bash
/var/log/nova/nova-scheduler.log
/var/log/nova/nova-conductor.log
```

### 2. Candidate có trong Placement nhưng vẫn fail

Thường do Nova filter loại tiếp.

Kiểm tra:

- `enabled_filters`;
- flavor extra specs;
- image properties;
- server group policy;
- aggregate metadata;
- compute service disabled;
- NUMA/PCI/hugepage yêu cầu quá chặt.

### 3. VM bị dồn vào một vài host

Kiểm tra weighers:

```ini
[filter_scheduler]
ram_weight_multiplier
cpu_weight_multiplier
disk_weight_multiplier
num_instances_weight_multiplier
host_subset_size
```

Nếu muốn spread hơn:

```ini
ram_weight_multiplier = 1.0
cpu_weight_multiplier = 1.0
num_instances_weight_multiplier = -1.0
host_subset_size = 10
```

### 4. Compute mới thêm nhưng scheduler không thấy

Trong Cells v2, cần map host:

```bash
nova-manage cell_v2 discover_hosts --verbose
nova-manage cell_v2 list_hosts
```

Hoặc bật tự động:

```ini
[scheduler]
discover_hosts_in_cells_interval = 300
```

## XI. TÓM TẮT DỄ NHỚ

```text
Placement trả lời: host nào có đủ resource/trait/aggregate?
Filter trả lời: host nào hợp lệ theo policy/yêu cầu?
Weigher trả lời: trong các host hợp lệ, host nào tốt nhất?
```

So sánh:

| Giai đoạn | Chức năng | Ví dụ |
| --------- | --------- | ----- |
| Placement prefilter | lọc sớm bằng inventory/trait/aggregate | VCPU, RAM, DISK, AZ, trait |
| Filter | loại host không hợp lệ | compute disabled, image mismatch, anti-affinity |
| Weigher | chấm điểm host | RAM, CPU, disk, build failure, IO ops |

Nếu học Nova Scheduler, nên nhớ flow này:

```text
RequestSpec -> Placement candidates -> Filters -> Weights -> Selected host
```
