# CÀI ĐẶT VÀ CÁC PACKAGES CỦA TELEMETRY

> **Phiên bản tham chiếu**: OpenStack **2026.1 Gazpacho**

## I. TELEMETRY VÀ CEILOMETER — CÀI ĐẶT VÀ CẤU TRÚC THƯ MỤC

Dịch vụ Ceilometer cần được phân phối trên cả Controller Node (Notification Agent) và các Compute Node (Polling Agent).

### 1. Phương thức cài đặt Package

#### Cách 1: Sử dụng Package Manager của hệ điều hành

- **Trên Ubuntu/Debian (`.deb`)**:

  ```bash
  sudo apt-get update
  # Cài trên Controller:
  sudo apt-get install -y ceilometer-agent-notification
  # Cài trên Compute:
  sudo apt-get install -y ceilometer-agent-compute
  ```

- **Trên Rocky Linux/RHEL (`.rpm`)**:

  ```bash
  # Cài trên Controller:
  sudo dnf install -y openstack-ceilometer-notification
  # Cài trên Compute:
  sudo dnf install -y openstack-ceilometer-compute
  ```

#### Cách 2: Cài đặt qua PIP và môi trường ảo (Virtualenv)

Đây là cách cài đặt độc lập để chạy các phiên bản tùy chỉnh mà không làm ảnh hưởng tới thư viện Python hệ thống:

```bash
# 1. Khởi tạo môi trường ảo Python 3:
python3 -m venv /openstack/venvs/ceilometer
source /openstack/venvs/ceilometer/bin/activate

# 2. Cài đặt Ceilometer và các thư viện hỗ trợ từ OpenStack Opendev:
pip install --upgrade pip
pip install git+https://opendev.org/openstack/ceilometer.git@stable/2026.1
```

### 2. Cấu trúc thư mục `/etc/ceilometer` và tệp cấu hình

- **/etc/ceilometer/ceilometer.conf**: Tệp cấu hình chính chứa các tham số xác thực Keystone, chuỗi kết nối RabbitMQ và bộ chuyển tiếp (dispatcher) khai báo `gnocchi`.

- **/etc/ceilometer/polling.yaml** (thay thế cho `pipeline.yaml` cũ trong các bản mới):

  - Khai báo các nguồn dữ liệu cần cào (meters) và chu kỳ thời gian (interval) cào dữ liệu thô.

- **/etc/ceilometer/event_pipeline.yaml**:

  - Quản lý luồng xử lý và xuất bản (publish) các sự kiện nhận được từ hệ thống hàng đợi MQ.

#### Cấu trúc tệp tin `polling.yaml` mẫu

```yaml
---
sources:
  - name: some_cpu_counters
    interval: 60
    meters:
      - cpu
      - cpu_util
    sinks:
      - gnocchi_sink
sinks:
  - name: gnocchi_sink
    publishers:
      - gnocchi://
```

## II. GNOCCHI — CÀI ĐẶT CÁC PHÂN HỆ VÀ CẤU TRÚC THƯ MỤC

Gnocchi yêu cầu cài đặt đầy đủ các thư viện driver liên quan đến cơ sở dữ liệu Indexer và kho chứa Storage được chỉ định.

### 1. Cài đặt bằng PIP hỗ trợ Extras (PostgreSQL, Ceph, Swift)

Khi cài đặt Gnocchi qua PIP, ta cần khai báo rõ các phân hệ đi kèm trong ngoặc vuông để Python tự động tải các driver kết nối tương ứng:

```bash
# Cài đặt môi trường ảo chuyên biệt cho Gnocchi:
python3 -m venv /openstack/venvs/gnocchi
source /openstack/venvs/gnocchi/bin/activate

# Cài đặt Gnocchi kèm driver cho PostgreSQL (Indexer) và Ceph/S3/Swift (Storage):
pip install gnocchi[postgresql,ceph,file,swift]
```

- `postgresql`: Cài đặt thư viện `psycopg2` để giao tiếp với DB PostgreSQL.
- `ceph`: Tải thư viện `cados` để tương tác trực tiếp với RADOS Object Store của Ceph.
- `swift`: Driver kết nối với dịch vụ lưu trữ Object Storage của OpenStack.

### 2. Cấu trúc thư mục `/etc/gnocchi` và tệp cấu hình

- **/etc/gnocchi/gnocchi.conf**: Tệp cấu hình trung tâm định nghĩa driver Indexer (PostgreSQL) và driver Storage (Ceph/S3).
- **/etc/gnocchi/api-paste.ini**:

  - Định cấu hình luồng pipeline WSGI của Gnocchi API Server.
  - Sử dụng để tích hợp thư viện `keystonemiddleware.auth_token` phục vụ việc chặn và xác thực token Keystone của các request gửi tới trước khi xử lý dữ liệu.

#### Một đoạn cấu hình WSGI mẫu trong `api-paste.ini`

```ini
[pipeline:main]
pipeline = gnocchi+auth

[filter:keystone]
paste.filter_factory = keystonemiddleware.auth_token:filter_factory

[app:gnocchi+auth]
paste.app_factory = gnocchi.rest.app:app_factory
```

## III. AODH — CÀI ĐẶT VÀ CẤU TRÚC THƯ MỤC

Aodh thường chạy trên Controller Node để thực thi việc điều phối và giám sát các ngưỡng cảnh báo.

### 1. Phương thức cài đặt Package Aodh

#### a.Cách 1: Sử dụng Package Manager của hệ điều hành

- **Trên Ubuntu/Debian (`.deb`)**:

  ```bash
  sudo apt-get install -y aodh-api aodh-evaluator aodh-notifier aodh-listener
  ```

- **Trên Rocky Linux/RHEL (`.rpm`)**:

  ```bash
  sudo dnf install -y openstack-aodh-api openstack-aodh-evaluator openstack-aodh-notifier openstack-aodh-listener
  ```

#### b.Cách 2: Cài đặt qua PIP và môi trường ảo (Virtualenv)

```bash
# Khởi tạo venv riêng biệt cho Aodh:
python3 -m venv /openstack/venvs/aodh
source /openstack/venvs/aodh/bin/activate

# Cài đặt trực tiếp từ mã nguồn aodh ổn định:
pip install git+https://opendev.org/openstack/aodh.git@stable/2026.1
```

### 2. Cấu trúc thư mục `/etc/aodh` và tệp cấu hình

- **/etc/aodh/aodh.conf**: Tệp cấu hình chính chứa thông tin kết nối database MariaDB riêng của Aodh, địa chỉ kết nối API của Gnocchi và Keystone credentials.

- **/etc/aodh/api-paste.ini**:

  - Cấu hình tương tự như Gnocchi, tệp này chứa pipeline WSGI để kiểm soát luồng xác thực Keystone cho dịch vụ `aodh-api`. Nó chỉ cho phép các request có Header chứa Keystone Token hợp lệ truy cập vào hệ thống quản trị Alarm của dự án.

- **/etc/aodh/policy.yaml**:

  - Quy định chính sách phân quyền RBAC (Role-Based Access Control) cho Aodh, phân chia quyền hạn tạo/xem/xóa alarm giữa `admin`, `project_member` và `reader`.
